# wiki-activate

구축된 LLM 위키를 읽어, 질의 답변과 책·강의·블로그 산출물로 구동하는 활용 워크플로우입니다. 카파시(Karpathy) LLM-Wiki 패턴에서 위키는 코드베이스, 코워크는 프로그래머, 옵시디언은 IDE에 해당합니다. 이 스킬은 그 코드베이스를 읽어 실행하는 단계를 담당합니다.

## 전제 조건

이 스킬은 위키가 이미 존재하는 상태를 가정합니다. 다음 두 가지를 먼저 확인합니다.

1. 위키 폴더에 위키 페이지가 1장 이상 존재합니다. 생성 경로는 무관합니다(wiki-ingest, 위키 폴더 자체 Ingest 절차 등).
2. 소스 폴더가 위키 볼트의 CLAUDE.md에 등록되어 있거나, 사용자가 이번 작업의 소스 폴더를 지정합니다.

전제가 충족되지 않으면 진행하지 않고, wiki-ingest로 먼저 인제스트할지 사용자에게 확인합니다. 운영 지침(CLAUDE.md)이 없는 폴더에는 스킬 기본값으로 임의 실행하지 않고, 대상 위키 폴더를 먼저 확인합니다(폴더 가드).

## 위키 폴더 지침 우선

위키 폴더에 운영 지침(CLAUDE.md 등)이 있으면 그 스키마·인덱싱·소스 표기 규약을 이 스킬 기본값보다 우선 적용합니다.

- 스키마: 폴더가 `type` 필드를 쓰지 않고 다른 분류 필드(예: `category`)로 개념/경험을 구분하면 그 필드를 따릅니다. 이때 `type` 미사용은 결함이 아닙니다.
- 인덱싱: 폴더가 MOC 대신 dataview index(예: index.md 자동수집)를 쓰면 수동 MOC 갱신·점검을 생략하고 index 노출만 확인합니다.
- 소스 표기: 폴더가 정한 sources 형식을 따릅니다. 위키링크(`[[ ]]`)는 노트형 소스에만 쓰고, docx·pptx·pdf 등 비노트 원본은 경로 문자열로 표기합니다.
- 명명·배치·본문 구조: 폴더가 파일명 접두어(예: `W_`)·하위 폴더(예: `wiki/`)·본문 섹션 구성(예: 8섹션)을 정하면 기본 템플릿보다 그 규약을 따릅니다.

폴더 지침이 없을 때만 아래 기본 규약(`type`·MOC)을 적용합니다.

## 활용 모드 (4종)

사용자 요청에서 모드를 판별합니다. 신호가 모호하면 모드 1개를 추천하고 확인합니다.

| 모드 | 신호 | 출력 |
|------|------|------|
| A 질의 | 위키 근거로 답해줘, 차이 정리, 빈틈 찾아줘 | 대화 답변 |
| B 재투입 | 위키로 책/강의/블로그, 위키 근거로 작성 | 초안 또는 후속 스킬 입력 |
| C 학습 | 치트시트, 학습 로드맵, 점검 문제 | 요약·퀴즈·로드맵 |
| D 연결 | 교차링크, 페이지 관계, MOC 갱신, 글감 | 링크 제안·글감 목록 |

모드별 상세 절차와 코워크 지시문은 `references/activation-patterns.md`를 참조합니다.

## 프로세스 (Phase 0 ~ 5)

### Phase 0 — 전제 점검과 소스 연결

위키 폴더와 소스 폴더를 확인합니다. 소스 폴더는 raw/ 아래로 한정하지 않습니다. 02 AI 리서치 노트, 90 References 등 위키 볼트 안의 다른 폴더도 소스로 등록합니다. 연결 방식은 `references/reuse-pipelines.md`의 소스 등록 3가지를 따릅니다.

이때 경계를 명확히 합니다. 소스 폴더는 읽기 전용으로 다루고 수정하지 않습니다. 위키 폴더만 갱신 대상입니다. 같은 볼트에서 작업할 경우, 위키 작업 중 write-/lecture-/book- 스킬이 오발동하지 않도록 주의합니다.

### Phase 1 — 활용 모드 확정

위 4종 중 하나를 확정합니다. 재투입(B) 모드는 산출 채널(책·강의·블로그·페북·네이버)을 함께 확정합니다.

### Phase 2 — 위키 읽기

해당 모드에 필요한 위키 페이지와 소스 노트를 읽습니다. 사용자가 "위키 밖 지식 금지"를 요청하면, 위키와 등록 소스 폴더 밖의 지식을 답변에 사용하지 않습니다. 이 제약은 위키를 신뢰 가능한 단일 소스로 검증하는 장치입니다.

### Phase 3 — 실행 (Generator)

모드별로 산출물을 생성합니다. 재투입 모드에서는 채널별 요구를 적용합니다. 책은 깊이와 경험, 강의는 비교·실습·시각 소재, 블로그·페북은 후크와 가독성을 우선합니다.

### Phase 4 — 검증 (Evaluator)

Phase 3과 분리된 시점에서 다음을 점검합니다.

- 산출물의 사실·수치·출처가 위키 페이지와 일치하는가
- 위키에 없는 내용을 임의 생성하지 않았는가
- 위키 밖 지식 금지 요청 시 이를 위반하지 않았는가
- 근거로 사용한 위키 페이지명을 표기했는가

불일치 항목은 위키 근거로 교정합니다. 위키에 근거가 없으면 "위키에 근거 없음"으로 표시하고 임의 보충하지 않습니다.

### Phase 5 — 산출물 출력과 후속 스킬 연결

모드와 채널에 따라 분기합니다.

- 질의(A): 대화 답변. 근거 위키 페이지명을 끝에 표기합니다.
- 재투입(B): 초안을 제공하거나, 후속 스킬에 넘길 입력으로 정리합니다.
  - 책 → book-writing-pro 또는 해당 책 전용 스킬(book-ai-1in 등)
  - 강의 → lecture-research(RL_ 노트) → lecture-slides
  - 블로그 → write-blog, 페북 → write-facebook, 네이버 → write-naver-info
- 학습(C)·연결(D): 요약·로드맵·링크 제안·글감 목록을 제공합니다.

산출물 형식은 사용자 작업 워크플로우를 따릅니다. 단편 콘텐츠 초안은 대화창 텍스트, 장편·구조화 산출물(책 원고·강의 슬라이드)은 후속 스킬에서 파일로 생성합니다.

모든 모드 공통: 위키 폴더가 작업 로그(예: log.md)를 요구하면 [Activate] 1줄을 기록합니다(대상 페이지·활용 모드·산출 채널 포함).

## 소스 연결 규칙

raw/ 폴더 단일 의존이 아니라, 위키 볼트 안의 여러 폴더를 소스로 묶을 수 있습니다. 세 가지 방식을 상황에 맞게 선택합니다.

1. CLAUDE.md 소스 등록 — 소스 폴더 목록과 권한을 명시. 기본 방식.
2. 위키 페이지 frontmatter 소스 경로 — 페이지별 출처 추적이 필요할 때.
3. 소스 레지스트리 노트 — 흩어진 자료를 옮기지 않고 목록으로 등록할 때.

상세는 `references/reuse-pipelines.md`를 참조합니다.

## Harness Engineering

이 스킬은 다음 4축을 적용합니다.

- 생성-평가 분리: Phase 3(Generator)과 Phase 4(Evaluator)를 분리해, 위키 근거 일치를 별도 시점에서 검증합니다.
- AI 흔적 제거: 산출물에서 금지어(혁신적인·획기적인·완벽한·매우·쉽게·빠르게·~할 수 있습니다)와 모호한 수식을 제거합니다. 종결어미는 ~합니다체로 통일합니다.
- 보존 레벨:
  - L1 (원문 보존) — 위키의 사실·수치·출처. 변경하지 않고 그대로 인용합니다.
  - L2 (재배열 허용) — 위키 페이지의 순서·묶음. 산출 목적에 맞게 재배열합니다.
  - L3 (자유 생성) — 산출물의 도입·전환·문체. 채널에 맞게 새로 작성합니다.
- 분량 가드레일:
  - 질의 답변: 핵심부터, 모드 A는 화면 1~2개 분량.
  - 재투입 초안: 후속 스킬의 분량 규격을 따릅니다.
  - 위키 페이지 1장에서 직접 끌어오는 인용은 핵심 위주로 압축합니다.

## 출력 규약

- 한국어로 출력합니다. 시각·날짜는 KST 기준입니다.
- 코워크 지시문·코드·설정은 코드 블록(```)에 넣습니다.
- 근거로 사용한 위키 페이지명을 산출물 끝에 표기합니다.
- 위키에 근거가 없는 부분은 임의 생성하지 않고 "위키에 근거 없음"으로 표시합니다.
