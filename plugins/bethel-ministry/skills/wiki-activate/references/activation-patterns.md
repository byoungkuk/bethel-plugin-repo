# 활용 모드 상세 (activation-patterns)

4가지 모드의 절차와 코워크(Cowork) 지시문 예시입니다. 모든 지시문은 위키 폴더와 등록 소스 폴더를 읽는 것을 전제로 합니다.

## 목차
1. 모드 A — 검색·답변
2. 모드 B — 콘텐츠 재투입
3. 모드 C — 학습·자기 점검
4. 모드 D — 연결·발견

---

## 1. 모드 A — 검색·답변

위키를 단일 소스로 두고 질문에 답하는 모드입니다. 가장 자주 쓰며, 위키 구조가 작동하는지 검증하는 첫 단계입니다.

### 절차
1. 질문과 관련된 위키 페이지를 식별합니다.
2. "위키 밖 지식 금지" 요청이 있으면 위키·소스 폴더 밖 지식을 차단합니다.
3. 페이지를 읽고 답합니다.
4. 근거 페이지명을 끝에 표기합니다.

### 지시문 예시
```
"50 LLM 위키만 근거로 답해줘. RAG와 파인튜닝의 선택 기준을
정리하고, 근거로 쓴 페이지명을 끝에 표기해줘."
```
```
"위키에서 'Cowork' 페이지를 읽고, 내가 놓치고 있을 법한
활용 포인트 3개만 짚어줘."
```
```
"이 주제(AI 에이전트)에 대해 위키에 빠진 부분을 찾아줘.
채워야 할 페이지 목록으로."
```

마지막 "빈틈 찾기"는 위키를 키우는 엔진입니다. 위키가 다음 인제스트 대상을 스스로 제시합니다.

---

## 2. 모드 B — 콘텐츠 재투입

위키를 책·강의·블로그 산출물의 입력 소스로 쓰는 모드입니다. 매번 다시 조사하지 않고 위키를 근거로 산출합니다. 채널마다 위키에 요구하는 형태가 다릅니다.

### 채널별 요구

| 채널 | 위키에서 뽑는 것 | 후속 스킬 |
|------|----------------|----------|
| 책 | 개념 깊이, 본인 경험·사례, 출처 | book-writing-pro, book-ai-1in |
| 강의 | 비교 데이터, 시각 소재, 실습 거리 | lecture-research → lecture-slides |
| 블로그 | 핵심 1개 + 검색 키워드 | write-blog |
| 페북 | 후크·더보기 클릭 유도 | write-facebook |
| 네이버 | 검색 의도·모바일 가독성 | write-naver-info |

### 지시문 예시
```
"위키 20 Concepts 폴더의 MCP·Skill·Cowork 페이지를 묶어
강의 1꼭지 분량으로 재구성. 이어서 lecture-research RL_ 노트로."
```
```
"위키 'AI 1인 기업' 페이지들을 근거로 book-ai-1in Ch3 작성.
경험 메모 페이지를 경험 주입 소스로."
```
```
"위키 'Prompt Engineering' 페이지를 근거로 write-facebook
인트로 작성. 더보기 클릭 유도형으로."
```

### 주의
- L1(사실·수치·출처)은 위키 그대로 인용합니다. L3(도입·전환·문체)만 채널에 맞게 새로 씁니다.
- 위키에 없는 사례·수치를 임의로 보충하지 않습니다.

---

## 3. 모드 C — 학습·자기 점검

위키를 교재로 삼아 요약·로드맵·점검 문제를 만드는 모드입니다.

### 지시문 예시
```
"위키 10 Models 폴더 전체를 읽고, 모델 비교 치트시트
한 장으로 압축. 표로."
```
```
"위키 'RAG' 페이지로 객관식 5문제 만들어줘. 이해 점검용."
```
```
"위키를 처음 보는 사람을 위한 학습 순서를 로드맵으로.
어떤 페이지부터 읽어야 하는지."
```

---

## 4. 모드 D — 연결·발견

페이지 사이를 엮어 통찰을 뽑고, 위키 구조를 유지하는 모드입니다. 누적된 페이지끼리 연결할 때 위키가 RAG보다 강한 지점이 드러납니다.

### 지시문 예시
```
"위키에서 'Context Window'와 'Skill Design' 페이지가 어떻게
연결되는지 분석하고, 두 페이지에 서로 [[ ]] 링크를 추가."
```
```
"위키 전체를 스캔해서 아직 [[ ]]로 연결 안 된 관련 페이지
쌍을 찾아 연결 제안 목록으로."
```
```
"MOC(LLM-Wiki-MOC.md)를 현재 페이지 구성에 맞게 갱신하고,
새 카테고리가 생겼으면 반영."
```
```
"위키 전체를 스캔해서 (1) 본문이 얕은 페이지,
(2) 최근 추가됐는데 글로 안 쓴 페이지를 찾아 이번 달
블로그 글감 후보 5개를 제목과 함께."
```

마지막 글감 추출은 위키를 콘텐츠 캘린더 엔진으로 쓰는 방식입니다. 쓴 글은 다시 위키로 돌아와 페이지를 보강합니다.

## 모드 판별 가이드

| 사용자 표현 | 모드 |
|------------|------|
| "~ 근거로 답해줘", "차이 정리", "빈틈" | A |
| "위키로 책/강의/블로그", "~ 근거로 작성" | B |
| "치트시트", "로드맵", "문제 만들어" | C |
| "교차링크", "관계", "MOC", "글감" | D |

표현이 모호하면 모드 1개를 추천하고 사용자 확인을 받습니다.
