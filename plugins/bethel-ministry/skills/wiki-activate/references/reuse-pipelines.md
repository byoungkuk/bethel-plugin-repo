# 재투입 파이프라인 (reuse-pipelines)

위키를 허브로 두고 책·강의·블로그로 분기하는 파이프라인, 소스 연결 3방식, 채널별 재투입 규격입니다.

## 목차
1. 원소스 멀티유즈 파이프라인 3종
2. 소스 연결 3방식
3. 채널별 재투입 규격

---

## 1. 원소스 멀티유즈 파이프라인 3종

한 번 쌓은 위키에서 여러 산출물이 갈라져 나오는 흐름입니다.

### 시나리오 1 — 한 주제를 책·강의·블로그로 동시 전개

```
[소스]                    [허브]              [산출물]
02 AI 리서치 노트 ┐
chat/ 커뮤니티 Q&A ┼─→  위키 페이지 누적  ─┬─→ 책 챕터
web/ 신규 리서치   ┘    (개념·사례·데이터)  ├─→ 강의 슬라이드
                                          └─→ 블로그·페북
```

절차:
1. 소스 연결 — CLAUDE.md에 소스 폴더 등록.
2. 위키 컴파일 — 소스를 읽어 개념 페이지 정리. 본인 경험 메모는 별도 페이지로 분리.
3. 빈틈 보충 — 객관 데이터 빈칸을 wiki-research로 보충합니다(원문 raw 보존 → R_ 정리 → 위키 갱신). 넓은 탐색만 필요하면 research-mega-topic을 참고 수준으로 씁니다.
4. 책 재투입 — 위키 페이지 근거로 book-writing-pro 또는 전용 스킬. 경험 페이지를 경험 주입 소스로.
5. 강의 재투입 — 같은 페이지를 lecture-research RL_ 노트로 변환 → lecture-slides.
6. 블로그·페북 재투입 — 핵심 페이지 1개로 write-blog → write-facebook 인트로.

같은 위키를 책은 깊이, 강의는 비교·실습, 블로그는 후크 중심으로 다르게 뽑습니다. 소스는 하나, 출력은 셋입니다.

### 시나리오 2 — 강의를 먼저, 누적되면 책으로 승격

```
강의 진행 → Q&A·반응을 chat/에 raw 저장
→ 위키 갱신(현장 사례 누적)
→ 3~4회 누적 후 위키가 책 1장 분량 도달
→ book-writing-pro로 챕터화
```

강의 현장 질문과 커뮤니티 반응이 책의 1차 자료가 됩니다. 웹 자료만으로는 만들지 못하는 차별점이 여기서 생깁니다.

### 시나리오 3 — 위키가 다음 글감을 제안

```
위키 스캔(얕은 페이지·미발행 페이지) → 글감 후보 도출
→ write-blog 발행 → 발행 글을 다시 위키로 → 페이지 보강
```

글쓰기와 위키가 서로를 키우는 순환입니다.

### 시나리오 선택

| 시나리오 | 출발점 | 적합한 때 |
|----------|--------|----------|
| 1 동시 전개 | 주제 확정 | 책·강의 동시 준비 |
| 2 강의→책 승격 | 강의 운영 | 강의가 이미 도는 주제 |
| 3 글감 엔진 | 기존 위키 | 위키가 어느 정도 쌓인 뒤 |

## 2. 소스 연결 3방식

raw/ 폴더 단일 의존이 아니라, 위키 볼트 안의 여러 폴더를 소스로 묶는 방식입니다. 옵시디언 `[[ ]]`·그래프뷰는 같은 볼트면 폴더 무관하게 연결되고, 코워크는 지정한 폴더는 어디든 읽습니다.

### 방식 A — CLAUDE.md 소스 등록 (기본)

물리 이동 없이, 위키 볼트의 CLAUDE.md에 소스 폴더와 권한을 명시합니다.

```
## 위키 소스 폴더 (읽기 전용, 수정 금지)
- 02 AI 리서치 노트/
- 90 References/
- raw/web/

## 위키 폴더 (코워크가 갱신)
- 50 LLM 위키/
```

코워크는 소스 폴더는 읽기만, 위키 폴더만 수정합니다.

### 방식 B — 위키 페이지 frontmatter 소스 경로

페이지별 출처 추적이 필요할 때 사용합니다.

```
---
type: concept
sources:
  - "02 AI 리서치 노트/RL_MCP.md"
  - "90 References/karpathy-llm-wiki.md"
updated: 2026-05-31
---
```

소스가 갱신되면 위키를 재컴파일할 근거가 됩니다. 위키링크/경로 표기는 폴더 규약을 따르며, 비노트 원본(docx·pptx·pdf)은 경로 문자열로 적습니다.

### 방식 C — 소스 레지스트리 노트

흩어진 자료를 옮기지 않고 목록으로만 등록합니다. raw/ 자리에 "어느 폴더의 어떤 노트가 소스인지" 링크 목록 노트 한 장을 둡니다.

### 경계 유지 주의

여러 스킬이 볼트 전역에서 트리거되는 구조에서는, 여러 폴더를 소스로 연결하면 트리거 간섭 표면이 넓어집니다. 위키 작업은 별도 볼트로 분리하거나, 같은 볼트라면 CLAUDE.md 상단에 "위키 작업 중 write-/lecture-/book- 스킬 트리거 비활성화"를 명시합니다. 이 규칙을 폴더 CLAUDE.md 상단에 상시 두면 매 세션 반복 선언이 없어집니다.

## 3. 채널별 재투입 규격

재투입(모드 B) 시 채널마다 다음을 적용합니다.

| 채널 | L1 유지 | L3 새로 작성 | 후속 스킬 |
|------|---------|-------------|----------|
| 책 | 사실·수치·출처·경험 사례 | 문체·서술·장 구성 | book-writing-pro |
| 강의 | 비교 데이터·통계·실습 예제 | 슬라이드 메시지·전환 | lecture-research → lecture-slides |
| 블로그 | 핵심 개념·출처 | 제목·도입·소제목 | write-blog |
| 페북 | 핵심 주장 | 후크·더보기 인트로 | write-facebook |
| 네이버 | 정보·수치 | 검색 키워드·모바일 가독성 | write-naver-info |

공통 규칙:
- L1(위키의 사실·수치·출처)은 변경 없이 인용합니다.
- 위키에 없는 사례·수치를 임의 보충하지 않습니다. 필요하면 빈틈으로 표시하고 보충 리서치를 권합니다.
- 산출물 끝에 근거 위키 페이지명을 표기합니다.
