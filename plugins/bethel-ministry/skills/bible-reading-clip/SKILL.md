# 성경봉독 절 클립 추출 (bible-reading-clip)

사용자(김병국 목사)는 파이널컷프로에서 하듯 특정 절 구간만 골라 클립으로
만들고 싶어 하지만, Claude는 파이널컷프로 GUI를 조작할 수 없다. 대신 ffmpeg로
똑같은(또는 더 정밀한) 결과를 만든다. 이 스킬은 그 작업을 다시 손으로
반복하지 않도록, 절 경계를 자동으로 찾고 잘라 붙이고 엔딩 캡션까지 합성하는
과정을 스크립트로 묶어 놓은 것이다.

왜 이렇게까지 자동화하는가: 이 템플릿(공동체 성경읽기)은 매주 같은 레이아웃을
쓰는 시리즈이기 때문에, 절 번호 위치·전환 타이밍·엔딩 캡션 스타일이 챕터가
바뀌어도 거의 그대로 유지된다. 즉 한 번 제대로 풀어둔 로직이 앞으로 계속
재사용될 수 있다는 뜻이다.

## 준비물 확인

1. **원본 영상**: 자르려는 챕터 전체가 담긴 mp4 (예: "마태복음 11장.mp4").
   이 영상은 아직 엔딩 캡션이 없는, 낭독만 이어지는 형태인 경우가 많다.
2. **원하는 절 범위**: 사용자가 말한 구간을 그대로 받되, 혹시 성서정과
   본문처럼 중간 절을 건너뛰는 구간(예: 16-19, 25-30)인지 확인한다.
3. **참고(완성본) 영상**(선택): 이미 엔딩 캡션까지 들어간 과거 영상이 있으면
   함께 확인해서 문구·색·위치가 여전히 같은지 검증한다. 없으면
   `references/style_notes.md`에 정리된 기본값을 그대로 쓴다.

애매한 점(어느 구간인지, 엔딩 캡션을 넣을지 말지, 참고 영상이 이번에도
유효한지)이 있으면 작업 전에 먼저 사용자에게 확인한다.

## 작업 순서

### 1. 기술 정보 확인

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 "원본.mp4"
```

전체 길이를 파악해두면 이후 단계에서 이상한 값(예: 음수 구간, 길이 초과)을
바로 알아챌 수 있다.

### 2. 참고 영상이 있다면 엔딩 캡션 스타일을 먼저 눈으로 확인

참고 영상 끝부분에서 프레임 몇 장을 뽑아 Read 도구로 직접 본다:

```bash
ffmpeg -y -sseof -3 -i "참고영상.mp4" -frames:v 1 ref_end.png
```

`references/style_notes.md`에 적힌 기본 문구("인도자 : 이 말씀은 하나님의
말씀입니다." / "회   중 : 하나님, 감사합니다.")·색상(RGB 251,32,0)·위치와
같은지 비교한다. 다르면(절기가 바뀌어 문구가 달라졌거나 스타일이
수정됐다면) `build_clip.py`에 `--ending-line1/--ending-line2/--ending-color`
로 새 값을 넘긴다. 이 확인은 자동화하지 않는다 — 한글 문장을 OCR로 억지로
읽는 것보다 직접 보고 판단하는 게 훨씬 정확하다.

### 3. 클립 생성

`scripts/build_clip.py` 하나로 절 경계 탐지 → 구간별 컷 → 크로스페이드로
이어붙이기 → (필요하면) 엔딩 캡션 합성까지 전부 처리된다.

```bash
python3 scripts/build_clip.py \
  --source "마태복음 11장.mp4" \
  --ranges "16-19,25-30" \
  --output "마태복음 11장(16-19,25-30) 봉독본.mp4"
```

**이 명령은 한 번에 끝나지 않는다 — 일부러 그렇게 만들었다.** 몇 분짜리
영상을 처음부터 끝까지 인코딩하는 작업은 한 번의 셸 명령이 편하게 기다려줄
수 있는 시간보다 오래 걸릴 수 있다. 그래서 이 스크립트는 매번 "한 단계"만
처리하고 멈춘다. 실행하면 `STEP DONE: ...` 과 `Run this same command again
to continue.` 가 출력되는데, 그러면 **정확히 같은 명령을 다시 실행**하면
된다. 진행 상황은 작업 디렉터리에 체크포인트로 저장되므로 중간에 멈췄던
지점부터 이어서 진행한다. `ALL DONE -> ...`이 출력되면 그 경로에 완성된
mp4가 있는 것이다. 도중에 어느 한 번이 시간 제한에 걸려 오류로 끝나더라도,
그 단계가 스스로 재시도 가능하게 되어 있으므로 당황하지 말고 같은 명령을 한
번 더 실행하면 된다.

절을 건너뛰지 않는 단일 구간이면 `--ranges "25-30"`처럼 쓰면 된다. 엔딩
캡션이 필요 없는 경우(이미 있는 영상이거나 그냥 발췌만 필요할 때)는
`--no-ending`을 추가한다.

내부적으로 하는 일 (자세한 근거는 각 스크립트의 docstring과
`references/style_notes.md` 참고):

- `verse_timeline.py`의 로직으로 1fps 프레임을 뽑아 절 번호 영역만 잘라
  OCR로 읽고, 초 단위 "몇 초에 몇 절이 떠 있는지" 타임라인을 만든다(여러
  ffmpeg/tesseract 호출을 병렬로 돌려서 몇 분짜리 챕터도 20초 안팎에
  끝난다).
- 소스 전체 오디오에 `ffmpeg silencedetect`를 한 번 돌려 무음(나레이션
  사이 pause) 구간 목록을 만들어둔다.
- 각 요청 구간에 대해, 절 번호가 화면에서 사라지는 시점 기준 안전한
  "화면 컷 지점"을 먼저 잡고, 그 근처의 실제 무음 구간을 찾아 "오디오 컷
  지점"으로 스냅한다. **이 템플릿은 나레이션이 채 끝나기 전에 화면이 먼저
  다음 절로 넘어가는 경우가 있어서**, 두 지점이 다를 수 있다 — 이때는
  화면은 화면 컷 지점에서 마지막 프레임으로 얼리고(freeze), 오디오만
  오디오 컷 지점까지 자연스럽게 이어서 재생한다. 그 결과 다음 절(또는
  건너뛴 절)의 그림이 절대 비치지 않으면서도 나레이션은 문장 끝까지
  온전히 들린다.
- 각 구간을 정확히 재인코딩해서 잘라내는데, 이때 **맨 처음 구간에는 흰색
  페이드인을, (엔딩 캡션을 쓰지 않는 경우) 맨 마지막 구간에는 페이드아웃을
  함께 구워 넣는다.** 완성된 클립 전체를 다시 한 번 통으로 재인코딩해서
  페이드를 입히는 대신 이렇게 하는 이유는, 몇 분짜리 결과물 전체를 다시
  인코딩하는 건 시간이 오래 걸리고 이 환경에서는 종종 시간 제한을 넘기기
  때문이다 — 이미 다시 인코딩하는 김에 공짜로 끼워 넣는 게 훨씬 안전하다.
- **절을 건너뛰는 구간이 여러 개면**, 각 구간이 끝난 자리에 짧은 무음
  정지 구간(기본 0.6초, `--skip-pause`)을 끼워 넣어 "건너뛴다"는 느낌이
  느껴지도록 살짝 호흡을 준 다음 다음 구간으로 크로스페이드한다.
- 구간 사이는 0.5초 크로스페이드로 이어 붙인다(원본 자체가 절마다
  크로스페이드로 넘어가는 스타일이기 때문에 건너뛴 구간 사이도 같은
  톤으로 자연스럽게 연결된다).
- **엔딩 캡션 앞에 자연스러운 무음 구간을 못 찾은 경우**(마지막 구간의
  나레이션이 화면 컷 근처까지 계속 이어지는 드문 경우), 엔딩 캡션을 붙이기
  전에 짧은 백지 쿠션(정지 프레임 + 무음 0.5초)을 자동으로 하나 더 끼워
  넣어 나레이션 꼬리와 캡션이 부딪히지 않게 한다.
- 엔딩 캡션을 만들 때는 새 그림을 그리는 게 아니라 **마지막으로 남긴 절의
  배경 이미지를 그대로 재사용**해서, 기존 텍스트 블록만 흰색으로 지우고 그
  자리에 빨간 응답 문구를 앉힌다. 그래서 엔딩 캡션도 다른 절 전환과 똑같이
  크로스페이드로 자연스럽게 넘어가고, 흰색 페이드아웃도 이 짧은 엔딩 클립
  자체에 구워 넣는다(기본 0.35초 페이드인 / 0.5초 페이드아웃).
- 마지막으로, 완성된 파일을 작업 디렉터리에서 `--output` 경로로 그대로
  복사한다(재인코딩이 아니라 단순 파일 복사라 순식간에 끝난다).

각 STEP이 출력하는 컷 지점 메시지에 `"WARNING"`이 보이면, 그 구간 근처에서
무음을 못 찾았다는 뜻이다 — 결과물을 눈으로/귀로 한 번 더 확인하는 게
좋다.

### 4. 컷 지점 눈으로 검증

특히 처음 써보는 챕터거나 절 길이가 유난히 짧은 구간이 섞여 있다면, 완성된
클립에서 각 구간의 시작/끝 부근 프레임을 몇 장 뽑아 확인한다:

```bash
ffmpeg -y -i "결과물.mp4" -ss <시간> -frames:v 1 check.png
```

확인할 것: (1) 요청한 절 번호만 순서대로 나오고 건너뛴 절이 안 보이는지,
(2) 구간 전환이 이전 절의 잔상 없이 매끈한지, (3) 엔딩 캡션 문구·색·위치가
참고 영상과 같아 보이는지. 여러 지점을 한 번에 보고 싶으면 PIL로 그리드
이미지를 만들어 Read 한 번으로 훑어보는 게 효율적이다 (Python으로 이미지들을
세로/격자로 이어 붙이는 것).

### 5. 파일 이름 정하기

최종 결과 파일명은 `yyyymmdd_성경봉독(해당교회력).mp4` 형식을 쓴다
(예: `20260628_성경봉독(성령강림절후5주).mp4`, 참고 영상들과 같은 규칙).

1. **yyyymmdd**: 작업하는 날짜에서 가장 가까운 주일(일요일)을 구한다.
   직접 계산하지 말고 `scripts/nearest_sunday.py`를 쓴다(요일 계산 실수를
   막기 위함):
   ```bash
   python3 scripts/nearest_sunday.py           # 오늘 기준
   python3 scripts/nearest_sunday.py --date 2026-07-04   # 특정 날짜 기준
   ```
2. **해당교회력**: 그 주일의 전례력(교회력) 절기 이름(예: "성령강림절후5주",
   "대림절1주", "사순절3주" 등)을 확인한다. 참고 영상 파일명(예:
   `20260607_성경봉독(성령강림절후2주).mp4`, `20260628_성경봉독(성령강림절후5주).mp4`)이
   있으면 그 규칙(같은 절기면 주차가 3주씩 증가하는 패턴 등)을 참고해서
   유추할 수 있는지 먼저 확인한다. **조금이라도 불확실하면 추측하지 말고
   사용자에게 이번 주일이 교회력으로 몇 절기인지 직접 물어본다** — 틀린
   절기명으로 파일명을 만드는 것보다 한 번 확인하는 게 훨씬 낫다.
3. 두 값을 합쳐 최종 파일명을 만들고, `build_clip.py --output`에 이
   파일명을 지정한다.

### 6. 전달

`mcp__cowork__present_files`로 결과 mp4를 사용자에게 전달한다. 무엇을
잘라냈는지(절 범위), 엔딩 캡션을 넣었는지 여부만 짧게 언급한다 — 과정을
장황하게 설명할 필요는 없다.

## 참고 자료

- `references/style_notes.md`: 템플릿 레이아웃, 크롭 좌표, 엔딩 캡션의 정확한
  문구/색상/위치, 그리고 이 값들이 왜 그렇게 설정됐는지에 대한 근거.
- `scripts/verse_timeline.py`: 절 번호 타임라인만 뽑아내는 독립 스크립트
  (디버깅하거나 `build_clip.py --timeline`으로 재사용하고 싶을 때).
- `scripts/build_clip.py`: 전체 파이프라인을 실행하는 메인 스크립트. `--help`로
  모든 옵션(버퍼 조정, 전환 길이, 엔딩 홀드 시간, 스킵 포즈 길이 등) 확인 가능.
- `scripts/nearest_sunday.py`: 파일명에 쓸 "가장 가까운 주일" yyyymmdd를
  계산하는 작은 유틸리티 (5단계 "파일 이름 정하기" 참고).

## 알아두면 좋은 점 / 한계

- 이 스크립트는 "공동체 성경읽기" 템플릿 전용이다. 완전히 다른 자막 스타일의
  영상이면 `--crop-rel`부터 다시 잡아야 한다.
- 절 하나가 화면에 1초도 안 뜨는 극단적으로 짧은 경우(예: 매우 짧은 후렴구)는
  기본 버퍼 값이 안 맞을 수 있다. 이런 구간이 섞여 있다면 4단계 검증을 꼭
  거치고, 필요하면 `--start-buffer`/`--end-buffer`를 조정한다.
- tesseract, ffmpeg, Pillow(PIL)가 설치돼 있어야 한다. 이 실행 환경에는 이미
  다 있는 것으로 확인됐다.
- `build_clip.py`는 진행 상황을 시스템 임시 폴더(기본값)에 체크포인트로
  저장한다. `--workdir`를 직접 지정할 경우, 사용자에게 전달할 최종
  결과물을 두는 폴더(예: outputs 폴더)는 피해야 한다 — 그런 폴더는 한 번
  쓴 파일을 지우거나 덮어쓰지 못하게 막아둔 경우가 있어서, 진행 상황을
  거기 저장하면 중간에 막힐 수 있다. `--output`으로 지정한 최종 파일만
  마지막에 그 폴더로 복사되므로 이 문제와 무관하다.
- "Run this same command again to continue."가 나오는 건 버그가 아니라
  정상 동작이다. 같은 명령을 그대로 반복 실행하면 된다.
- 무음 감지(`silencedetect`) 임계값은 `-20dB`로 맞춰져 있다(이 템플릿의
  배경음악 톤 기준 실측값). 완전히 다른 녹음 톤/배경음이면 이 값이 안 맞을
  수 있으니, `references/style_notes.md`의 "오디오가 끝까지 끊기지 않게
  자르는 법" 항목을 참고해 검증한다.
- 결과물을 1fps로 OCR 검증할 때, 구간 사이 크로스페이드가 진행되는
  0.1~0.3초짜리 프레임 하나가 가끔 엉뚱한 숫자로 읽힐 수 있다(예: 19에서
  25로 넘어가는 디졸브 중간에 "29"처럼 읽히는 경우). 이건 실제 화면에
  그 절 번호가 뜬 게 아니라 두 이미지가 겹쳐 보이는 크로스페이드 중간
  프레임을 OCR이 잘못 읽은 것뿐이다 — 사람 눈으로 보면 자연스러운
  디졸브로 보인다. 눈으로 검증할 때(4단계) 이 점을 헷갈리지 않는다.
