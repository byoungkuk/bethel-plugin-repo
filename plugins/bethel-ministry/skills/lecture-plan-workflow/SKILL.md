# 강의안 워크플로우 (Lecture Plan Workflow)

강의 기획서(강의안)를 구조적으로 작성하는 3단계 프로세스.
주제와 대상 정보를 입력받아, 제안·기획·등록에 바로 쓸 수 있는 강의안 문서를 생성한다.

## 보조 참조 파일

| 파일 | 용도 | 읽는 시점 |
|------|------|-----------|
| `references/template.md` | 강의안 섹션별 구조·작성 규칙·분량 기준 | Step 2 시작 전 |
| `references/sample.md` | 완성 강의안 예시 (기업 제안용 + 내부 기획용) | Step 2 작성 시 참고 |

---

## 전체 흐름

```
Step 1: 입력 수집·정리 → Step 2: 강의안 초안 작성 → Step 3: 리라이팅·최종 출력
```

사용자 상태에 따라 진입점을 조정한다.
- 주제만 있음 → Step 1부터 (필요 정보를 질문으로 수집)
- 목차·대상이 있음 → Step 2부터 (빠진 항목만 추정 후 명시)
- 초안이 있음 → Step 3부터

### 패스트트랙 (Step 1~2 통합 처리)

주제·대상·시간 3가지가 모두 명시된 경우 Step 1~2를 **하나의 턴**에서 통합 처리한다.

- Step 1 입력 정보를 상단에 간략 정리
- 선택 입력 항목은 합리적으로 추정하되, 추정 내용을 명시
- 이어서 Step 2 강의안 초안까지 한 번에 제시
- 사용자 확인 후 바로 Step 3으로 진입

패스트트랙 판단 기준: 주제·대상·시간이 모두 한 메시지에 있으면 자동 적용.
용도·형태가 빠져 있으면 기본값(기업·기관 제안용, 오프라인)을 적용하고 명시한다.

---

## 공통 원칙

### 강의안의 성격

강의안은 **기획 문서**다. 읽는 사람은 교육 담당자, 기관 관계자, 또는 강사 본인이다.
글의 목적은 "이 강의가 무엇을 다루고, 누구에게 필요하며, 어떤 구조로 진행되는가"를
한 문서에서 판단할 수 있게 하는 것이다.

### 문체 기준

- **설명 중심, 판단 기준 제시형**: 가르치지 않되 이끄는 어조
- **단정형 문장**: "~할 수 있습니다" 대신 "~합니다" / "~한다"
- **금지어**: 과장형 형용사(혁신적인, 획기적인), 모호한 부사(매우, 쉽게), 추측 표현(~할 수 있습니다)
- **구체적 서술**: 형용사 대신 행동·상태·결과를 설명하는 단어 사용

### 용도별 톤 조정

| 용도 | 톤 | 특징 |
|------|-----|------|
| **기업·기관 제안용** | 격식체(~합니다) | 교육 목표·기대 효과 강조, 교육 대상자 명확히 기술 |
| **내부 기획용** | 반말/메모체(~한다) | 핵심만 간결하게, 실행 중심 |
| **플랫폼 등록용** | 격식체(~합니다) | 수강 혜택·차별점 부각, 학습자 관점 서술 |
| **특강·단발 제안용** | 격식체(~합니다) | 1~3시간 분량, 핵심 메시지 집중 |

용도를 명시하지 않으면 **기업·기관 제안용**을 기본값으로 적용한다.

## Step 1: 입력 수집·정리

사용자에게 다음 정보를 수집한다. 이미 제공된 항목은 건너뛴다.

### 필수 입력

| 항목 | 질문 | 예시 |
|------|------|------|
| **주제** | 무엇을 가르치는가? | Claude 글쓰기 스킬 만들기 |
| **대상** | 누가 듣는가? 현재 수준은? | 기업 마케터, AI 도구 초보 |
| **시간** | 총 강의 시간은? (회차 포함) | 3시간 × 1회 / 2시간 × 4회 |

### 선택 입력 (없으면 합리적으로 추정)

| 항목 | 질문 | 기본값 |
|------|------|--------|
| **용도** | 이 강의안을 어디에 쓰는가? | 기업·기관 제안용 |
| **강의 형태** | 오프라인/온라인/혼합? | 오프라인 |
| **실습 비율** | 이론 대 실습 비율은? | 4:6 (도구 강의 기본값) |
| **핵심 도구** | 주요 사용 도구는? | 주제에서 추정 |
| **특별 요청** | 꼭 포함할 내용이나 조건? | 없음 |

### Step 1 산출물

수집한 정보를 아래 형태로 정리하여 사용자 확인을 받는다.

```
[강의안 입력 정보]
- 주제: ___
- 대상: ___
- 시간: ___
- 용도: ___
- 형태: ___
- 이론:실습 비율: ___
- 핵심 도구: ___
- 특별 요청: ___
```

확인 후 Step 2로 진행한다.

## Step 2: 강의안 초안 작성

**시작 전 반드시 `references/template.md`를 읽는다.**
작성 시 `references/sample.md`를 참고한다.

Step 1에서 정리한 입력 정보를 바탕으로 template.md의 7개 섹션 규칙에 따라 순서대로 채운다.

### 강의안 7개 섹션 (상세 규칙은 template.md 참조)

1. **강의 제목** — 주제와 핵심 가치를 한 문장에 담는다
2. **강의 소개** — 왜 이 강의가 필요한지, 무엇을 다루는지 3~5문장
3. **학습 목표** — 수강 후 할 수 있는 것 3~5개, 행동 동사로 시작
4. **강의 대상** — 누구에게 적합한지 + 사전 지식 수준
5. **강의 목차** — Ch 단위 구성 + 세부 항목 + 시간 배분
6. **강의 운영 방식** — 형태, 실습 비율, 도구/환경, 교재/자료
7. **기대 효과** — 수강 후 변화, 업무 적용 시나리오

용도에 따라 섹션별 포함 수준이 달라진다. template.md의 **용도별 섹션 매트릭스**를 따른다.

### Step 2 산출물

강의안 초안을 대화창 텍스트로 제시한다.
사용자의 수정 요청을 반영한 뒤 Step 3으로 진행한다.

---

## Step 3: 리라이팅·최종 출력

### 셀프 체크리스트 (리라이팅 전 확인)

- [ ] 강의 제목이 주제와 가치를 모두 담고 있는가?
- [ ] 강의 소개가 "왜 필요한가"를 설명하는가? (기능 나열이 아닌가?)
- [ ] 학습 목표가 행동 동사로 시작하는가?
- [ ] 대상 기술에 사전 지식 수준이 명시되어 있는가?
- [ ] 목차의 세부 항목이 행동·판단 중심 문장인가?
- [ ] 시간 배분이 실제 진행 가능한 분량인가?
- [ ] 금지어(과장형·모호형·추측형)가 없는가?
- [ ] 용도에 맞는 톤(격식체/메모체)이 일관되는가?

### 리라이팅 처리

사용자 명령에 따라 수준을 구분한다.

| 명령 | 처리 수준 |
|------|-----------|
| "다듬어줘" | 문장 단위 교정 (구조·분량 유지) |
| "수정해줘" | 섹션 단위 재작성 (구조 유지, 내용 보강) |
| "전면 수정해줘" | 전체 재설계 (구조 변경 가능) |

### 최종 출력

- 대화창 텍스트로 최종본 제시
- 사용자 요청 시 `.docx` 파일로 저장·제공
- `.docx` 생성 시 `/mnt/skills/public/docx/SKILL.md`를 먼저 읽고 따른다
