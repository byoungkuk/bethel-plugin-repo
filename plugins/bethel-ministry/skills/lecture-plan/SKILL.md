# lecture-plan v2.1

강의 기획서를 구조화된 문서로 생성하는 4단계 프로세스. 파이프라인 1단계.

v2 대비 개선점: lecture-blueprint 연계 추가(반일 이상 강의 분기), YAML에 next_skill 명시, 관문 1 역할을 "리서치 진입 검증"으로 명확화.

## 파이프라인 위치

```
lecture-plan [관문 1] → lecture-research [관문 2] → lecture-blueprint [관문 BP] → lecture-slides [관문 3] → lecture-review
```

## 언제 사용하나

- 강의 주제는 있지만 기획서가 없을 때
- 기업·기관·플랫폼 제안용 기획서가 필요할 때
- 내부 커리큘럼 설계가 필요할 때

## 언제 사용하지 않나

- 슬라이드 1장 단위 설계(블루프린트) → lecture-blueprint
- 강의 리서치 → lecture-research
- 슬라이드 제작 → lecture-slides
- 블로그 강좌 소개 → write-course-intro

## 입력

### 필수
- 강의 주제 또는 초안

### 선택
- 대상 기관·기업 정보
- 강의 시간·운영 형태
- 기존 커리큘럼 참조 자료
- 리서치 노트(RL_*.md)

## 프로세스

### Phase 1. 입력 수집·정리

아래 항목을 사용자에게 확인한다. 누락 시 Phase 1.5로 넘어가기 전에 1회 확인.

- **강의 제목**: 30자 이내, 구체적
- **강의 시간**: 분 단위 명시 (예: 180분)
- **운영 형태**: 녹화형 / 현장형 / 온라인 실시간 / 혼합
- **제안 용도**: 기업 / 기관 / 플랫폼 등록 / 내부 기획
- **대상 기관·기업**: (있으면)
- **주제 범위**: 포함/제외

### Phase 1.5. 타깃 프로파일 추출 (신규)

"강의 대상 = 일반 직장인" 같은 추상적 정의를 피한다. 아래 5항목을 구조화해 뽑아낸다.

```
- 직무/업종: (예: 중소기업 마케터 / 공공기관 중간관리자)
- 사전지식: (AI 도구 사용 경험, 관련 개념 친숙도)
- 관심 맥락: (동기 — 실무 적용, 비용 절감, 승진, 규제 대응 등)
- 이탈 요인: (너무 기술적, 추상적, 본인 업무와 거리, 영어 원문)
- 반응 요인: (본인 직무 유사 사례, 숫자 결과, 비포/애프터, 실습)
```

**작성 규칙**
- 직무/업종은 구체적 직함 또는 업종명. "일반 직장인", "누구나" 금지
- 이탈 요인·반응 요인은 각각 2개 이상 필수
- 복합 타깃(예: 마케터 + 기획자)인 경우 주/부 프로파일 분리

사용자에게 제시 후 확인. 확인 불가 항목은 "미정 — 리서치 단계에서 재확인"으로 표시.

### Phase 2. 강의안 초안 작성

아래 템플릿으로 초안 생성.

```markdown
# {강의 제목}

## 강의 소개
{3~5문장. 왜 이 강의가 필요한지, 무엇을 다루는지, 어떻게 진행되는지}

## 타깃 프로파일
- 직무/업종: {...}
- 사전지식: {...}
- 관심 맥락: {...}
- 이탈 요인: {...}
- 반응 요인: {...}

## 학습 목표
강의 종료 후 수강생은 다음을 할 수 있다.
1. {행동 동사}로 {대상}을 {수준}까지 {할 수 있다}
2. ...
3. ...

## 강의 대상
- 주 대상: {...}
- 부 대상: {...}
- 권장 사전지식: {...}

## 강의 목차

### Ch1. {꼭지 제목} ({N}분)
- 세부 항목: {...}
- 수강생 산출물: {꼭지 종료 시 수강생이 알게 되거나 만든 것}
- 실습 포함 여부: {있음/없음}

### Ch2. {꼭지 제목} ({N}분)
...

**총 소요 시간**: {합계 = 강의 시간}

## 운영 방식
- 진행 형태: {...}
- 실습 비중: {...%}
- 준비물: {...}
- 수강생 과제: {있음/없음}

## 기대 효과
- 개인 차원: {...}
- 조직 차원: {...}

## 사전 질문지 (6~8문항)
1. {수강생 현재 수준 파악}
2. {업무 맥락 파악}
3. {기대사항 파악}
...
```

**학습 목표 행동 동사 규칙 (필수)**

금지 동사: 이해한다, 안다, 파악한다, 숙지한다, 익힌다

허용 동사 (Bloom's Taxonomy 기반):
- 기억: 열거한다, 구분한다, 식별한다
- 이해: 설명한다, 요약한다, 예시를 든다
- 적용: 적용한다, 실행한다, 만든다, 사용한다
- 분석: 비교한다, 분해한다, 진단한다
- 평가: 평가한다, 선택한다, 판단한다
- 창조: 설계한다, 구성한다, 생성한다

**목차 꼭지 시간 배분 규칙 (필수)**

- 꼭지당 예상 시간을 분 단위로 명시
- 합계가 강의 총 시간과 일치해야 함
- 권장 꼭지 길이: 15~45분 (이보다 길면 분할 권장)
- 쉬는 시간·실습 시간 별도 표기

**수강생 산출물 필드 규칙 (필수)**

각 꼭지 종료 시 수강생이 얻는 것을 1문장으로 명시. 예:
- "자사 마케팅 카피 1개를 AI로 생성할 수 있다"
- "프롬프트 템플릿 3종을 직접 작성한다"
- "AI 도구 5종의 장단점을 비교표로 정리한다"

추상적 표현("AI에 대한 이해") 금지. 구체적 행동·결과물 중심.

### Phase 3. 관문 1 검증 및 리라이팅

초안 완성 후 아래 관문 체크리스트를 실행한다. **10개 이상 통과 시** 리라이팅으로 진행, 미만이면 부족 항목 보완 후 재검증.

#### 관문 1: 리서치 진입 검증

**기본 정보 (4개)**
- [ ] 강의 제목이 30자 이내로 구체적인가
- [ ] 강의 시간이 분 단위로 명시되었는가
- [ ] 운영 형태가 명시되었는가 (녹화/현장/온라인/혼합)
- [ ] 제안 용도가 명시되었는가

**타깃 프로파일 (5개)**
- [ ] 직무/업종이 구체적인가 (일반 직장인 X)
- [ ] 사전지식 수준이 명시되었는가
- [ ] 관심 맥락이 1개 이상 명시되었는가
- [ ] 이탈 요인이 2개 이상 명시되었는가
- [ ] 반응 요인이 2개 이상 명시되었는가

**학습 목표·목차 (3개)**
- [ ] 학습 목표가 행동 동사(금지어 제외)로 작성되었는가
- [ ] 목차 꼭지당 예상 시간이 명시되었고 합계가 강의 시간과 일치하는가
- [ ] 각 꼭지에 수강생 산출물이 구체적으로 명시되었는가

**통과 기준**: 12개 중 10개 이상

**실패 시 대응**
- 1회 실패: 부족 항목을 사용자에게 제시하고 보완 요청
- 2회 연속 실패: "기획안 재작성 권장" 알림 + Phase 1로 회귀

#### 다음 스킬 자동 권장 (신규)

관문 1 통과 후, 예상 슬라이드 수에 따라 다음 스킬을 자동 권장한다.

**예상 슬라이드 수 산정**

- 꼭지 수 × 평균 슬라이드 수(3~5장) + 도입/정리 슬라이드(2장)
- 예: 4꼭지 × 4장 + 2 = 18장

**분기 규칙**

| 예상 슬라이드 수 | 권장 다음 스킬 | YAML next_skill |
|-----------------|---------------|-----------------|
| 15장 이상 | lecture-research → lecture-blueprint | lecture-blueprint |
| 10~14장 | lecture-research → lecture-blueprint (선택) | lecture-blueprint |
| 10장 미만 | lecture-research → lecture-slides (BP 생략 가능) | lecture-research |

**사용자 확인 메시지**

```
예상 슬라이드 수: {N}장
다음 권장 경로: {권장 스킬 체인}
BP 스킬 진행하시겠습니까? (Y/N)
```

#### 리라이팅

관문 통과 후 아래 규칙으로 리라이팅.

- 과장형 형용사 제거 (혁신적인, 획기적인, 완벽한)
- 모호한 부사 제거 (매우, 쉽게, 빠르게)
- 추측 표현 제거 (~할 수 있습니다)
- 설명 중심 능동형 문장
- 제안 용도에 맞는 톤 조정

### Phase 4. 최종 출력

- 파일명: `LP_{강의명}_{YYYYMMDD}.md`
- YAML 프론트매터

```yaml
---
title: {강의명} 기획서
type: lecture-plan
lecture_title: {강의 제목}
lecture_duration_minutes: {시간}
lecture_format: {녹화/현장/온라인/혼합}
proposal_type: {기업/기관/플랫폼/내부}
target_profile:
  job: {직무/업종}
  prior_knowledge: {사전지식}
  motivation: {관심 맥락}
  avoid: {이탈 요인}
  react: {반응 요인}
expected_slide_count: {N}
gate_1_passed: true
gate_1_score: {N}/12
gate_1_checked_at: {YYYY-MM-DD}
next_skill: {lecture-blueprint | lecture-research}
created: {YYYY-MM-DD}
tags: [lecture, plan, LP]
---
```

## 출력

- `LP_{강의명}_{YYYYMMDD}.md` 1개 (대화창 텍스트 + .md 파일)
- 관문 1 통과 시 `gate_1_passed: true` 플래그 기록
- 실패 시 부족 항목 리포트 별도 제시
- 저장 직후 다음 스킬 자동 제안 메시지 출력

## 연계 스킬

- **입력**: (없음 — 파이프라인 1단계)
- **출력 연계(필수)**: lecture-research (YAML의 target_profile 블록을 그대로 전달)
- **출력 연계(반일 이상 강의)**: lecture-blueprint (꼭지 단위를 슬라이드 단위로 분해)
  - 슬라이드 15장 이상 예상 시 lecture-research 이후 lecture-blueprint 실행 권장
  - YAML에 `next_skill: lecture-blueprint` 자동 기록

## Harness 블록

| 항목 | 값 |
|------|-----|
| **원문 보존 레벨** | L1 (요약형) — 사용자 입력을 기획서 형식으로 재구성 |
| **생성-평가 분리** | 초안 생성 → 관문 1 검증 → 실패 시 재작성 → 리라이팅 |
| **분량 가드레일** | 기획서 전체 2,000~4,000자 (강의 시간 비례) |
| **재생성 트리거** | 관문 1 점수 10/12 미만 |

### 자가 평가 루프

**초안 직후**
- [ ] 타깃 프로파일 5항목이 모두 채워졌는가
- [ ] 학습 목표가 행동 동사 규칙을 통과하는가
- [ ] 꼭지별 시간 합계가 강의 시간과 일치하는가
- [ ] 꼭지별 수강생 산출물이 구체적인가

**관문 1 직후**
- [ ] 12개 항목 중 10개 이상 통과했는가
- [ ] 실패 항목에 대한 보완이 이뤄졌는가
- [ ] YAML 프론트매터의 gate_1_passed 플래그가 기록되었는가
- [ ] YAML 프론트매터의 next_skill이 기록되었는가 (신규)
- [ ] 예상 슬라이드 수에 따라 BP 분기가 사용자에게 안내되었는가 (신규)

## 실행 원칙

- 주제만 있는 경우 Phase 1부터 순차 진행
- 기존 기획서가 있는 경우 Phase 1.5부터 시작 (타깃 프로파일 점검)
- 타깃 프로파일 확인 불가 항목은 "미정 — 리서치 단계에서 재확인"으로 표시
- 학습 목표에 금지 동사 사용 시 자동 교체 (이해한다 → 설명한다)
- 꼭지 시간 합계 불일치 시 사용자에게 조정 요청
- 관문 1 통과 전에는 lecture-research 진입 금지
- 예상 슬라이드 수 15장 이상이면 lecture-blueprint 호출을 사용자에게 확인
- 금지어 규칙 적용 (과장형 형용사·추측 표현·AI 흔적 제거)
