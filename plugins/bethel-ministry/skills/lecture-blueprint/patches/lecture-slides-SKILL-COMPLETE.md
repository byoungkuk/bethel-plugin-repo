# 강의 슬라이드 워크플로우 (Lecture Slides Workflow)

강의 설계부터 슬라이드 생성, 발표 자료까지 아우르는 5단계 프로세스.

## 전체 흐름

```
Phase 0: 파이프라인 산출물 스캔 → Phase 1: 강의 기획 → Phase 2: 커리큘럼 설계 → Phase 3: 슬라이드 구조화 → Phase 4: .pptx 생성 → Phase 5: 발표 노트 + 핸드아웃
```

**모든 호출은 Phase 0(파이프라인 산출물 스캔)을 먼저 거친다.**
Phase 0 결과에 따라 아래 경로로 진입한다.

- BP_*.md 발견 (통과) → Phase 3 (재해석 없이 조판)
- LP + RL 있음 → Phase 3 (LP 연계 블록 + RL 소재)
- LP만 있음 → Phase 3 (LP 연계 블록)
- 아무것도 없음 → Phase 1부터 (기존 경로)
- 15장 이상 예상이지만 BP 없음 → lecture-blueprint 실행 권장 안내 후 사용자 선택
- 기존 슬라이드 수정 → Phase 4에서 pptx 스킬로 직접 편집 (Phase 0 생략)

Phase 0 스캔 상세는 `## Phase 0: 파이프라인 산출물 스캔` 섹션 참조.

### lecture-plan 연계 입력 (Phase 1~2 스킵)

lecture-plan의 최종 산출물이 입력으로 제공된 경우, Phase 1~2를 건너뛰고 **Phase 3부터 시작**한다.

**연계 입력 판별 기준**: 다음 중 하나 이상을 충족하면 연계 입력으로 판단한다.
- 입력에 `## 슬라이드 연계 정보` 블록이 포함되어 있음
- 사용자가 "기획안을 기반으로 슬라이드 만들어줘" 등으로 명시
- 강의안 형태의 문서(Ch 구성 + 시간 배분 + 학습 성과)가 제공됨

**연계 시 매핑 규칙**:

| 기획안(lecture-plan) | 슬라이드(lecture-slides) |
|---------------------|------------------------|
| Ch 1 (전체 개요) | 모듈 1: 타이틀 + 개요 슬라이드 (3~5장) |
| Ch 2~N (본론 각 챕터) | 모듈 2~N: 각각 독립 모듈 (8~22장/모듈) |
| 마무리/Q&A | 최종 모듈: 요약 + Q&A (3~5장) |
| 쉬는 시간 | 쉬는 시간 슬라이드 삽입 (선택) |

**연계 블록에서 추출하는 정보**:
- Ch별 제목·시간·핵심 메시지 → Phase 3 슬라이드 목록의 기본 골격
- 실습 유형 → 실습 안내 슬라이드 구성에 반영
- 총 시간·대상·개념:실습 비율 → 모듈별 슬라이드 수 배분에 반영
- **슬라이드 소재 키워드** → Phase 3 슬라이드 유형 결정에 반영 (아래 참조)

연계 블록이 없는 강의안이 입력된 경우에도, Ch 구성과 시간 정보를 기반으로 동일한 매핑을 수행한다.

### lecture-blueprint 연계 입력 (Phase 1~2 스킵 + 재해석 금지)

lecture-blueprint의 최종 산출물(BP_*.md)이 입력으로 제공된 경우, Phase 1~2를 건너뛰고 **Phase 3부터 시작**하되, 다음 원칙을 따른다.

**재해석 금지 원칙**:
- BP 슬라이드 테이블의 제목·핵심 메시지·증거는 임의 변경하지 않는다
- 변경이 필요하면 BP로 되돌아가 Phase 2~4 재실행 후 다시 진입한다
- lecture-slides는 BP 텍스트를 T-유형 템플릿에 조판하는 역할만 수행한다

**BP 입력 판별 기준**: 다음 중 하나 이상 충족하면 BP 연계로 판단한다.
- 입력 YAML에 `type: lecture-blueprint` 포함
- 입력에 "슬라이드 테이블" + 9필드(# / Ch / T-유형 / 제목 / 핵심 메시지 / 증거/소재 / 시각 힌트 / 시간 / 노트 힌트) 포함
- 사용자가 "블루프린트를 기반으로 슬라이드 만들어줘" 등으로 명시
- Phase 0 스캔에서 BP가 발견되고 사용자가 "Y" 선택

**BP → Phase 3 매핑 규칙**:

| 블루프린트(lecture-blueprint) | 슬라이드(lecture-slides Phase 3) |
|------------------------------|----------------------------------|
| # (순번) | 슬라이드 번호 (그대로 사용) |
| T-유형 | 강의디자인템플릿 v0.3 블록 템플릿 직결 |
| 제목 | 슬라이드 제목 (수정 금지) |
| 핵심 메시지 | 본문 메인 카피 (수정 금지) |
| 증거/소재 | 본문 보조 텍스트·예시 |
| 시각 힌트 `[DIAGRAM/CHART/IMG]` | Phase 4 시각 자료 생성 목록 |
| 시간 | Phase 2 시간표 참고 (있으면) |
| 노트 힌트 | speaker notes 시드 |

**관문 BP 확인**: BP 입력 시 YAML의 `gate_bp_passed: true` 확인. false면 lecture-blueprint Phase 5로 되돌려보낸다.

### 슬라이드 소재 키워드 활용 규칙

lecture-plan의 슬라이드 연계 블록에 `### 슬라이드 소재 키워드` 섹션이 포함된 경우 (리서치 연계 기획안), Phase 3에서 다음과 같이 활용한다.

| 키워드 유형 | Phase 3 슬라이드 유형 매핑 |
|-----------|------------------------|
| 비교 (`A vs B`, `Before/After`) | **비교/대조** 슬라이드로 구조화 |
| 프로세스 (`Step 1 → 2 → 3`) | **프로세스** 슬라이드로 구조화 |
| 도식화 대상 (플로우·비교·구조) | **다이어그램** 슬라이드 → Phase 4에서 visual-diagram SVG로 직접 생성 |
| 데이터 (수치·차트) | **다컬럼 정보** 또는 별도 데이터 슬라이드로 구조화 |

키워드가 특정 Ch에 매칭되면 해당 모듈 내 슬라이드 유형을 키워드에 맞게 배치한다. 매칭이 불명확하면 가장 관련 높은 모듈에 배치하고, Phase 3 산출물에 배치 근거를 메모한다.

### 패스트트랙 (Phase 1~3 통합 처리)

**패스트트랙은 Phase 0 스캔 이후에만 작동한다.** Phase 0 결과가 다음 중 하나면 패스트트랙을 타지 않는다.

- BP_*.md 발견 (통과) → Phase 3 재해석 없이 조판 경로 우선
- LP 발견 → LP 연계 경로 우선
- "앞단 재실행" 또는 "BP로 진행" 선택 시 → 해당 경로 우선

Phase 0 스캔 결과 "아무것도 없음" + 사용자가 주제·대상·시간을 한 번에 제공한 경우에만 Phase 1~3을 **하나의 턴**에서 통합 처리한다.

- Phase 1 산출물(강의 개요, 학습 성과)을 간략히 정리
- Phase 2 산출물(시간표, 모듈 구성)을 이어서 설계
- Phase 3 산출물(슬라이드 목록)까지 한 번에 제시
- **색상**: 주제에 맞는 추천 색상을 자동 적용하고, 결과 제시 시 "악센트 색: OOO 적용. 변경을 원하시면 말씀해 주세요." 한 줄 안내
- 사용자 확인 후 바로 Phase 4로 진입

패스트트랙 판단 기준: 주제·대상·시간 3가지가 모두 명시된 경우 + Phase 0 스캔 결과 "없음"인 경우 자동 적용.
목표·환경이 빠져 있으면 합리적으로 추정하되, 추정 내용을 명시한다.

## 공통 원칙

### 슬라이드 서술 원칙
- 슬라이드 제목은 기능명이 아닌 **행동·판단 중심 문장**으로 작성
  - ❌ "레이어 기능" → ✅ "레이어로 구조를 분리하는 기준"
- 각 섹션의 첫 슬라이드: **"왜 이걸 배워야 하는가"**를 전달
- 정보 나열 금지 → **개념 → 기준 → 적용** 순서로 전개
- 슬라이드 1장 = 1메시지 원칙
- 텍스트 최소화: 핵심 키워드와 시각 요소 중심

### 금지 요소
- 기능 목록만 나열하는 슬라이드
- 문장 전체를 슬라이드에 그대로 옮기는 구성
- 결과물에 대한 감상형 캡션
- 내용 없이 화려하기만 한 장식 슬라이드

## Phase 0: 파이프라인 산출물 스캔 (진입 최상단, 필수)

lecture-slides가 호출되면 Phase 1로 바로 진입하지 않는다. 먼저 볼트에서 앞단 파이프라인(lecture-plan, lecture-research, lecture-blueprint)의 산출물이 존재하는지 자동 스캔한다. 이 단계가 빠지면 앞단 자산이 있어도 중복 재해석되는 드리프트가 발생한다.

### 실행 순서

1. **강의 식별자 추출**: 사용자 입력에서 강의명 또는 일정 일자를 추출한다
   - 예: "AI 이미지 생성 실무 강의 슬라이드 만들어줘" → 강의명: "AI 이미지 생성 실무"
   - 날짜 표기가 있으면 `YYMMDD` 형식으로 정규화

2. **산출물 스캔 (우선순위 BP → RL → LP 순)**:

| 파일 유형 | 탐색 경로 | 확인 항목 |
|-----------|-----------|-----------|
| BP_*.md | `10 외부 강의/00 일정별 강의/{강의 폴더}/기획/` | `type: lecture-blueprint`, `gate_bp_passed: true` |
| RL_*.md | `10 외부 강의/00 일정별 강의/{강의 폴더}/리서치/` | `type: lecture-research` |
| LP_*.md | `10 외부 강의/00 일정별 강의/{강의 폴더}/기획/` | `type: lecture-plan`, `gate_1_passed: true` |

반복 강의(경희사이버대·출판진흥원 등)는 `10 외부 강의/{11~14 기관 폴더}/` 하위도 탐색한다.

3. **진입 지점 결정 매트릭스**:

| 발견 결과 | 진입 지점 | 동작 |
|-----------|-----------|------|
| BP 있음 (통과) | Phase 3 | BP 재해석 없이 조판 |
| BP 없고 LP + RL 있음 | Phase 3 | LP 연계 블록 + RL 소재 키워드 기반 슬라이드 구조화 |
| LP만 있음 | Phase 3 | LP 연계 블록 기반 (RL 없는 경로) |
| LP 있으나 BP·RL 없고 15장 이상 예상 | Phase 3 전에 lecture-blueprint 권장 안내 | 사용자 확인 후 진입 지점 결정 |
| 아무것도 없음 | Phase 1 | 기존 경로 (주제부터 재설계) |

4. **사용자 확인 (필수)**:

스캔 결과를 사용자에게 명시적으로 보고하고, 진입 지점 선택을 확인받는다.

```
파이프라인 산출물 스캔 결과:
- LP_{강의명}_{날짜}.md ✓ (관문 1 통과 11/12)
- RL_{강의명}_{날짜}.md ✓
- BP_{강의명}_{날짜}.md ✓ (관문 BP 통과 9/9)

발견된 블루프린트 기준으로 재해석 없이 슬라이드를 조판합니다. 계속 진행할까요?
[Y] 현재 BP로 진행 (권장)
[M] 앞단 재실행 (LP·BP 수정 후 재조판)
[N] 파이프라인 무시하고 주제부터 재설계
```

5. **스캔 생략 조건**:
- 사용자가 명시적으로 "주제부터 새로 만들어줘" 또는 "앞단 무시"를 요청
- 슬라이드 10장 이하·30분 이하 특강 (과설계 방지)
- 기존 슬라이드 수정·편집 요청 (Phase 4 직행)

6. **산출물 기록**:
- Phase 0 스캔 결과와 사용자 선택을 Phase 3 산출물(`03-slide-structure.docx`) 상단에 기록
- 기록 형식: `파이프라인 진입 지점: BP → Phase 3 / 사용자 선택: Y`

### 스캔 우선순위 원칙

- BP가 있고 `gate_bp_passed: true`면 다른 산출물보다 우선한다 (BP가 가장 고정도 높은 단위)
- BP가 실패 상태면 "BP 재검증 권장" 안내 후, 사용자가 Y 선택 시에만 사용
- LP·RL·BP가 동일 강의명에 여러 버전 있으면 최신 파일(파일명 날짜 또는 수정일 기준)을 우선

## Phase 1: 강의 기획 (Lecture Planning)

> Phase 0에서 LP 또는 BP가 발견되면 이 단계를 건너뛴다.

사용자에게 다음 정보를 수집한다.

| 항목 | 질문 | 예시 |
|------|------|------|
| **주제** | 무엇을 가르치는가? | AI 이미지 생성, 프롬프트 설계 |
| **대상** | 누가 듣는가? 현재 수준은? | 입문자, 실무 마케터, 대학생 |
| **시간** | 총 강의 시간은? | 2시간, 반일(4시간), 1일(6시간) |
| **목표** | 수강 후 무엇을 할 수 있어야 하는가? | 독립적으로 프롬프트 설계 가능 |

## Phase 3: 슬라이드 구조화 (Slide Structure)

커리큘럼의 각 모듈을 슬라이드 단위로 분해한다.

> Phase 0에서 BP 또는 LP가 발견되면 이 단계부터 시작한다. BP 발견 시 재해석 없이 조판.

**→ 슬라이드 유형별 상세 레이아웃은 `references/slide-types.md`를 읽는다.**

### 슬라이드 유형 요약

| 유형 | 용도 | 핵심 구성 |
|------|------|----------|
| **타이틀** | 강의 시작 | 제목 + 부제 + 강사 정보 + 일러스트 |
| **섹션 구분** | 모듈 전환 | 원형 번호 + 섹션 제목 |
| **콘텐츠** | 핵심 내용 전달 | 번호 제목(판단 중심) + 일러스트 |
| **비교/대조** | 차이점 설명 | 제목 + 2분할 일러스트 |
| **프로세스** | 단계별 흐름 | 제목 + 카드×화살표 레이아웃 |
| **실습 안내** | 참여 유도 | 연한 배경 + 과제/조건/시간/힌트 카드 |
| **체크포인트** | 이해도 확인 | 질문 + 선택지 카드 (정답 악센트 테두리) |
| **다컬럼 정보** | 병렬 비교/로드맵 | 2~4컬럼 카드 + 항목 + 목표 |
| **요약/정리** | 섹션 마무리 | 핵심 포인트 + 일러스트 |
| **Q&A** | 질의응답 | 최소 텍스트, 질문 유도 문구 |

### 모듈별 슬라이드 배분 기준

| 모듈 시간 | 슬라이드 수 | 구성 |
|----------|------------|------|
| 20분 | 8~12장 | 섹션구분 1 + 콘텐츠 4~6 + 예시 2 + 정리 1 |
| 30분 | 12~16장 | 섹션구분 1 + 콘텐츠 5~8 + 예시 3 + 실습 1 + 정리 1 |
| 40분 | 16~22장 | 섹션구분 1 + 콘텐츠 7~10 + 예시 3~4 + 실습 2 + 정리 1 |

실습 모듈은 슬라이드 수가 적고 (5~8장), 실습 안내와 체크포인트 중심으로 구성한다.

### 슬라이드 소재 키워드 → 유형 배치

**배치 프로세스:**
1. 키워드 유형별로 슬라이드 유형을 결정한다 (위 "슬라이드 소재 키워드 활용 규칙" 참조)

3. 슬라이드 목록의 해당 위치에 유형·제목·핵심 내용을 기재한다
4. 배치 결과를 `03-slide-structure.docx`의 메모란에 표기한다

**시각화 후보 키워드 처리:**
- 도식화 키워드는 슬라이드 유형 결정과 동시에 Phase 4 시각 자료 생성 목록에 자동 등록한다

- 수치·통계·비율·추이 → `[CHART: 설명]` 태그 부여 (visual-chart로 생성)

### 산출물: `03-slide-structure.docx`

다음 항목을 포함:

## Phase 4: .pptx 생성 (Slide Production)

Phase 3의 구조를 기반으로 실제 슬라이드를 생성한다.

### 생성 전 필수 사항

1. **반드시 `references/template-spec.md`를 먼저 읽는다** — 슬라이드 크기, 색상, 폰트, 좌표 사양
2. **반드시 `/mnt/skills/public/pptx/SKILL.md`를 먼저 읽는다** — pptx 생성 기술 가이드, QA 절차
3. **반드시 `references/slide-types.md`를 읽는다** — 유형별 레이아웃 상세

### 강의 슬라이드 디자인 원칙

- **1슬라이드 = 1메시지**: 한 장에 여러 개념을 넣지 않음
- **텍스트 최소화**: 문장이 아닌 키워드·구문 중심 (발표 노트에 상세 설명)
- **일러스트 중심 구성**: 콘텐츠 슬라이드는 제목 + 대형 일러스트 이미지로 구성
- **일관된 레이아웃 패턴**: 같은 유형의 슬라이드는 같은 레이아웃
- **섹션별 번호 체계**: 섹션 구분 슬라이드에 원형 번호, 콘텐츠 슬라이드에 ①②③ 번호 접두사

### 색상 커스터마이징

**우선순위 (위에서 아래로)**

1. **사용자 직접 지정**: 사용자가 색상을 명시적으로 요청하면 그 값을 최우선 적용
2. **BP palette_key 경로**: Phase 0에서 발견된 BP의 YAML `palette_key` 값을 강의디자인템플릿 v0.3 팔레트 규칙에 따라 적용 (navy/darknavy/teal/slate/orange/purple/green/rose 중 1)
   - darknavy는 Amber 대신 Coral 페어 자동 적용
   - 사용자에게는 "BP에 지정된 팔레트 {palette_key}를 그대로 적용합니다. 변경 원하시면 말씀해 주세요." 1줄만 안내
3. **LP 연계 경로**: LP의 주제·성격에 맞는 추천 색상 자동 적용 + 확인
4. **패스트트랙 경로**: 주제에 맞는 추천 색상이 이미 적용된 상태. 사용자가 변경을 요청하면 반영
5. **일반 경로 (Phase 1~3 개별 진행)**: Phase 4 시작 시 "악센트 색을 변경하시겠습니까? (현재: #F27100 주황)" 확인

주제별 추천 색상표는 `references/template-spec.md` 섹션 7 참조.

### 이미지 처리

- 사용자가 일러스트 이미지를 제공하면 해당 이미지를 슬라이드에 배치
- 이미지 배치: 슬라이드 면적의 60~70%를 차지하도록 하단 중앙에 배치

**이미지 미제공 시:**
- 데모·스크린샷 슬라이드: 회색 플레이스홀더(#F0F0F0, 점선 테두리)로 표시
- 도식화 대상 슬라이드: Phase 4 내에서 visual-diagram / visual-chart의 레이아웃을 pptxgenjs 네이티브 도형으로 직접 구성 (아래 참조)

### 시각 자료 통합 (visual-diagram + visual-chart 연계)

Phase 4에서 .pptx를 생성할 때, 시각화 대상 슬라이드를 식별하고 visual-diagram / visual-chart의 레이아웃 설계를 참조하여 pptxgenjs 네이티브 도형(addShape + addText)으로 직접 구성한다. SVG→PNG 이미지 변환을 사용하지 않으므로 서버 환경의 한글 폰트 유무와 무관하게 뷰어(PowerPoint) 측 시스템 폰트로 정상 렌더링된다. 별도 이미지 제작 단계 없이 Phase 4 안에서 완결된다.

**사용하는 시각화 스킬:**

| 스킬 | 용도 | 태그 |
|------|------|------|
| visual-diagram | 개념도·플로우차트·비교도·구조도·관계도 | `[DIAGRAM: 설명]` |
| visual-chart | 수치 데이터 차트 (막대·선·도넛·영역) | `[CHART: 설명]` |

**실행 순서:**

1. **후보 식별**: Phase 3 구조에서 `[DIAGRAM: 설명]` 또는 `[CHART: 설명]` 태그가 붙은 슬라이드 + Phase 4 생성 중 시각화가 효과적인 슬라이드를 목록화한다
2. **스킬·유형 판단**: 각 후보의 내용에 따라 참조할 스킬(visual-diagram / visual-chart)과 레이아웃/차트 유형을 선택한다 (아래 매핑 참조)
3. **네이티브 도형 구성**: pptxgenjs의 `addShape()` + `addText()`로 다이어그램/차트 요소를 직접 구성한다. SVG→PNG 이미지 변환을 사용하지 않는다. 뷰어(PowerPoint) 측 시스템 폰트로 한글이 렌더링되므로 폰트 누락 문제가 발생하지 않는다
4. **레이아웃 구현**: visual-diagram/visual-chart의 레이아웃 설계(노드 배치, 색상 규칙, 화살표 방향 등)를 참조하되, 실제 구현은 pptxgenjs 네이티브 도형(ROUNDED_RECTANGLE, OVAL, RIGHT_ARROW 등)과 addText()로 수행한다. 색상은 슬라이드 악센트 색상과 동일하게 적용한다
5. **QA 검증**: markitdown으로 텍스트 내용 확인. PDF 변환 후 레이아웃 검수 시, 서버 환경에 한글 폰트가 없으면 프리뷰에서 한글이 깨질 수 있으나 실제 .pptx 파일은 정상이므로 레이아웃 배치만 확인한다

**visual-diagram 레이아웃 매핑:**

| 슬라이드 내용 유형 | visual-diagram 레이아웃 |
|-----------------|----------------------|
| 비교/대조 (A vs B) | 2분할 비교 (좌우 카드) |
| 프로세스/단계 (Step 1→2→3) | 수평 플로우 |
| 기능·역할 매트릭스 | 체크리스트 매트릭스 (표) |
| 중심 개념 + 파생 항목 | 중앙 방사형 |
| 시간순 변화 | 타임라인 |
| 상위-하위 구조 | 계층 트리 |

**visual-chart 유형 매핑:**

| 슬라이드 내용 유형 | visual-chart 차트 유형 |
|-----------------|---------------------|
| 항목별 수치 비교 | 세로 막대 |
| 순위·길이 비교 | 가로 막대 |
| 시간 추이·변화 | 선 그래프 |
| 비율·구성 | 도넛 |
| 누적 변화 | 영역 그래프 |

**시각 자료 생성 기준:**
- 다이어그램: 노드 3~8개, 노드당 텍스트 20자 이내
- 차트: 데이터 포인트 최대 12개, 라벨 최대 15자, Y축 단위 필수
- 색상: 슬라이드 악센트 색상을 primary로, 연한 변형을 light로 사용
- 총 시각 자료 수: 강의당 4~10개가 적절. 모든 슬라이드에 넣는 것이 아니라 시각화가 내용 전달에 효과적인 슬라이드에만 적용한다

### Speaker Notes 삽입

## Phase 5: 발표 노트 + 핸드아웃 (Supporting Materials)

### 발표 노트 (Speaker Notes)

**기본: .pptx 내부 노트로 완결.** Phase 4에서 `slide.addNotes()`로 이미 삽입되어 있다.

**별도 `05-speaker-notes.docx` 생성 기준:**
- 사용자가 명시적으로 요청한 경우
- 노트 분량이 슬라이드당 평균 400자를 초과하는 경우 (상세 스크립트)

### 핸드아웃 (수강생 배포용, 선택)

## 관문 3: 시각 자료 통합 검증

lecture-slides Phase 4 종료 시 관문 3을 실행한다.

**검증 항목:**
- 시각 자료 삽입 대상 슬라이드가 모두 식별되었는가 (DIAGRAM + CHART)
- 각 시각 자료가 pptxgenjs 네이티브 도형(addShape + addText)으로 정상 구성되었는가
- 시각 자료 색상이 슬라이드 악센트 색상과 일치하는가
- 다이어그램: 노드 수(3~8개), 텍스트 길이(20자 이내) 가드레일 준수
- 차트: 데이터 포인트(12개 이내), 라벨(15자 이내), Y축 단위 가드레일 준수
- markitdown으로 텍스트 내용 확인 + PDF 변환 후 레이아웃 배치 검수 (서버 한글 폰트 부재 시 프리뷰 한글 깨짐은 정상)

**처리:**
- 통과 시 YAML에 `gate_3_passed: true` 기록
- 실패 시 항목별 보완 → 2회 실패 시 다이어그램 없이 플레이스홀더로 유지하고 사용자에게 보고
