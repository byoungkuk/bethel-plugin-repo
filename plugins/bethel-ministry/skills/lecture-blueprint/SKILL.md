# lecture-blueprint v0.5

강의 기획안과 슬라이드 사이의 브릿지 문서(Blueprint)를 생성하는 5단계 프로세스. 파이프라인 3단계.

## 역할

기획안의 꼭지 단위 정보를 슬라이드 1장 단위로 분해하고 고정한다. 블루프린트가 있으면 lecture-slides는 재해석이 아닌 조판(Layout + Render) 역할만 수행한다.

이 스킬이 해결하는 문제:
- 기획안은 꼭지·시간 단위, 슬라이드는 1장 단위. 단위 변환이 없으면 슬라이드 생성기가 매번 재해석하면서 드리프트(Drift)가 발생한다.
- 기획안에 "AI 활용 사례"라고만 적혀 있으면 슬라이드 생성기는 임의의 사례를 불러온다.
- 슬라이드가 나온 뒤에야 "이건 아니다"가 보인다. 블루프린트가 있으면 텍스트 단계에서 먼저 검수한다.

## 파이프라인 위치

```
lecture-plan [관문 1] → lecture-research [관문 2] → lecture-blueprint [관문 BP] → lecture-slides [관문 3] → lecture-review
```

## 언제 사용하나

- 반일 이상 강의 (슬라이드 15장 이상)
- 기획안의 꼭지별 메시지를 슬라이드 단위로 고정해야 할 때
- 동일 기획안으로 반복 강의를 할 때 (슬라이드 일관성 확보)
- 외부 편집자·공동 강사와 검수를 분리해야 할 때

## 언제 사용하지 않나

- 슬라이드 10장 이하 특강 (lecture-slides 패스트트랙)
- 기존 슬라이드의 텍스트만 교체하는 업데이트
- 핵심 메시지가 이미 고정된 반복 강의 (기존 BP 재활용)

## 입력

### 필수
- `LP_*.md` (lecture-plan 산출물) 또는 동등한 강의안 텍스트

### 선택
- `RL_*.md` (lecture-research 산출물: 사례·실습 소재)
- 강의디자인템플릿 v0.3 팔레트 키 (navy, darknavy, teal, slate, orange, purple, green, rose)
- 기존 BP 참조 파일 (반복 강의)

## 출력

- `BP_{강의명}_{YYYYMMDD}.md` 1개 (대화창 텍스트 + .md 파일)
- 관문 BP 통과 시 YAML에 `gate_bp_passed: true` 기록

저장 위치
- 1회성 강의: `10 외부 강의/00 일정별 강의/{강의명}/기획/`
- 반복 강의: `10 외부 강의/{11~14 기관 폴더}/`

## 프로세스

### Phase 1. 입력 정리

- `LP_*.md` 로드 → Ch·꼭지별 시간·산출물·타깃 프로파일 추출
- `RL_*.md` 있으면 사례·실습 소재 추가 로드
- 강의 총 시간 확인 → 예상 슬라이드 수 계산 (분당 0.5~1장 기준, 실습 시간 제외)
- 팔레트 키 확인 (미지정 시 `recommendPalette()` 규칙으로 추천)

### Phase 2. 핵심 메시지 추출 (역순 설계)

시간표가 아닌 핵심 메시지부터 확정한다. 이 단계가 가장 중요하다.

- Ch별로 "청중이 반드시 가져갈 한 문장"을 1~2개 추출
- 강의 전체 3~7개 범위 유지 (그 이상은 청중이 기억하지 못함)
- 각 메시지에 연결될 증거·사례·실습을 1개 이상 매칭
- **사용자 확인 관문**: 핵심 메시지가 강의 의도와 일치하는지 먼저 확인받고 다음 Phase로 넘어간다

**메시지 작성 규칙**
- 행동 동사 포함 (설명한다·만든다·비교한다·적용한다·선택한다)
- 추상 명사 중심 금지 ✗ "AI의 중요성", ○ "AI로 마케팅 카피 1개를 작성한다"
- 한 문장 50자 이내
- 금지어 위반 0건 (혁신적인, 획기적인, 완벽한, 매우, 쉽게, 빠르게)

### Phase 3. 슬라이드 분해

각 Ch를 T-유형 시퀀스로 분해한다.

**→ T-유형 매칭 규칙은 `references/t-type-matching.md`를 먼저 읽는다.**

**배분 기준**
- Ch당 5~8장 기본 (30~40분 기준)
- 실습 Ch는 3~5장 (실습 시간이 길어 슬라이드는 적게)
- 슬라이드 1장 = 1메시지 원칙
- 각 Ch 시작에 T-S(섹션 구분) 1장 배치

**필수 슬라이드**
- T-0 표지 1장 (강의 시작)
- T-S 섹션 구분 각 Ch당 1장
- T-Fin 마무리 1장 (강의 종료)
- T-Sum 챕터 요약 (선택, Ch 전환 전 또는 Ch 말미)

**단조로움 방지**
- 같은 T-유형 연속 3장 이상 배치 금지 (T-1, T-3, T-4, T-5를 섞어 사용)
- 본문 슬라이드 비율 T-1~T-5 중 3~4종 이상 혼합

### Phase 4. 필드 채우기

각 행(슬라이드)에 9개 필드를 채운다.

| 필드 | 규칙 |
|---|---|
| # | 슬라이드 순번 (1부터) |
| Ch | 속한 꼭지 (Ch1~ChN, 표지·마무리는 `-`) |
| T-유형 | v0.3 10종 중 하나 (T-0, T-S, T-1~T-5, T-Sum, T-Fin) |
| 제목 | 행동·판단 중심 문장 (기능명·명사 나열 금지) |
| 핵심 메시지 | 한 문장, 50자 이내. 섹션·표지·마무리는 `(표지)`, `(섹션)`으로 표기 |
| 증거/소재 | 사례·숫자·도구명·실습 파일 1~2개. 미정은 "미정 — 리서치 보완 필요" |
| 시각 힌트 | `[DIAGRAM: 설명]` / `[CHART: 설명]` / `[IMG: 설명]` / `-` |
| 시간 | 예상 분 (0.5~30분) |
| 노트 힌트 | 발표 전환 멘트 또는 강조 포인트 1줄 |

**제목 작성 규칙**
- ✗ "레이어 기능" → ○ "레이어로 구조를 분리하는 기준"
- ✗ "AI 도구 소개" → ○ "도구 선택은 목적별로 나뉜다"
- 30자 이내 권장

**시각 힌트 규칙**
- visual-diagram 연계: `[DIAGRAM: 2분할 비교]`, `[DIAGRAM: 수평 플로우 4단]`
- visual-chart 연계: `[CHART: 세로 막대]`, `[CHART: 도넛]`
- 이미지 참조: `[IMG: 결과 비교 2장]`, `[IMG: 시리즈 4장]`
- 전체 슬라이드의 25~50% 비율 유지 (지나치게 많으면 가독성 저하)

### Phase 5. 관문 BP (Generator ↔ Evaluator 루프)

이 Phase는 **생성(Generator)과 평가(Evaluator)를 분리**한 자동 수정 루프로 동작한다. Phase 4 산출물을 Generator 결과로 보고, 아래 9항목 Evaluator를 실행해 점수화한다.

#### Evaluator 규칙 (자동 판정 로직)

| # | 항목 | 자동 판정 규칙 | 실패 시 자동 수정 지점 |
|---|------|----------------|-------------------------|
| 1 | 슬라이드 총수 ↔ 강의 시간 정합 | (강의 시간 − 실습 시간) ÷ 슬라이드 수 ∈ [1분, 2분] 범위 | 분당 1장 초과 시 병합, 2분 초과 시 분할 |
| 2 | 제목·핵심 메시지 채움 | T-0/T-S 외 모든 행에 제목·메시지 필드 비어있지 않음 | 빈 행 식별 → Phase 4 필드 채우기 재실행 |
| 3 | 핵심 메시지 중복률 | 행 간 메시지 Jaccard 유사도 ≥ 0.6 비율 ≤ 20% | 중복 메시지 쌍 식별 → 한쪽 삭제 또는 재작성 |
| 4 | T-유형 유효성 | 모든 T-유형 ∈ {T-0, T-S, T-1~T-5, T-Sum, T-Fin} | 허용 외 값 발견 시 근접 T-유형으로 치환 |
| 5 | Ch별 T-S 배치 | 각 Ch 첫 슬라이드가 T-S | 누락 Ch에 T-S 1장 자동 삽입 |
| 6 | T-0 + T-Fin 존재 | 맨 앞 T-0 1장, 맨 뒤 T-Fin 1장 | 누락 시 자동 삽입 |
| 7 | 증거 미정 행 비율 | "미정" 텍스트 포함 행 ÷ 전체 ≤ 30% | 초과 시 RL 재참조 또는 사용자에 질의 |
| 8 | 시각 힌트 비율 | `[DIAGRAM/CHART/IMG]` 태그 보유 행 ÷ 전체 ∈ [25%, 50%] | 부족 시 T-2/T-3/T-5 행에 태그 추가, 과다 시 T-1/T-4 행에서 제거 |
| 9 | 학습 목표 ↔ 메시지 연결 | 각 학습 목표가 최소 1장 이상 슬라이드에 매칭 | 누락 목표 식별 → 해당 Ch에 1장 추가 |

#### 자동 수정 루프 (최대 2회)

```
[생성 Generator] Phase 4 초안
   ↓
[평가 Evaluator] 9항목 점수 산출 → 미달 항목 목록
   ↓
미달 0건? → YES → gate_bp_passed: true 기록 → 종료
   ↓ NO
[수정 Fixer] 미달 항목 자동 수정 규칙 적용 (위 표의 "자동 수정 지점")
   ↓
[재평가 Evaluator 2차] 9항목 재점수
   ↓
7/9 이상? → YES → 종료
   ↓ NO
[사용자 보고] 미달 항목·위치·시도 내역 제시 + Phase 2 회귀 제안
```

#### 통과 기준
- 정상 통과: 9/9
- 조건부 통과: 7/9 이상 + 미달 항목이 7(증거 미정)·8(시각 힌트) 중 하나 이하
- 실패: 6/9 이하 또는 핵심 항목(1·2·4·5·6·9) 중 하나라도 미달

#### Evaluator 실행 지침
- 각 항목을 **서로 다른 호출**로 판정한다 (일괄 판정 금지 — Generator 자기 편향 방지)
- 판정 결과는 "통과 / 미달 / 해당 없음"만 반환하고, 미달 시 해당 슬라이드 번호·구체 위치를 적시한다
- 자동 수정은 원본 대비 120%를 넘지 않는다. 초과 시 사용자 확인 요청

**최종 출력**
- 파일명: `BP_{강의명}_{YYYYMMDD}.md`
- 대화창 텍스트로도 동일 내용 제공
- 저장 위치 규칙에 따라 해당 폴더에 저장

**저장 직후 자동 제안 (필수)**

BP 파일 저장이 완료되면 즉시 사용자에게 다음 행동을 제안한다.

```
블루프린트 저장 완료: BP_{강의명}_{YYYYMMDD}.md (관문 BP {N}/9 통과)

다음 단계로 슬라이드 조판(.pptx 생성)을 진행하시겠습니까?
[Y] 바로 lecture-slides 실행 (BP 재해석 없이 조판)
[N] 잠시 보류 (BP만 저장하고 종료)
```

Y 선택 시 lecture-slides Phase 3으로 바로 진입한다. 이때 BP 파일 경로를 입력으로 명시 전달해 "BP 입력 판별 기준"을 충족시킨다.

## 블루프린트 파일 양식

**→ 상세 양식은 `templates/blueprint-template.md`를 복사해 사용한다.**

핵심 구조
- YAML 프론트매터: 강의 메타데이터 + 관문 BP 결과 + 슬라이드 총수·Ch 매핑
- 강의 개요 (LP에서 인용)
- 핵심 메시지 (Phase 2 결과, 3~7개)
- 슬라이드 테이블 (1장 = 1행, 9개 필드)
- 관문 BP 체크 결과
- 변경 이력

## YAML 프론트매터

```yaml
---
title: {강의명} 블루프린트
type: lecture-blueprint
lecture_title: {강의 제목}
lecture_duration_minutes: {N}
slide_count_total: {N}
ch_mapping:
  - ch: Ch1
    title: {꼭지 제목}
    slide_range: "2-9"
    slide_count: 8
  - ch: Ch2
    title: {꼭지 제목}
    slide_range: "10-19"
    slide_count: 10
key_messages:
  - {메시지 1}
  - {메시지 2}
palette_key: {navy/darknavy/teal/slate/orange/purple/green/rose}
gate_bp_passed: true
gate_bp_score: {N}/9
gate_bp_checked_at: {YYYY-MM-DD}
source_lp: {LP_*.md 파일명}
source_rl: {RL_*.md 파일명 또는 none}
next_skill: lecture-slides
created: {YYYY-MM-DD}
tags: [lecture, blueprint, BP]
---
```

## 연계 스킬

- **입력 연계**: lecture-plan (LP YAML의 target_profile·ch 구조·학습 목표 전달)
- **입력 연계(선택)**: lecture-research (RL 소재를 증거 필드에 주입)
- **출력 연계**: lecture-slides (BP 테이블이 Phase 3 슬라이드 목록 역할, 관문 3 진입 조건)
- **검증 연계**: lecture-review (BP 핵심 메시지 반영률 체크)

## 기존 스킬 변경 사항 (권장)

이 스킬의 효과를 완전히 보려면 아래 3개 스킬에 연동 변경이 필요하다.

- **lecture-plan**: 출력 YAML에 `next_skill: lecture-blueprint` 추가
- **lecture-slides**: Phase 3 진입 조건에 "BP_*.md 존재" 추가 (15장 이상 강의 한정)
- **lecture-review**: 체크리스트에 "블루프린트 핵심 메시지 반영률" 추가

## Harness 블록

| 항목 | 값 |
|---|---|
| 원문 보존 레벨 | L1 (요약형) — LP를 슬라이드 단위로 재구조화 |
| 생성-평가 분리 | 슬라이드 분해 → 관문 BP 검증 → 실패 시 재작성 (최대 2회) |
| 분량 가드레일 | 강의 시간 × 0.5~1장 (예: 180분 → 90~180장, 실습 제외 권장 30~60장) |
| 재생성 트리거 | 관문 BP 점수 7/9 미만 |

### 자가 평가 루프

**Phase 2 직후**
- [ ] 핵심 메시지가 3~7개 범위에 있는가
- [ ] 각 메시지가 행동 동사로 작성되었는가
- [ ] 사용자 확인을 받고 다음 Phase로 넘어갔는가

**Phase 4 직후**
- [ ] 모든 행의 9개 필수 필드가 채워졌는가
- [ ] 핵심 메시지가 Ch별 학습 목표와 정합하는가
- [ ] T-유형 배치가 강의 흐름(도입·본론·요약)에 맞는가
- [ ] 같은 T-유형 연속 3장 이상이 없는가

**Phase 5 직후**
- [ ] 관문 BP 9개 중 7개 이상 통과했는가
- [ ] 실패 항목에 대한 보완이 이뤄졌는가
- [ ] YAML 프론트매터에 gate_bp_passed 플래그와 점수가 기록되었는가

## 실행 원칙

- 반드시 LP_*.md를 먼저 읽고 시작한다
- 핵심 메시지 확정(Phase 2) 전에는 슬라이드 분해로 넘어가지 않는다
- 증거 미정 행은 "미정 — 리서치 보완 필요"로 표기한다 (숨기지 않는다)
- 관문 BP 통과 전에는 lecture-slides 진입을 차단한다
- BP_*.md 수정 이력은 프론트매터 하단 "변경 이력" 섹션과 `tags`에 기록한다 (v0.1, v0.2 ...)
- 핵심 메시지가 3~7개 범위를 벗어나면 경고한다
- 팔레트 키가 지정되지 않으면 recommendPalette() 규칙으로 추천하고 사용자 확인을 받는다
- 한국어 산출물은 한국어로 작성한다
