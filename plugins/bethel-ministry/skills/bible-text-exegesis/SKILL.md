# 성경 본문 석의(Exegesis) 스킬

## 이 스킬의 위치

```
[bible-text-exegesis] → [theological-dialogue] → [sermon-conceptnet] → [sermon-lectionary] ↔ [sermon-critic]
  본문을 깊이 판다        신학자들과 대화한다      메인아이디어·36개념망    무브·초안·제목        채점·청중반응
  (석의 7단계)            (선택 단계)             ·3대지·B&T            (생산 라인)          (판정)
                                                       ↕
                                              [buttrick-homiletic] 무브 구조 진단 (필요시)
```

- **단독 사용**: 설교와 무관하게 본문 자체를 깊이 연구할 때 — 성경공부 교안 준비(`bible-study-worksheet`), 의정부교도소 사역, 개인 묵상, 강해 설교 자료.
- **연계 사용**: 이번 주 설교를 준비할 때, 이 스킬로 먼저 심화 석의를 마친 뒤 → `theological-dialogue`(신학자 관점 보강, 선택) → `sermon-conceptnet`(개념망)으로 넘긴다. `sermon-lectionary`의 약식 §1~2보다 이 스킬의 절차가 학문적으로 훨씬 엄밀하므로, 시간 여유가 있는 주 또는 본문이 까다로운 주에 사용을 권한다.

## 작업 철학 — 구조화가 아니라 맥락화

석의 7단계는 절차의 뼈대이지 목적이 아니다. 7단계를 다 채웠는가가 아니라, 그 결과로 본문의 맥락(문예적·역사적·정경적 맥락)이 실제로 더 선명해졌는가가 기준이다. 칸을 채우기 위해 관찰을 만들지 않는다 — 본문을 따라간 결과로 칸이 채워지는 것이어야 한다.

같은 이유로, 이 스킬은 이미 구조 자체가 귀납적이다: 원문(2단계)에서 시작해 신학적 종합(7단계)으로 나아가지, 신학적 결론을 먼저 세우고 원문을 거기 맞추지 않는다. **이 순서를 뒤집지 않는 것이 곧 귀납을 지키는 것이다** — 아래 "단계 순서 준수" 원칙과 같은 원리다.

### 판단 루프 — 목사님의 작업 성향 참조
이 스킬의 규칙이 명시적으로 다루지 않는 판단(어느 관찰을 살릴지, 배경 조사를 어디까지 파고들지 등)이 필요할 때는 볼트 파일 `40.설교/00.공통참조/목회자-작업성향-프로파일.md`를 참조해 거기 기록된 성향(구조화보다 맥락화, 연역보다 귀납, 부분보다 전체 연속성 등)을 기본 기준으로 삼는다(볼트 루트 Vault_BK 기준 경로 — 어느 프로젝트·폴더 스코프에서 세션을 열든 동일하게 참조 가능; 폴더 이동 가능성이 있으니 `.obsidian/` 판정 우선, 경로 하드코딩 금지). 이 스킬 작업 중 그 볼트 파일에 없는 새로운 개입이 나오면, 작업이 끝난 뒤 그 파일에 사례를 추가한다.

## 작업 시작 전 확인

1. **모드 선택**
   - **A. 단일 본문 모드**: 본문 하나만 준다 (예: "요한복음 4장 5-42절 연구해줘")
   - **B. 성서정과 모드**: "이번 주 성서정과 본문 석의해줘"처럼 설교 준비 맥락이면, 구약·시편·서신·복음서 4개 본문 전체를 대상으로 한다. 사용자가 본문을 안 주면 이번 주 성서정과를 확인해서 먼저 제시하고 확인받는다.
2. 청중/용도를 짧게 확인한다 (설교용 / 성경공부용 / 교도소사역용 / 개인묵상용) — 7단계 산출물의 어투와 적용 방향이 달라진다.
3. 원문 확인 도구가 마땅치 않으면(그리스어 원문 데이터베이스 접근 불가 등) 있는 지식과 웹 검색으로 최선을 다하되, 불확실한 원문·이문 판단은 추측하지 말고 "확실하지 않습니다"라고 명시한다.
4. **기존 파일을 먼저 찾는다.** `03.본문석의/`에 같은 본문·같은 주일의 석의가 이미 있는지 확인한다. 있으면 **새 파일을 만들지 말고 그 파일에 이어 쓴다.** 파일명이 조금 달라도 같은 본문이면 같은 문서다 — 이름이 다르다고 새로 만들면 볼트에 사본이 갈라지고, 나중에 어느 쪽이 최신인지 판정할 수 없게 된다. 보강할 지점만 묻고 해당 절을 append 한다.
5. **위키 우선 확인.** 볼트에 `70.LLM 위키/`가 있으면, 이 본문(pericope)·주제·관련 신학자를 다루는 `W_` 페이지가 이미 있는지 먼저 확인한다(`index.md` 조회 우선, 필요하면 `wiki-activate` 스킬로 정식 조회). 있으면 그 내용을 근거로 인용하고 이미 정리된 부분은 중복 조사하지 않는다 — 근거로 쓴 페이지는 노트에 `[[W_페이지명]]`으로 표기한다. 위키에 없거나 부족한 부분만 표시하고 정상적으로 7단계를 새로 진행한다(위키 밖 지식을 위키 내용인 것처럼 섞지 않는다). `70.LLM 위키/` 폴더 자체가 없으면 이 단계를 건너뛴다.

## 석의 7단계

### 1단계 — 본문 확정과 예비 이해 (Textual Orientation)
- 성서정과 모드면 4개 본문 전체를 먼저 통독하고, 이 주일이 교회력 흐름(절기) 안에서 어느 지점인지 확인
- 본문의 경계(pericope) 확정: 번역본마다 다를 수 있으므로 직접 판단하고 근거 제시
- 사본학적 이슈(중요 이문)가 설교/연구에 영향을 줄 정도인 경우만 언급

### 2단계 — 원문 분해 (Grammatical-Syntactical Analysis)
- 절 단위로 원어(헬라어/히브리어)를 끊어 읽는다
- 동사의 시제·태·법에 주목 (헬라어 부정과거 vs 현재시제 뉘앙스 등)
- 접속사·전치사가 논리 흐름을 어떻게 통제하는지 확인 (γάρ, οὖν, δέ 등)
- 핵심 신학 용어는 사전적 정의보다 **본문 안 용례**를 우선해서 의미 범위를 좁힌다
- 산출물: 절별 직역 + 문법적 관찰 메모 (표 형식 권장: 절 / 직역 / 문법 관찰 / 신학적 함의)

### 3단계 — 문학적·장르적 분석 (Literary Analysis)
- 장르 식별(비유/기적서사/논쟁서사/담화/서신 권면 단락 등) — 장르마다 해석 규칙이 다르므로 명시
- 서사 구조(해당 시): 배경-갈등-전환-해소
- 수사적 장치: 반복, 대구, 역설, 아이러니, 침묵된 부분(gap)
- 화자의 시점과 청자의 반응 묘사 방식

### 4단계 — 역사적·문화적 배경 (Historical-Cultural Context)
- 1세기 팔레스타인/그레코-로만 세계의 사회적 관습 (명예-수치 문화, 후원-피후원 관계, 정결법 등)
- Kenneth Bailey류의 중동 문화적 렌즈를 적극 활용 (목사님이 선호하는 접근)
- 저작 연대·저자·수신 공동체 상황 (서신서일 경우 특히 중요)
- 구약 인유(引喩)·반향(echo) 추적: 복음서/신약 본문이 구약 어느 본문을 배경에 깔고 있는지

### 5단계 — 문맥 분석 (Contextual Analysis)
- **근접 문맥**: 바로 앞뒤 단락과의 연결
- **책 전체 문맥**: 해당 복음서/서신 전체 신학 안에서 본문이 하는 역할 (예: 누가복음의 성령론, 요한복음의 표적 구조)
- **정경적 문맥**: 신구약 전체 구속사 속 본문의 위치

### 6단계 — 성서정과 통합 (Lectionary Synthesis) — *성서정과 모드에서만*
- 구약·시편·서신·복음 4개 본문이 공유하는 하나의 신학적 실을 찾는다
- 이 실이 **메인아이디어 후보**가 된다 — `sermon-conceptnet` §3의 입력으로 그대로 넘길 수 있는 형태로 정리한다
- 형식 제안: `[인간 현실]에도 불구하고/속에서 [하나님의 행동]이 [어떻게] 작동한다` + 표제어(단일 명사·동명사) 후보
- 단일 본문 모드에서는 이 단계를 생략하고 5단계에서 7단계로 바로 넘어간다

### 7단계 — 신학적 종합과 적용 준비 (Theological Synthesis → Bridge)
- 본문의 핵심 신학 명제를 한 문장으로 요약 (Exegetical Idea)
- 이 명제를 청중의 삶의 자리로 옮기기 위한 다리를 놓는다
  - **설교용**: 여기서 Buttrick 현상학적 전개로 넘어갈 준비 완료 → `theological-dialogue`(선택) → `sermon-conceptnet`(개념망)으로 이어짐
  - **성경공부/교도소사역용**: 토의 질문 3~5개, 삶의 적용 포인트로 마무리 → `bible-study-worksheet`(교안 PDF)의 역사배경·질문해설 재료로 그대로 쓴다
- **복음의 공공성/사회적 책임** 차원이 본문 안에 어떻게 내재해 있는지 별도 항목으로 반드시 표시한다. 개인 구원으로만 축소하지 않을 것.

## 작업 원칙

- **엄밀한 추론 우선**: 근거 없는 추론보다 자료 분석에 근거한 추론. 불확실하면 "확실하지 않습니다"라고 답한다.
- **이단 배제**: 구원파·신천지 등에서 주장하는 해석 철저히 배제
- **인문학적 깊이 환영**: 시적 표현, 철학적 통찰을 적극 반영하되, 성경적 근거 없는 묘사·숫자 삽입은 금지
- **단계 순서 준수**: 원문 분해 없이 배경 설명으로 건너뛰지 않는다. 각 단계 산출물이 다음 단계의 재료가 되도록 순차 진행
- **분량**: 단계별로 과도하게 길게 쓰지 않는다. 2~4단계는 표/불릿 중심으로 압축하고, 7단계에서 종합할 때 산문으로 풀어쓴다

### 저장 위치는 모드에 따라 다르다 — 같은 내용을 두 곳에 복사하지 않는다

볼트는 **전체 석의는 한 곳에, 주간 작업 폴더에는 압축 요약 + 위키링크**라는 단계적 노출 구조로 운영된다. 전문을 두 곳에 복사하면 나중에 한쪽만 고쳐졌을 때 어느 것이 최신인지 판정할 수 없다. 이 구조를 지키는 것이 중요하다.

**A. 단일 본문 모드** (성경공부·교도소사역·개인묵상)
- `03.본문석의/{YYYYMMDD}_{본문약칭}_본문석의.md` 한 곳에만 저장한다.
- 주간 설교 폴더는 건드리지 않는다.

**B. 성서정과 모드** (설교 준비)
1. **전체 석의**는 `03.본문석의/{YYYYMMDD}_{절기}_{본문}_본문석의.md`에 저장한다.
   - 예: `20260816_성령강림절후12주_마태복음15_10-28_본문석의.md`
   - 파일명 규칙을 반드시 지킨다. 다른 형식으로 만들면 볼트에서 같은 주의 자료가 흩어진다.
2. **주간 폴더**(`교회력설교작성/{절기}-{YYYY-MM-DD}/`)에는 `00-본문연구.md`를 만들되, **전문이 아니라 압축본**을 넣는다. 구성:
   - 프론트매터(date, 절기, 본문, 상태, tags)
   - `전체 석의는 별도 문서에 있다: [[{위 파일명}]]` — 위키링크 필수
   - 문학적 위치 (3~5줄)
   - 결정적 문법 관찰 (번호 목록 5~6개)
   - **배제 목록** — 근거 부족해서 설교에 쓰면 안 되는 통설들. 이 항목이 실제로 가장 자주 쓰인다.
   - 다뤄야 할 저항점 (청중이 걸려 넘어질 질문)
   - 메인아이디어(확정됐으면)
   - `01-개념망` 위키링크

- 프론트매터에 `본문`, `날짜`, `모드`(단일본문/성서정과), `연계설교여부`(예/아니오)를 기록
- 노트 템플릿은 `references/note-template.md` 참조
- 저장 전 항상 완성된 노트 초안을 대화창에 먼저 보여주고 확인받은 뒤 저장한다 (경로 재확인 포함)
- **파일 삭제·덮어쓰기는 반드시 확인받는다.** 기존 파일이 있으면 append가 기본이다.

## 다음 단계로 넘기는 방법

### 설교 준비로 이어갈 때
1. 이 스킬로 석의 노트 완성 및 저장
2. (선택) "신학자 관점에서도 봐줘"라고 하면 `theological-dialogue`로 넘겨 바르트·본회퍼·몰트만·브루그만·N.T. 라이트·윌슨·버틀릭·김기석·피터슨 고정 9인 패널의 신학적 틀로 본문을 다시 읽는다. 그 결과는 전체 석의 문서에 절을 추가해 기록한다.
3. "이 석의로 개념망 뽑아줘" 또는 "sermon-conceptnet으로 넘어가줘"라고 요청
4. `sermon-conceptnet`이 6단계 통합 메인아이디어 후보와 7단계 Exegetical Idea를 입력으로 받아 §3(메인아이디어 확정) → §4(36개념망) → §6(3대지) → §7(Breaking & Twisting)을 수행
5. 그 뒤 `sermon-lectionary` §5(무브 확정)부터 이어간다

> 넘길 때는 7단계 전문이 아니라 **6·7단계 요약**만 전달한다. 원문분해·배경조사 전문을 이후 단계에 다시 붙이지 않는다 (토큰 절약 원칙).
