# 조치와 리포트 (audit-actions)

조치 유형 정의, 절차, 리포트 형식, 코워크(Cowork) 지시문 예시입니다.

## 목차
1. 조치 유형 5종
2. 병합·분할 절차
3. 리포트 형식
4. 코워크 지시문 예시

---

## 1. 조치 유형 5종

| 조치 | 성격 | 승인 | 대상 발견 |
|------|------|------|----------|
| 링크 보정 | 비파괴 | 동의 | 깨진 링크, MOC 미등록, 연결 누락 |
| 갱신 | 비파괴 | 동의 | 노후, 소스 미반영, frontmatter 누락 |
| 분할 | 구조 변경 | 승인 | 개념·경험 혼합, 한 페이지 다주제 |
| 병합 | 파괴 | 승인 필수 | 중복 페이지 |
| 삭제 | 파괴 | 승인 필수 | 빈 페이지, 폐기 합의된 페이지 |

비파괴 조치는 동의 후 곧장 반영합니다. 분할은 구조를 바꾸므로 방향을 제시하고 승인을 받습니다. 병합·삭제는 승인 없이 실행하지 않습니다.

---

## 2. 병합·분할 절차

### 병합

1. 병합 방향 제시: 어느 페이지를 본문으로 남기고 어느 페이지를 흡수할지, 근거와 함께.
2. 승인 대기.
3. 승인 후 합치기:
   - 양쪽 `sources`를 합집합으로 보존.
   - 본문은 충돌 없는 내용을 통합, 충돌 지점은 "소스 대조 필요"로 표시.
   - 흡수되는 페이지를 가리키던 `[[ ]]` 링크를 본문 페이지로 일괄 교체.
   - 인덱싱: MOC 방식이면 흡수 페이지 항목 제거. dataview index 방식이면 파일 삭제로 자동 반영.
4. 경험 페이지는 개념 페이지에 흡수하지 않습니다. 유형이 다르면 병합 대상이 아닙니다.

### 분할

1. 분할 기준 제시: 개념/경험 경계 또는 주제 경계.
2. 승인 후 page-schema 템플릿으로 새 페이지 생성, 원 페이지는 남는 내용으로 축소.
3. 양쪽에 `[[ ]]` 교차링크 추가. MOC 방식이면 신규 페이지 등록, dataview index 방식이면 자동 노출.

## 3. 리포트 형식

점검 리포트는 심각도 상→하 순으로 배치합니다. 충돌을 최상단에 둡니다.

```
# 위키 점검 리포트 (KST 2026-06-02)
점검 범위: 50 LLM 위키 / 전체 (페이지 N장)

## 상 — 우선 조치
| # | 군 | 대상 | 발견 | 제안 조치 | 승인 |
|---|----|------|------|----------|------|
| 1 | 충돌 | A·B 페이지 | 같은 수치 다른 값 | 소스 대조 후 정리 | - |
| 2 | 신선도 | C 페이지 | 소스 미반영 | 갱신 | 동의 |

## 중 — 차순위
| # | 군 | 대상 | 발견 | 제안 조치 | 승인 |
| 3 | 중복 | D·E 페이지 | 핵심 80% 겹침 | 병합(D 본문) | 승인 필요 |

## 하 — 일괄 보정
| # | 군 | 대상 | 발견 | 제안 조치 | 승인 |
| 4 | 구조 | F 페이지 | MOC 미등록 | MOC 추가 | 동의 |
| 5 | 구조 | G→H 링크 | 깨진 링크 | 링크 보정 | 동의 |

## 요약
- 충돌 1, 노후 1, 중복 1쌍, 구조 2건
- 승인 필요(파괴): 병합 1건
```

조치 반영 후에는 변경 목록을 따로 표기합니다.

```
## 조치 결과
- C 페이지 갱신(updated 2026-06-02), sources 반영
- F 페이지 MOC 등록, G→H 링크 보정
- D·E 병합은 승인 대기
```

## 4. 코워크 지시문 예시

### 전체 감사

```
50 LLM 위키 전체를 점검해줘. 5군(중복·충돌·신선도·구조·스키마).
- 충돌·소스 미반영을 최상단에, 링크·MOC 누락은 하단에.
- 병합·삭제는 자동 실행하지 말고 승인 항목으로 표시.
- 충돌은 위키 안에서 단정하지 말고 "소스 대조 필요"로.
- 리포트는 심각도 상→하 표로.
```

### 신선도만 부분 감사

```
50 LLM 위키 신선도만 점검해줘.
- 빠른 변화 주제(도구·모델·가격)는 90일, 일반 개념은 180일 기준.
- sources 노트가 페이지 updated보다 나중이면 임계값과 무관하게 갱신 후보.
- 경험 페이지는 노후 점검 제외.
```

### ingest 인계 점검

```
방금 wiki-ingest에서 중복으로 건너뛴 페이지군 점검해줘.
- 기존 페이지와 병합할지, 분리 유지할지 판단해서 제안.
- 병합 방향과 근거 제시 후 승인 대기. 경험 페이지는 개념에 흡수 금지.
```
