# 점검 항목 (audit-checks)

5군 점검의 판정 기준과 신선도 임계값입니다. 스키마·인덱싱 기준은 위키 폴더 지침을 우선하며, 폴더 지침이 없을 때 wiki-ingest의 page-schema를 기준으로 점검합니다. 폴더가 `type` 미사용·dataview index 방식이면 해당 항목을 폴더 기준으로 판정합니다.

## 목차
1. 중복 점검
2. 충돌 점검
3. 신선도 점검
4. 구조 점검
5. 스키마 점검
6. 심각도 등급

---

## 1. 중복 점검

같은 주제를 다루는 페이지가 둘 이상 있는지 봅니다.

판정 신호:
- 제목이 같은 개념을 가리킴(예: `MCP` ↔ `Model Context Protocol`)
- 본문 핵심 내용이 70% 이상 겹침
- sources가 동일하거나 크게 겹침

처리 방향: 중복 후보로 표시하고 병합 제안. 자동 병합하지 않습니다. concept와 experience가 같은 주제를 다뤄도 유형이 다르면 중복이 아닙니다. 분리 유지합니다.

---

## 2. 충돌 점검

같은 사실을 페이지마다 다르게 적은 경우입니다. 가장 심각한 군입니다. 활용 단계의 L1 검증을 직접 망가뜨립니다.

판정 신호:
- 같은 수치를 페이지마다 다른 값으로 기재
- 같은 개념을 상반되게 정의
- 한 페이지가 다른 페이지를 부정하는 서술

처리 방향: 충돌 쌍과 불일치 지점을 표시합니다. 위키 안에서 어느 쪽이 맞는지 단정하지 않습니다. sources를 대조해 근거가 명확한 쪽으로 정리하되, 소스에 근거가 없으면 "소스 대조 필요" 또는 "소스에 근거 없음"으로 표시하고 보충 리서치를 권합니다.

---

## 3. 신선도 점검

페이지가 노후했거나 소스 갱신을 반영하지 못한 경우입니다.

판정 기준:
- updated 경과: KST 현재 기준 페이지 `updated`가 임계값을 넘음
- 소스 미반영: `sources` 경로의 소스 노트 수정 시각이 페이지 `updated`보다 나중(노트형 소스만 대조. docx·pptx·pdf 등 비노트 원본은 갱신 시각 대조에서 제외)
- 빠른 변화 주제: AI 도구·모델·가격처럼 변동이 큰 주제는 임계값을 짧게 적용

기본 임계값(사용자가 조정 가능):

| 주제 성격 | 임계값 | 비고 |
|----------|--------|------|
| 빠른 변화(도구·모델·가격) | 90일 | 넘으면 갱신 권고 |
| 일반 개념 | 180일 | 넘으면 검토 권고 |
| 경험 기록 | 만료 없음 | 사실이 고정됨, 노후 점검 제외 |

expires_at 우선: 페이지나 R_ 노트 frontmatter에 `expires_at`이 있으면 위 임계값보다 우선 적용합니다(wiki-research Phase 4와 동일 기준: 트렌드·도구 90일 / 시장·정책 180일 / 일반 개념은 만료 대신 180일 검토 / 경험 기록 만료 없음). 임계값 표의 "일반 개념 180일"은 만료가 아니라 검토 권고입니다.

소스 미반영은 임계값과 무관하게 항상 갱신 후보로 표시합니다.

---

## 4. 구조 점검

위키의 연결 무결성을 봅니다.

판정 항목:
- 깨진 링크: `[[ ]]`가 존재하지 않는 페이지를 가리킴
- 미인덱싱: MOC 방식 폴더는 MOC 미등록을, dataview index 방식 폴더는 index 자동수집 노출 여부를 봅니다. index 방식은 신규 페이지가 자동 노출되어 통상 해당 없음
- 고아 페이지: 어디서도 `[[ ]]`로 링크되지 않는 페이지(index 방식 폴더는 MOC 조건 제외)
- concept↔experience 연결 누락: 개념과 그 적용 경험이 있는데 서로 링크되지 않음

처리 방향: 모두 비파괴 조치(링크 추가·MOC 등록)로 제안합니다. 사용자 동의 후 반영합니다.

---

## 5. 스키마 점검

위키 폴더 스키마(없으면 wiki-ingest page-schema) 준수 여부입니다.

판정 항목:
- frontmatter 필수 필드 누락(폴더 스키마 기준. 기본은 type·sources·updated, `type` 미사용 폴더는 폴더 분류 필드·sources·updated)
- 분류 필드 값이 폴더 정의 범위를 벗어나거나 비어 있음(기본 스키마는 type이 concept·experience인지 확인)
- 한 페이지에 개념과 경험이 혼합(concept인데 1인칭 경험이 섞임 등)
- created·updated가 KST 형식이 아님
- (폴더 조건부) 폴더 지침이 정의한 경우에만 점검: 상태 필드 장기 정체(예: 1개월 이상 `status: draft`), 출처 등급(A/B/C) 미표기, 본문 분량 상한 초과(예: 4,000자)

처리 방향: 필드 보정·유형 재지정은 비파괴 조치로 제안. 개념·경험 혼합은 분할 후보로 표시(분할은 페이지 구조 변경이므로 승인 후 처리). 폴더 조건부 항목(장기 draft·등급 미표기·분량 초과)은 비파괴 갱신 권고로 제안하며 심각도는 하로 둡니다.

---

## 6. 심각도 등급

Evaluator 단계에서 발견에 등급을 부여합니다.

| 등급 | 대상 | 처리 순서 |
|------|------|----------|
| 상 | 충돌(수치·정의 불일치), 소스 미반영 노후 | 우선 조치 |
| 중 | 중복, 빠른 변화 주제 노후, 개념·경험 혼합 | 차순위 |
| 하 | 깨진 링크, MOC 미등록, 고아, 연결 누락 | 일괄 보정 |

상 등급 중 충돌은 활용 단계 신뢰성을 직접 해치므로, 리포트 최상단에 배치합니다.
