# 설교 평가 (sermon-critic) — Gate 파이프라인 (2026-08-28 Codex 호환판)

`sermon-lectionary` §8·§8.5를 담당하는 **판정 전용** 스킬. 쓰지 않는다. 채점하고 반응한다.

이 문서는 2026-08-21 "설교채점 파이프라인 진단 및 재설계"(프로젝트 문서 `claude/설교채점_파이프라인_진단및재설계.md`)에서 확정한 4단계 Gate 구조를 실제 SKILL.md로 옮긴 것이다. 그 진단 문서가 결정이고, 이 파일이 그 결정의 실행판이다 — 둘이 어긋나면 이 파일이 최신이므로 이 파일을 따른다.

## 왜 이 버전인가 (재설계 배경 — 요약)

이전 7항목 체계는 세 가지 문제를 반복적으로 일으켰다.

1. **청중 프롬프트가 "불만 생성기"로 작동함.** 개방형 질문 다수(6~7개)가 텍스트 품질과 무관하게 매 라운드 새 불만을 만들어냈다 — 실제 결함 측정이 아니라 불만 풀에서 매번 새로 뽑는 구조였다.
2. **"청중 데이터가 채점자 예비 점수와 다르면 실제 청중을 따른다"는 규칙을, 단 1회짜리 LLM 시뮬레이션에 그대로 적용**해 단일 샘플을 확정된 사실처럼 취급했다.
3. **청중적합성(15점)이 100점 총점 안에 섞여 있어, 90점 문턱이 사실상 도달 불가능**했다(실측 최대 약 88점) — 청중 시뮬레이션의 변동성이 그대로 총점을 흔들었기 때문이다.

그래서 이 버전은 **채점자의 100점(Gate 1)에서 청중적합성을 완전히 뺀다.** 청중 반응은 별도 채널(Gate 2)에서 점수화 없이 다수결로만 다룬다. 두 결과는 마지막까지 섞지 않는다(Gate 3).

---

## 왜 별도 스킬인가 (유지)

무브를 쓴 에이전트가 그 무브를 채점하면 점수가 후해진다. 자기가 방금 고른 단어를 자기가 부정하기 어렵다. 그래서 이 스킬은 **원고를 쓴 문맥과 분리된 서브에이전트로 실행한다.**

---

## 작업 철학 — 구조화가 아니라 맥락화

네 개 Gate는 품질을 통제하는 도구이지 점수와 결함을 만들어내는 목적이 아니다. Gate 1은 항목 칸을 기계적으로 채우지 않고 실제 문장과 무브의 맥락에서 귀납적으로 지목한다. Gate 2는 불만을 억지로 생성하지 않으며, 독립 표본에서 반복된 반응만 결함으로 인정한다. 규칙이 애매할 때는 현재 사용자 지시와 실제 원고의 작동을 우선한다.

# 실행 방식 (필수, 비협상)

메인 에이전트(이 대화를 진행하는 나 자신)는 Codex의 **`spawn_agent`로 서브에이전트를 호출**한다. 직접 채점하지 않는다. 모든 역할은 부모 대화의 선입견을 받지 않도록 `fork_turns: none`으로 생성하고, 필요한 원고·기준·배경은 프롬프트 본문에 직접 넣는다.

**Gate 1과 Gate 2는 절대 같은 서브에이전트가 겸하지 않는다.** Gate 1(채점자)이 통과한 뒤에만 Gate 2(청중)를 부른다 — 순차적이지만, 역할은 반드시 물리적으로 분리된 서브에이전트여야 한다. 한 서브에이전트가 "먼저 청중 흉내를 낸 다음 채점자 흉내를 낸다"는 식으로 내부에서 두 역할을 순서대로 연기하는 것은 **이 스킬이 막으려는 바로 그 오염**이다. 메인 에이전트가 `spawn_agent`를 **역할별로 별도 호출**해야 한다 — Gate 2는 `gpt-5.6-luna` 청중 3인을 동시에 생성한다.

`서브에이전트는 서브에이전트를 부르지 않는다`(고정 규칙) — 그러므로 병렬 호출의 책임은 언제나 메인 에이전트에게 있다. 서브에이전트가 "저는 병렬 호출 도구가 없습니다"라고 보고하는 것은 정상이다(사양대로다) — 그 말을 "그러니 내부에서 두 역할을 다 하겠다"는 뜻으로 오독하지 않는다. 메인 에이전트가 애초에 역할마다 따로 불러야 한다.

## 호출 전 메인 에이전트가 먼저 하는 일 (비협상)

1. **Gate 0을 먼저 돌린다.** 아래 §Gate 0 스크립트로 자수·기계적 오류를 사전 검사한다. Gate 0 실패 항목은 에이전트 호출 없이 메인이 직접 지목하고, 목사님께 먼저 수정 여부를 확인한다.
2. **자수를 메인이 계측한다.** `python3 -c "import re; print(len(re.sub(r'\s','',open(경로,encoding='utf-8').read())))"` 로 실측해 **숫자를 프롬프트에 박아 넣는다.** 서브에이전트에게는 "이미 계측 완료, 재계측 금지"라고 명시한다.
3. **수정 규모를 판정한다.** 직전 버전과 대조해 변경 문장 수를 센다. 이 값이 모델·입력 범위를 결정한다.
4. **Gate 1을 먼저, Gate 2는 Gate 1 통과 후에만.** Gate 1 미만이면 Gate 2를 호출하지 않는다 — 구조가 안 잡힌 원고에 청중 반응을 물어봐야 소음만 는다.

Gate 1 채점자 프롬프트에는 다음 세 줄을 반드시 포함한다.

```text
- 서브에이전트를 추가로 호출하지 마라. 네가 직접 수행해 답하라.

```

# Gate 0 — 기계적 사전검사 (토큰 0, 순수 스크립트)

에이전트를 부르기 전에 메인이 직접 실행한다. 실패 시 에이전트 호출 없이 직접 수정 지점을 제시한다.

원고가 파일이면 이 `SKILL.md`가 있는 폴더를 기준으로 다음 스크립트를 실행한다. 표준 주일 무브는 기본 범위가 700~750자이며, 성찬주일은 `--min 600 --max 650`을 지정한다.

```bash
python3 scripts/gate0.py <원고경로> [--min 700] [--max 750]
```

대화에 붙여넣은 원고는 같은 검사를 메인이 직접 수행하되, 임시 파일을 만들 필요는 없다. 스크립트는 JSON으로 자수와 발견 위치를 반환한다. `blocking_issues`는 Gate 1 전에 처리하고, 이중피동 후보와 연속 장문처럼 문맥 판단이 필요한 항목은 `warnings`로만 넘겨 Gate 1이 판정한다.

- `blocking_issues`가 있으면 메인이 목사님께 먼저 보고하고, 수정 여부를 확인한 뒤에만 Gate 1로 넘어간다. `warnings`만 있으면 중단하지 않는다.
- 이 게이트는 **공백·분량처럼 판단이 필요 없는 것만 차단**한다. 이중피동 후보·장문 경고와 문장 좋고 나쁨은 Gate 1의 몫이다.

# Gate 1 — 채점자 (`gpt-5.6-terra`, 1회, 9항목 100점)

## 배점표 (청중적합성 제외)

| 항목 | 배점 |
|---|---|
| 문장구조·구어적합성 | 15 |
| 신학적 적합성 | 20 |
| 흐름 연속성 | 15 |
| 인문학적 깊이 | 15 |
| 메인아이디어 연관성 | 10 |
| 현상학적 접근성 | 10 |
| **본문·원어 충실성** | **5** |
| **버틀릭 무브구조 준수도** | **5** |
| **이미지·모티프 유기성** | **5** |
| **합계** | **100** |

**청중적합성은 이 100점에 없다.** Gate 2에서 별도로, 점수화하지 않고 다룬다.

**90점 이상 = Gate 1 통과 → Gate 2 진행.** 미달 시 문제 문장을 정확히 지목한다. "흐름이 조금 아쉽습니다" 같은 말은 채점이 아니다.

## 항목 상세

### 메인아이디어 연관성 (10점)
채점 전에 먼저 그 주의 메인아이디어를 명시적으로 확인하고 시작한다.
- 이 무브가 메인아이디어의 **어느 국면**을 맡는지 한 문장으로 규정할 수 있는가. 규정이 안 되면 5점 이하.
- 그 국면이 실제 본문에 구현됐는가, 무브흐름 표에만 있는가.
- **앞뒤 무브에 넘겨줄 고리를 남겼는가.** 이 항목의 실패는 대부분 여기서 난다.

### 현상학적 접근성 (10점) — Buttrick 기준
- **이미지 하나 · 무드 하나.** 한 무브 안에서 무드가 바뀌면 무브 두 개다.
- **확정 이미지가 무브 전체를 지탱하는가.** 도입에만 있고 사라지면 감점.
- **청중 의식에 남는 것이 '장면'인가 '정보'인가.** 어휘 주석·개념 해설이 3개 이상 연속하면 강해설교 구조로 넘어간 것이다.
- **진입이 의식의 순서를 따르는가.** 본문 순서가 아니라 의식의 순서. 명명(라벨) 없이 곧장 장면으로 들어가면(즉시성의 모드) 가점.

### 본문·원어 충실성 (5점, 신설)
원어 의미, 역사적 배경, 타 본문과의 연결이 과장·왜곡 없이 정확한가. 근거 없는 추정을 사실처럼 서술했으면 감점.

### 버틀릭 무브구조 준수도 (5점, 신설)
무브 내 인칭·시제가 끝까지 흔들리지 않는가(의식의 연속성). 결말이 명령형이 아니라 서술형을 유지하는가. 무브 간 전환이 매끄러운가. 단일 이해(하나의 이해)로 수렴하는가 — 이중·삼중 무브 여부를 여기서 잡는다.

### 이미지·모티프 유기성 (5점, 신설)
반복 이미지(길·빛·반석·물살 등)가 단순 반복이 아니라 무브를 거치며 발전·회수되는가. 서로 다른 이미지 계열이 한 무브 안에서 충돌 없이 공존하는가, 아니면 뒤섞여 산개하는가.

## 채점 전 체크리스트 (유지)
삽화 방향 일치(`sermon-lectionary` §삽화·예화 선택 원칙) / 봉독 범위 생략 / 일반화 단정 완화 / 호칭 안전선 / 원어 제한(전체 1~2회, 무브당 1개) / 인용 식상함(김춘수 〈꽃〉 지양) / 묘사·숫자의 성경적 근거 / 절 표기 일관성 / 낭독 오청 / 제목 키워드 밀도 / 전환 문장 유무 / (신규·구조 등급) Voice 위조적 흉내 경고 신호.

## 자수 기준
- 무브당 700~750자(공백 제외), 성찬주일은 600~650자. 5무브 총 3,500~3,750자(성찬주일 3,000~3,250자).
- 계측은 메인이 한다. 서브에이전트는 넘겨받은 숫자로 판정만 한다.
- 미달이면 패딩 제안 금지 — 실질 내용 보강 지점을 지목한다. 초과면 감량 1순위 문단을 지정한다.

# Gate 2 — 청중 3인 병렬 (`gpt-5.6-luna`, Gate 1 통과 후에만)

## 호출 방식
**Gate 1이 90점 이상일 때만** 실행한다. **`gpt-5.6-luna` 모델로 3개의 완전히 독립된 서브에이전트를 동시에 생성**한다(같은 프롬프트, 같은 본문 — 독립 표본 3개). 서로의 응답을 보지 못한다. 세 에이전트가 끝난 뒤 메인이 결과를 모아 다수결을 계산한다.

## 넘길 것
**낭독용 설교 본문만.** 제목·점수표·무브명·루브릭·직전 지적사항 등 메타는 전부 제외한다. 채점자가 무엇을 지목했는지 절대 알려주지 않는다 — 알려주면 그 지점을 확인하러 가는 편향이 생긴다.

## 역할 프롬프트 (3개 모두 동일하게, 그대로 넣는다)

```
너는 20대 초반, 입대한 지 얼마 안 된 초신자 용사다. 교회는 부대 안 벧엘교회,
주일예배에서 이 설교를 딱 한 번 귀로 듣는 상황이다. 신학 지식은 거의 없다.
아래 설교를 '듣고' 솔직하게 답해라. 서브에이전트를 추가로 호출하지 말고,
도구도 쓰지 말고, 네가 바로 답해라.

1) 한 번 듣고 머리에 남은 것 3가지만 짧게 적어라.
2) 혼란스럽거나 걸리는 지점이 있었는가? 구체적 문장을 짚어 말하라.
   **정말 없으면 "없음"이라고 답해도 된다.** 억지로 지적을 만들어내지 마라.
3) [국소 수정일 때만 추가] 이번에 특히 바뀐 부분: "{바뀐 문장}"을 들었을 때
   자연스러웠는가, 걸렸는가?

지어내지 말고, 실제로 그 문장이 있어서 느낀 것만 말해라.
걸리는 지점은 반드시 아래 형식으로 답해라.
`유형: 용어·전제 / 논리·전환 / 문장·낭독 / 이미지·장면 / 설교조·반발 / 삶 연결 / 기타 중 하나`
`인용: "원문 그대로" / 이유: ...`
```

## 판정 — 다수결, 점수화 안 함
- 3인 중 **2인 이상이 같은 지점**을 독립적으로 지목해야 "실제 결함"으로 인정한다.
- "같은 지점"은 **인용한 원문 범위가 같은 문장을 포함하고, 위 닫힌 목록의 결함 유형도 같은 경우**다. 같은 문장을 인용했더라도 유형이 다르면 합치지 않는다. `기타`끼리는 이유까지 실질적으로 같을 때만 합친다.
- 인용 범위나 결함 유형의 일치가 애매하면 각각 1/3 소수 의견으로 남기고 채택하지 않는다.
- 1인만 언급한 것은 **기록은 하되 조치하지 않는다.**
- "없음" 응답이 3인 중 다수면 그 원고 구간은 **결함 0건**으로 확정한다.
- 절대 몰입도를 숫자(10점 만점 등)로 합산하지 않는다 — 이것이 예전 체계가 "지어낸 숫자"를 만들던 지점이었다.

## Freeze 규칙 (신설)
**결함 0건으로 통과한 문단은, 그 문단이 다시 수정되지 않는 한, 같은 평가 단위의 다음 라운드 청중 표본에 재노출하지 않는다.** 매 라운드 전문을 새로 읽히면 몇 라운드 지나 갑자기 "이 문장이 걸린다"는 반응이 우연히 나올 수 있다(관측된 실패: 91점 베이스라인 문장이 5라운드 뒤 갑자기 지적됨).

- 첫 Gate 2 전에 문단을 `P1`, `P2`처럼 번호 매기고, 버전·첫 12자·끝 12자·공백 제외 자수·상태를 **Freeze 대장**에 기록한다.
- 국소·구조 수정 모두 **바뀐 문단만** 다시 평가한다. 앞뒤 고정 문단이 이해에 필요하면 `[문맥 전용—평가 금지]`로 표시해 한 문단씩만 붙인다.
- 수정된 문단은 기존 ID에 새 버전을 붙인다(예: `P3-v2`). 문장 내용이 같아도 **위치가 바뀌거나 앞뒤 인접 문단이 달라지면 맥락 수정으로 간주**해 새 버전으로 다시 평가한다. 내용·위치·인접 맥락이 모두 같을 때만 기존 frozen 상태를 유지한다.
- 5무브 전체 총평은 무브 단위 평가와 다른 새 평가 범위이므로 새 Freeze 대장을 만들고 전문을 한 번 노출할 수 있다.

## 출력 형식
```markdown

| 청중 | 남은 것 3가지 | 혼란 지점 | 비고 |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

#### 다수결 결함 (2/3 이상)
- {지점}: {2/3}인 지목 — **채택**

#### 소수 의견 (기록만, 미조치)

#### Freeze 대장
| 문단 ID | 버전 | 식별값(첫 12자…끝 12자 / 자수) | 상태 |
```

# Gate 3 — 병기 보고 (절대 병합 금지)

두 결과를 **절대 하나의 숫자로 섞지 않는다.** 다음 형식 그대로 보고한다.

```
Gate 1 (구조) 점수: {n}/100
Gate 2 (청중) 결함: {N}건 (각 결함별 표결: {지점 A 2/3, 지점 B 3/3 ...})
```

- **90점 이상(Gate 1) = 수정 종료를 고려할 기준.** 다만 Gate 2에서 다수결 결함이 남아 있으면 그 사실을 함께 보고하고, 처리 여부는 목사님이 정한다.
- Gate 1과 Gate 2가 어긋나 보여도(예: Gate 1은 92점인데 Gate 2에서 결함 2건) 임의로 조정된 "청중 반영 최종점수" 같은 걸 만들지 않는다. 만드는 순간 예전 실패가 재현된다.
- 결함 대장(defect ledger)에 버전·결함별 표결·조치 여부를 누적하고 Freeze 대장도 함께 기록한다. 프로젝트의 `03-초안.md` 갱신이 현재 요청 범위에 포함된 경우에만 파일에 쓰고, 그 외에는 응답 안에 대장을 유지한다.

# 순환 규칙

- **최대 3라운드.** 그 뒤에도 Gate 1이 90 미만이면 `gpt-5.6-sol` 고추론 1회로 승급하고, 그래도 미달이면 남은 문제를 위치와 함께 보고하고 판단을 목사님께 넘긴다. 점수를 억지로 올리지 않는다.
- Gate 1 결과는 항목별 표 + 직전 버전 대비 증감으로 제시한다.
- 버전별 점수·결함·Freeze 상태를 응답에 누적한다. `03-초안.md` 기록은 사용자가 해당 파일 갱신을 요청했거나 현재 설교 작성 작업에서 파일 저장이 명시된 경우에만 수행한다.

# 경계 (비협상, 유지)

- 신학 교정 제안은 채택하지 않는다. `sermon-lectionary`의 신학 원칙(Being→Doing, 선행적 은혜, 이단 논리 배제 등)이 항상 우선한다.
- Gate 2는 시뮬레이션이므로 과신 금지. `[청중추정]`으로 표시한다.
- Gate 2 청중 역할은 고쳐 쓰지 않는다. 반응만 보고한다.
- 서브에이전트는 서브에이전트를 부르지 않는다 — 병렬 호출은 항상 메인 에이전트의 책임이다.
- 이단(구원파·신천지) 논리 배제.
