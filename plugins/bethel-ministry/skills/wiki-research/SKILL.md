# wiki-research

LLM 위키의 "검증 가능한 원천"을 만드는 리서치 워크플로우입니다.

범용 메가리서치는 검색·수집한 내용을 요약 노트로만 남깁니다. 폭은 넓지만 두 가지가 약합니다. 원문이 남지 않아 나중에 대조할 수 없고, 검증 단계 없이 위키에 들어갑니다. 그 결과물은 "수집·정리"이지 "검증"이 아닙니다. 이 스킬은 그 두 빈자리를 채웁니다. 원문을 먼저 보존하고, 정독하고, 인용 시점에 대조합니다.

메가리서치가 틀린 것이 아니라 목적이 다릅니다. 넓게 훑어 구조를 잡을 때는 메가리서치가 맞고, 위키에 들어갈 신뢰 가능한 자료를 만들 때는 이 스킬을 씁니다.

## 메가리서치와의 차이

| 항목 | research-mega-topic | wiki-research (이 스킬) |
| --- | --- | --- |
| 원문 보존 | 없음(요약 노트만 생성) | raw에 원문 저장 |
| 깊이 | deep 기본(소스 8~12, 원문 미보존) | deep 기본(web_fetch 정독 + raw 보존) |
| 출처 등급 | A/B/C 표기 | A/B/C 표기 + 1차 출처 우선 선별 |
| 검증 | 자가 평가만 | 인용 직전 1차 대조 |
| 목적 | 넓게 훑어 구조 잡기 | 신뢰 가능한 위키 원천 |

## 전제 — 위키 폴더 지침 우선

위키 폴더(예: `50 LLM 위키/`)에 CLAUDE.md가 있으면 그 스키마·소스 표기·운영 규약을 이 스킬 기본값보다 우선 적용합니다. 특히 그 폴더가 "위키 리서치 체인" 규칙을 정의했다면 이 스킬은 그 규칙의 실행 절차로 동작합니다. 폴더 지침이 없을 때만 아래 기본 절차를 그대로 씁니다.

## 6단계 워크플로우

### Phase 0 — 대주제·소스 확인
대주제와 저장 폴더(기본 `02 AI 리서치 노트/{대주제}/`), 위키 폴더를 확정합니다. 대주제가 모호하면 한 가지만 질문합니다. 동일 폴더가 있으면 덮어쓸지·이름을 바꿀지 확인합니다.

### Phase 1 — 수집 (원문 스크랩 → raw)
핵심 출처의 원문을 위키 `raw/` 폴더에 md로 저장합니다. 이 단계가 이 스킬의 핵심입니다. 원문이 옆에 있어야 나중에 요약을 대조할 수 있기 때문입니다. 각 파일 상단에 메타를 붙입니다.

```
raw_type: collect
source: 원문 URL
captured: 수집일(KST)
published: 작성일(있으면)
grade: A(공공통계·정부·국제기구) / B(민간 리서치·학계·산업계 인정) / C(언론·IR·블로그·SNS·업체 페이지)
context: 수집 이유 한 줄 + 연결할 위키 주제
```

원칙:
- `raw_type: collect`로 표기합니다. raw는 단일 폴더이고 용도는 속성으로 가립니다(수집 원문 collect, 인용 미러 mirror). 폴더를 쪼개지 않습니다.
- 본문은 광고·내비게이션을 제거하고 원문만 보존합니다. 요약·재구성하지 않습니다.
- 모든 자료를 넣지 않습니다. 반복 사용·판단 영향·작업 연결 중 2개 이상일 때만 넣습니다(선별). 정리에 5분 넘게 걸리면 보류합니다.
- 파일명은 `raw_원본제목.md`. 맥에서 만들면 파일명을 NFC로 정규화합니다(자소 분리로 링크가 깨지는 것을 막기 위함).
- 저장 전 같은 `source` URL의 기존 raw 파일이 있는지 점검합니다. 있으면 중복 저장하지 않고 알립니다.
- 스크랩이 막히면(접근 제한·동적 페이지) 건너뛰고 "스크랩 실패"로 표기합니다. 임의 우회·대체 수집은 하지 않습니다.

원문을 web_fetch로 가져온 뒤, 결정적 저장(파일명 NFC 정규화·중복 점검·frontmatter 일관성)은 `scripts/save_raw.py`에 맡깁니다. 매번 손으로 frontmatter를 쓰지 않게 해 동작을 일정하게 유지하기 위함입니다. 스크립트는 스킬 폴더의 `scripts/save_raw.py`에 있으며, 실행 시 설치 위치 기준 절대 경로로 호출합니다.

```bash
python scripts/save_raw.py \
  --raw-dir "<vault>/50 LLM 위키/raw" \
  --source "https://..." --title "원본제목" \
  --grade C --context "수집 이유 + 연결 위키 주제" \
  [--published 2026-05-20] --body-file body.txt
# 본문은 web_fetch 결과를 body.txt에 저장하거나 stdin으로 전달.
# 출력 JSON status: saved / duplicate(같은 source 존재) / error.
```

본문 전달 경로: web_fetch 결과를 먼저 작업 폴더의 임시 텍스트 파일(예: body.txt)에 쓴 뒤 `--body-file`로 넘깁니다. fetch 결과를 직접 파이프로 넘기면 대용량일 때 누락될 수 있습니다.

fetch 가용성: 위키·SEO 블로그·일부 언론은 web_fetch에서 빈 본문이나 차단(403)이 잦습니다. arXiv·정부·연구기관·1차 보고서처럼 fetch가 잘 되고 등급도 높은 출처를 우선 후보로 잡고, deep 소스 수(8~12)를 채우려면 실패에 대비해 후보 URL을 넉넉히 둡니다. 차단된 URL은 "스크랩 실패"로 표기하고 대체합니다.

### Phase 2 — 정리 (deep R_ 노트)
raw에 저장한 원문 파일을 정독하고, deep 깊이로 R_ 노트를 만듭니다. 스니펫이 아니라 문단을 읽어야 맥락 손실과 오독이 줄기 때문입니다.
- 소스 8~12개, 영문·한글 혼합.
- 슬롯: 개요 / 핵심 내용 / 주요 수치 / 시사점 / 출처.
- 각 R_ 노트의 sources에 자신이 근거한 raw 원문 파일을 명시합니다.
- R_ 노트 frontmatter에 `expires_at`(선택)을 부여합니다. 기준은 Phase 4 신선도 항목과 같습니다.

### Phase 3 — 정제 (선별 인제스트)
R_ 노트와 raw 원문을 근거로 위키 페이지(W_)를 만들거나 갱신합니다. 위키 폴더가 별도 인제스트 규칙을 가지면 그것을, 아니면 wiki-ingest를 따릅니다. 중복을 점검하고 일반화 가능한 개념만 선별합니다. 생성한 R_ 노트를 전부 위키에 넣지 않습니다.

### Phase 4 — 검증 (Evaluator)
Phase 2·3과 분리된 시점에서 점검합니다. 생성과 평가를 분리해야 자기 요약을 무비판적으로 신뢰하지 않기 때문입니다.
- 수치·사실이 raw 원문과 일치하는가(스니펫이 아니라 원문 대조).
- 등급 A·B만 단정했는가. C 단독 수치는 "참고 수준"으로 표기했는가.
- 원문에 없는 내용을 임의 생성하지 않았는가.
- 신선도(`expires_at`)를 R_ 노트에 주제 성격에 맞게 설정했는가(트렌드·도구 90일 / 시장·정책 180일 / 일반 개념은 만료 대신 180일 검토 / 경험 기록 만료 없음). wiki-audit 신선도 점검과 같은 기준이며, `expires_at`이 있으면 audit이 임계값보다 우선 적용합니다.

불일치는 원문 근거로 교정합니다. 근거가 없으면 "원문에 근거 없음"으로 표시하고 임의 보충하지 않습니다.

### Phase 5 — 출력·연결
생성한 R_·W_ 노트명과 raw 경로를 표기하고, 후속 스킬에 넘깁니다(블로그 write-blog, 책 book-writing-pro, 강의 lecture-research). 글·책에 사실·수치를 인용하는 시점에 Phase 4 검증을 한 번 더 적용합니다.

## 출처 등급 규약

수치를 어디까지 단정할지는 출처 등급으로 가릅니다. 같은 "45%"라도 정부 통계와 업체 블로그는 무게가 다르기 때문입니다.

| 등급 | 출처 | 사용 |
| --- | --- | --- |
| A | 공공통계·정부·국제기구 | 수치 단정 가능 |
| B | 민간 리서치·학계·산업계 인정 | 수치 단정 가능 |
| C | 언론·IR·블로그·SNS·업체 페이지 | "참고 수준"·교차확인 필요 |

## Harness

- 생성-평가 분리: Phase 2·3(생성)과 Phase 4(평가)를 분리해 원문 대조를 별도 시점에 수행합니다.
- 보존 레벨: raw 원문은 불변(L1). R_·W_의 묶음·순서 재배열은 L2. 도입·연결·문체는 L3.
- 금지어 0: 혁신적인·획기적인·완벽한·매우·쉽게·빠르게·"~할 수 있습니다 + 추상명사 중심문장"을 제거합니다. 종결어미는 ~합니다체로 통일합니다. 단, 영문 원문을 직역할 때 금지어가 들어가면(예: "easily gamed" → "쉽게") 의미를 보존한 의역으로 바꿉니다("적은 노력으로 우회"). 검증 메모에 금지어 목록 자체를 적지 않습니다(자동 스캔 오탐 방지).
- 분량: deep R_ 노트 3,000~5,000자. 분량은 소스 수를 맞춘 결과로 따라옵니다. 근거 없는 서술로 분량을 채우지 않습니다.

## 깊이 전환

기본은 deep입니다. 사용자가 "빠르게"·"basic으로"·"넓게만"이라고 하면 그때만 Phase 1(원문 스크랩)을 생략하고 메가리서치식 basic으로 전환합니다. deep는 web_fetch가 많아 토큰·시간이 더 들므로, 10주제 배치는 분할하거나 핵심 주제부터 진행합니다.

## 다른 스킬과의 관계

- 파이프라인: 이 스킬 → wiki-ingest(정제) → wiki-audit(점검) → wiki-activate(활용).
- 대체 아님: 넓은 탐색은 research-mega-topic, 단일 주제는 research-topic을 그대로 씁니다. 이 스킬은 "위키 원천 품질"이 필요할 때 씁니다.
