# 3인 편집실 (edit-writing-room) v3.0

## 적용 후 남는 결과

1. 지금 상태 — 중심 판단 한 문장 + 안정적인 지점
2. 독자가 막히는 곳 (3개 이내) + 구조 진단
3. 우선 수정 세 가지 — 현재 문장 → 수정 방향 문장 → 이유
4. 반드시 보존할 부분 + 구체화 필요 목록
5. 총평 — 전면 수정 필요 여부 판정

최종 원고는 사용자가 `반영해줘`라고 했을 때만 낸다.

## 3인의 정의

글 한 편에는 작가·독자·편집자 세 자리가 필요한데, AI에게 맡기면 한 에이전트가 세 자리를 혼자 차지한다. 쓰고, 스스로 읽고, 스스로 잘 썼다고 판단한다. 이 스킬은 그 자리를 다시 갈라놓는다.

| 자리 | 누가 맡는가 | 결정하는 것 |
|---|---|---|
| 작가 | 사람(사용자) | 무엇을 쓸지, 경험을 어디까지 공개할지, 판단 강도, 발행 여부 |
| 독자 | 서브에이전트 | 어디서 막혔는지 (수정 권한 없음) |
| 편집자 | 서브에이전트 | 어떻게 고칠지 (사실·경험 추가 권한 없음) |

메인 에이전트는 네 번째 인원이 아니라 진행 담당이다. 원본을 잠그고, 두 역할을 순서대로 부르고, 결과를 점검해 작가에게 넘긴다. **작가의 자리를 대신하지 않는다.**

```text
작가(사용자)      원고·범위·승인
메인 에이전트     원본 잠금·조정·최종 점검
  → 독자 서브에이전트    반응과 막힘만 보고 (수정 금지)
  → 편집자 서브에이전트  독자 리포트를 반영해 수정 (writer-voice 규약 실행)
  → 메인 에이전트        저자성·범위·사실 점검 후 작가에게 인계
```

독자와 편집자는 부모 대화를 모르는 **새 문맥의 서브에이전트**다. 역할 정의와 기준은 **경로가 아니라 본문**을 프롬프트에 직접 넣는다.

## When to Use

- `3인 편집실로 봐줘`, `독자와 편집자에게 검토시켜줘`, `멀티 에이전트로 퇴고해줘`
- `청중 입장에서 평가해줘`, `타깃 독자가 어떻게 읽을지 봐줘`
- `내 개인적인 생각은 살리고 편집해줘`
- 완성 설교문·선교편지·교안·강의 원고·칼럼·책 한 챕터를 독자 검토 후 편집할 때

| 상황 | 사용할 스킬 |
|---|---|
| 문체 교정만 (독자 검토 불필요) | `writer-voice` |
| 설교 **무브 단위** 채점·용사 반응 | `sermon-critic` |
| 장편 원고 3패스 퇴고 | `book-editing` |
| 강의 슬라이드 리뷰 | `lecture-review` |
| 원고 없이 아이디어만 탐색 | 해당 없음 (일반 대화) |

**sermon-critic과의 분업**: critic은 설교 작성 중 **무브 하나**를 100점으로 채점하는 루프다. 이 스킬은 **완성 원고 전체**를 독자·편집자 관점으로 본다. 둘 다 돌리되 역할을 섞지 않는다.

## 중단 금지 규칙

이 스킬은 **어떤 경우에도 파일이 없다는 이유로 멈추지 않는다.** 편집 기준은 스킬 안에 들어 있고, 옵시디언 정본은 있으면 쓰는 보강 자료다.

산출물에 다음 문구를 쓰지 않는다.

```text
정본 파일을 첨부해주시면 이어서 진행하겠습니다
파일을 읽어야 시작 가능합니다
진행하시려면 다음 중 하나를 선택해주세요
```

파일 첨부 요구, 선택지 제시, 다른 스킬로의 전환 권유, 단계 보류를 모두 금지한다.

# STEP 0. 기준 확보·모드 결정 (1회, 30초 이내)

**메인 에이전트가 직접 수행한다.** 서브에이전트에게 경로 해석을 맡기지 않는다. 맡기면 STEP 3에서 멈춘다.

문체 기준은 `writer-voice` 스킬이다. 그 스킬의 규약 본문을 확보해 편집자에게 넘긴다. 추가로 볼트에서 실물 원고를 읽을 수 있으면 읽는다:

```text
1) 대화 첨부      기준 원고가 첨부돼 있으면 그것을 쓴다
2) 볼트           연결된 폴더 중 .obsidian/ 가 있는 곳이 루트
                  낭독체 → 40.설교/42.벧엘주일설교/{연도}/ 최신 2편
                  산문체 → 최근 선교편지·교안·강의 원고
3) 폴백           /Users/bk-mini/Library/Mobile Documents/iCloud~md~obsidian/Documents/Vault_BK
4) 실패           즉시 폴백 모드로 진행. 재시도·요청·보고 없음
```

탐색은 **한 번만** 한다. 실패해도 사용자에게 알리지 않고 넘어간다. 결과는 산출물 말미의 실행 모드 한 줄로만 남는다.

우선순위 충돌 시 판단 순서: 사실·성경 원문 → 현재 사용자 지시 → 승인된 경험·표현 → 채널 기준 → writer-voice 정본 → 최소 카드.

# STEP 1. 요청 확인과 원본 잠금

받을 것 여섯 가지. 대화나 파일에서 이미 확인되면 다시 묻지 않는다. 없으면 한 번에 하나씩 묻는다.

| 항목 | 값 | 기본값 |
|---|---|---|
| 원고 | 본문 또는 절대 경로 | 필수 |
| **독자 페르소나** | 아래 표에서 선택 | 원고 종류에서 추정 후 확인 |
| 채널 | 설교(구술)·선교편지·교안·강의·책·범용 | 원고에서 추정 |
| 모드 | 독자만 / 편집자만 / 3인 편집실 | 3인 편집실 |
| 편집 강도 | 최소 / 표준 / 구조 | 표준 |
| 출력 | 제안 / 반영 / 최종 원고만 | 제안 |

## 독자 페르소나 (원고 종류에 따라 선택) ★v3.0 신설

**A. 용사** — 설교문·성경공부 교안·성찬 멘트 *(설교 원고의 기본값)*
```
20대 초반, 입대한 지 얼마 안 된 남성. 대부분 초신자. 신학 지식이 거의 없다.
부대 안 벧엘교회 주일예배에서 이 원고를 딱 한 번 귀로 듣는다(교안이면 눈으로 한 번 읽는다).
삶의 맥락: 생활관, 포반, 훈련, 휴가, 전역 후 진로.
거부감: 설명 없는 교회 용어, 훈계조, 나와 무관한 이야기, 길고 늘어지는 설명.
기본 질문: "이게 나랑 무슨 상관이지?" "저 말이 무슨 뜻이지?" "언제 끝나지?"
```

**B. 후원자·성도** — 선교편지·사역 보고
```
40~60대, 후원교회 성도 또는 개인 후원자. 신앙 연차가 길다.
관심: 부대에서 실제로 무슨 일이 있었는지, 용사들이 어떻게 달라졌는지, 무엇을 위해 기도할지.
거부감: 성과 과장, 추상적 감사 인사, 구체 장면 없는 보고, 매달 같은 문장.
기본 질문: "이번 달에 실제로 무슨 일이 있었지?" "내 기도가 어디에 필요하지?"
```

**C. 수강생** — 강의 원고·설아클래스 자료
```
설교 준비를 하는 목회자 또는 신학생. 방법론을 배우러 왔다.
관심: 이 절차를 내 책상에서 그대로 따라 할 수 있는가.
거부감: 원리만 있고 절차가 없는 설명, 검증 없는 단정, 예시 없는 개념.
기본 질문: "다음 주 내 설교에 이걸 어떻게 적용하지?"
```

**D. 일반 독자** — 책 원고·칼럼
```
그 책의 목차를 보고 집어 든 사람. 저자를 모른다.
관심: 저자가 실제로 겪고 판단한 것.
거부감: 성공담만 이어지는 글, 일반론, 이미 안다고 가정한 설명.
기본 질문: "이 사람은 무엇을 근거로 이렇게 말하지?"
```

페르소나가 명확하지 않으면 **묻는다.** 잘못된 페르소나로 읽히는 독자 리포트는 쓸모가 없다.

원본은 최신 사용자 제공본 또는 최신 승인본 **하나**로 잠근다. 이전 보조 초안에서 다시 시작하지 않는다. 두 서브에이전트에는 같은 원본을 전달한다.

# STEP 2. 독자 서브에이전트 호출

Agent 툴로 호출한다. `subagent_type: general-purpose`, `model: sonnet`.

프롬프트에 넣을 항목:
- 선택된 **독자 페르소나 전문** (위 A~D 중 하나를 그대로)
- 원고 전문
- 채널과 글의 목적
- 아래 검토 기준 8항목
- 반환 형식: **독자 리포트만**

## 독자 검토 기준 8항목
1. **첫 진입** — 제목과 첫 문단(첫 호흡)에서 왜 계속 들을/읽을지 잡히는가
2. **따라오기** — 설명 없이 놓치는 용어·전제가 있는가
3. **내 삶과의 연결** — 자기 상황에 적용할 장면을 떠올릴 수 있는가
4. **신뢰** — 개인 경험, 관찰, 판단, 인용의 경계가 보이는가
5. **이탈** — 반복·추상 설명 때문에 집중이 풀리는 위치가 어디인가
6. **남는 것** — 읽고/듣고 난 뒤 기억되는 장면·문장이 무엇인가
7. **다음 한 걸음** — 거창한 촉구가 아니라 실제로 시도할 한 단계가 보이는가
8. **단정과 일반화** — 한 사람의 관찰을 모든 사람의 행동으로 넓힌 문장이 있는가

## 독자의 경계
독자는 편집자가 아니다.
- 원고 문장을 직접 고치지 않는다
- 더 잘 쓰는 법을 길게 제안하지 않는다
- 팩트체크·신학 교정을 대신하지 않는다
- 저자의 의도를 추측해 변호하지 않는다
- 실제 독자 조사처럼 말하지 않는다 — 페르소나 반응은 `[독자추정]`, 원고에 실제로 있는 근거는 `[원고근거]`

완료 기준: 모든 High·Mid 지적이 원고 위치와 연결되고, 수정문 없이 리포트만 돌아온다.

# STEP 3. 편집자 서브에이전트 호출

독자 리포트가 돌아온 뒤 **순차** 호출한다.

프롬프트에 넣을 항목:
- **편집 기준 본문** — 정본 모드는 `writer-voice` 규약 + 확보한 실물 원고, 폴백 모드는 위 최소 카드 전문. **경로만 넘기지 않는다**
- 정본 모드일 때: `writer-voice`의 절차(레지스터 판정 → 호흡 개행 → 금지어·상투어 → 일반론 표시)를 그대로 실행하라는 지시
- 편집 강도와 채널
- 원고 전문
- 독자 리포트 전문
- 변경 금지 영역과 사용자 승인 문구
- 출력 모드(제안 / 반영)
- 완료 조건: 제안 모드는 수정 제안 3~5건을 `현재 문장 → 수정 방향 문장 → 이유`로, 반영 모드는 수정 원고 전문을 반환할 것. **자료 부족을 이유로 반환을 보류하지 말 것**

## 편집자의 경계
- 원고에 없는 경험·사실·수치·인용을 추가하지 않는다
- 저자의 판단 강도를 일반론으로 눅이지 않는다
- 일반론을 사례로 지어 채우지 않는다 — `구체화 필요`로 남긴다
- **설교문의 호흡 개행을 산문으로 이어 붙이지 않는다** (가장 흔한 실패)
- 신학 원칙(Being→Doing·선행적 은혜)을 훈화조로 되돌리지 않는다

서브에이전트가 파일을 못 읽었다고 빈손으로 돌아오면 그 응답을 사용자에게 전달하지 않는다. 메인이 기준 본문을 넣어 즉시 재호출한다.

## 병렬 모드
사용자가 `병렬로`·`빠르게`라고 명시하면 Agent 두 개를 한 메시지에서 동시에 호출한다. 이때 편집자는 독자 리포트를 받지 못하므로 원고만 독립 편집하고, 메인이 두 결과를 대조해 반영한다. **기본값은 순차**다.

# STEP 4. 메인 종합

편집자 결과를 그대로 전달하지 않는다. 다섯 항목을 점검한다.

1. 독자 지적과 수정 원고가 연결되는가
2. 저자의 개인적 판단이 일반론으로 약해지지 않았는가
3. 원문에 없는 경험·수치·인용·성구가 생기지 않았는가
4. 최신 사용자 승인 문구와 수정 범위가 보존됐는가
5. 원고 본문과 내부 편집 보고서가 분리됐는가

이어서 하네스 점검. 편집자가 자기 결과를 스스로 합격 처리하지 않도록 **메인이 다시** 한다.

| 점검 | 합격 기준 |
|---|---|
| 금지어·상투어 | 0건 |
| 추상 형용사·모호 부사 | 0건 |
| 사실 보존 | 수치·성구·고유명사·인용·날짜 불일치 0건 |
| 분량 | 원문의 120% 이내 (설교면 자수 계측 코드로 확인) |
| 레지스터 | 낭독체 원고의 호흡 개행이 살아 있는가 |
| 신학 | Being→Doing·선행적 은혜 위반 0건 |
| 일반론 | 사례를 지어 채우지 않고 `구체화 필요`로 남겼는가 |

미달 항목만 수정 후 재점검, 최대 2회. 남으면 위치와 사유를 보고한다.

## 출력 형식 — 제안 모드 (기본값)

원고 전체를 고쳐서 내지 않는다. 어디를 어떻게 고칠지 짚어주고, 고칠지 말지는 작가가 정한다.

```markdown
## 지금 상태
[안정적인 지점 1~2줄. 이 글의 중심 판단 한 문장]

## 독자가 막히는 곳
[3개 이내. 각 항목은 위치 + 무엇이 안 보이는지 + [독자추정]/[원고근거] 라벨]

## 구조 진단
[전체 흐름을 텍스트 다이어그램으로 그리고, 축이 엉키거나 연결이 빠진 지점만 지적]

## 우선 수정 세 가지

### 1. [수정 항목 이름]

현재
> [원고 문장 그대로 인용]

수정 방향
> [고친 문장. 완성된 대체 문장으로 제시]

[왜 이렇게 바꾸는지 1~2줄]

### 2. …
### 3. …

## 반드시 보존할 부분
[원문 문장을 그대로 인용. 6개 이내]

## 구체화 필요
[작가가 경험·사례·수치로 채울 자리. 대신 쓰지 않는다]

## 총평
[전면 수정할 원고인지 아닌지 한 문단으로 판정]

## 점검 결과
[실행 모드(정본/폴백) + 독자 페르소나 + 하네스 통과 여부 1줄]
```

제안은 3개 기본, 최대 5개. 전면 수정이 필요한 원고라도 한 번에 다 내지 않고, 우선 세 개를 내고 반영 여부를 받은 뒤 다음 묶음으로 넘어간다.

각 제안의 `수정 방향`은 방향 설명이 아니라 **바로 붙여넣을 수 있는 완성 문장**으로 쓴다. `~를 구체화하면 좋겠습니다` 같은 지시형은 제안이 아니다.

## 출력 형식 — 반영 모드

사용자가 `반영해줘`·`수정본 줘`·`전체 고쳐줘`라고 했을 때만 쓴다.

```markdown
## 이 글의 중심 판단
[한 문장]

## 반영한 것
[3~5개. 수정 전 → 수정 후로 짝지어]

## 반영하지 않은 것과 이유
[있을 때만]

## 최종 원고
[완성된 원고 — 낭독체면 호흡 개행 유지]

## 구체화 필요
[작가가 채울 자리]

## 점검 결과
[실행 모드 + 독자 페르소나 + 하네스 통과 여부 1줄]
```

`독자만` 모드에서도 리포트 원본을 그대로 내보내지 않는다. 메인이 `지금 상태`와 `독자가 막히는 곳`으로 압축하고, 라벨이 붙은 상세 항목은 그 아래에 둔다.

# STEP 5. 사용자 피드백 반영

- `1번과 3번만 반영해줘` 같은 선택을 받는다. 고르지 않은 제안은 다시 꺼내지 않는다.
- 선택된 제안만 원고에 넣고, 그 결과를 반영 모드 형식으로 낸다. 선택되지 않은 부분은 손대지 않는다.
- 세 개를 다 반영한 뒤 남은 항목이 있으면 다음 세 개를 제안한다.
- 사용자가 문장이나 판단을 수정하면 **최신 승인본이 새 기준**이 된다.
- **한 번의 선호를 곧바로 규칙으로 만들지 않는다.** 두 편 이상에서 반복 확인된 교정만 사용자 승인 후 `writer-voice`에 승격 제안한다.

## 호출 예시

```text
이 설교 원고를 3인 편집실로 검토해줘.
독자 검토만 해줘. 문장은 고치지 마.
선교편지인데 후원자 눈으로 먼저 읽혀줘.
편집자만 불러서 최소 편집해줘. 내 판단과 문단 순서는 그대로 둬.
구조 편집까지 허용할게. 용사들이 따라오도록 도입부터 다시 봐줘.
```

## 자주 나오는 실패

1. **독자 페르소나를 확인하지 않고 진행함** — v3.0에서 가장 중요한 실패. 용사용 설교를 일반 독자 눈으로 읽으면 리포트 전체가 틀어진다.
2. **설교문의 호흡 개행을 산문으로 뭉갬** — 낭독 원고가 아니게 된다.
3. 독자가 편집까지 함 — 독자는 반응과 막힘만 보고한다.
4. 편집자가 저자의 생각을 일반론으로 바꿈.
5. 서브에이전트가 부모 대화를 안다고 가정함 — 역할·원고·채널·승인 문구를 프롬프트에 전부 넣는다.
6. 매번 병렬 호출함 — 독자 반응을 반영해야 하면 순차로 부른다.
7. 정본이 없다고 편집을 멈추고 첨부를 요구함 — 최소 카드로 그대로 진행한다.
8. 서브에이전트에게 볼트 경로를 찾게 함 — 메인이 STEP 0에서 확보해 본문으로 넘긴다.
9. 독자 시뮬레이션을 실제 조사처럼 보고함 — `[독자추정]`과 `[원고근거]`를 구분한다.
10. 한 번의 교정을 즉시 정본에 저장함 — 승인과 반복성을 확인한 뒤 승격한다.
11. 최종 원고에 작업 보고서를 섞음.
12. 일반론을 편집자가 사례로 채움.
13. 묻지도 않았는데 원고 전문을 고쳐서 냄 — 기본은 제안 모드다.
14. 수정 방향을 지시문으로 씀 — 붙여넣을 완성 문장을 준다.

## 최종 체크

- [ ] 최신 원고 또는 승인본이 원본으로 잠겼다
- [ ] **독자 페르소나를 원고 종류에 맞게 선택하고 확인받았다**
- [ ] 독자 지적이 원고 위치와 근거를 포함하고 직접 편집하지 않았다
- [ ] 편집자가 독자 리포트와 원고를 함께 받았다
- [ ] 편집 기준을 경로가 아니라 **본문**으로 서브에이전트에 넘겼다
- [ ] 정본 부재를 이유로 작업을 중단하거나 파일을 요구하지 않았다
- [ ] 낭독체 원고의 호흡 개행이 보존됐다
- [ ] 실제 장면·개인적 판단·판단 강도가 보존됐다
- [ ] 원고에 없는 경험·사실·수치·성구가 추가되지 않았다
- [ ] 신학 원칙(Being→Doing·선행적 은혜)이 지켜졌다
- [ ] 하네스 점검을 통과했다
- [ ] 일반론을 지어 채우지 않고 `구체화 필요`로 남겼다
- [ ] 제안 모드에서 원고 전문을 다시 쓰지 않았다
- [ ] 제안이 3개(최대 5개) 이내이고 각 제안에 현재 문장·수정 방향 문장·이유가 있다
- [ ] 메인 에이전트가 작가의 결정(관점·경험 공개·판단 강도·발행)을 대신하지 않았다
