# 강의 슬라이드 리뷰 워크플로우 v1.1 (Lecture Review Workflow)

완성된 슬라이드의 구조·내용·시각·발표 흐름을 종합 점검하고 수정까지 반영하는 4단계 프로세스.

v1 대비 개선점: 점검 축 0.5 (블루프린트 반영률) 추가, BP 입력 경로 명시, 수정 반영 시 BP 재점검 로직 추가.

## 전체 흐름

```
Phase 1: 슬라이드 읽기 → Phase 2: 종합 점검 → Phase 3: 피드백 리포트 → Phase 4: 수정 반영
```

## 파이프라인 위치

```
lecture-plan → lecture-research → lecture-blueprint → lecture-slides → [이 스킬] lecture-review
```

lecture-slides Phase 4에서 .pptx가 완성된 뒤 실행한다. 강의 노트(옵시디언)에 기획안·리서치·블루프린트·슬라이드 구조가 정리되어 있으면, 해당 노트를 함께 참조하여 기획 의도 및 BP 대비 슬라이드 구현을 대조 점검한다.

---

## Phase 1: 슬라이드 읽기 (Slide Intake)

입력 .pptx를 분석하여 리뷰 기초 데이터를 수집한다.

### 입력

| 항목 | 필수 | 설명 |
|------|------|------|
| `.pptx` 파일 | 필수 | 리뷰 대상 슬라이드 |
| 강의 노트 / 기획안(LP_*.md) | 권장 | 기획 의도·학습 목표·타깃 프로파일 대비 점검에 사용 |
| 블루프린트(BP_*.md) | 권장 | 슬라이드 1장 단위 T-유형·제목·메시지·시각 힌트 대조에 사용. 있으면 점검 축 0.5 실행 |
| 리서치 노트(RL_*.md) | 선택 | 내용 정확성·출처 대조 (선택) |
| 사용자 지정 점검 포인트 | 선택 | "시간 배분이 맞는지 봐줘" 등 특정 관심사 |

### 실행

1. **pptx 스킬을 읽는다** — `/mnt/skills/public/pptx/SKILL.md`
2. `markitdown`으로 슬라이드 전체 텍스트를 추출한다
3. PDF 변환 → 이미지 추출로 시각 레이아웃을 확인한다
4. 슬라이드 인벤토리를 작성한다:

| # | 슬라이드 유형 | 제목 | 텍스트 양(자) | 이미지 유무 | 노트 유무 |
|---|-------------|------|-------------|-----------|---------|

5. **강의 노트·기획안·BP를 탐색한다**: 옵시디언 볼트의 강의 폴더에서 해당 강의 노트를 찾아 읽는다.
   - LP_*.md 발견 → 학습 목표·타깃 프로파일·Ch 구성·시간 배분 추출
   - BP_*.md 발견 → 슬라이드 1장 단위 T-유형·제목·핵심 메시지·시각 힌트·증거 추출 (점검 축 0.5 실행 플래그 ON)
   - RL_*.md 발견 → 사례·실습 소재·수치 근거 추출 (선택)
   - 모두 없으면 사용자에게 타깃 정보를 확인한다

### 산출물

대화창에 인벤토리 요약을 제시한다 (파일 생성하지 않음):
- 총 슬라이드 수, 유형별 분포
- 평균 텍스트 양, 이미지 삽입 비율
- 기획안 대비 매핑 여부 (LP 제공 시)
- BP 대비 매핑 여부 (BP 제공 시) — BP 슬라이드 수 vs 실제 슬라이드 수

## Phase 2: 종합 점검 (Comprehensive Review)

7개 점검 축으로 슬라이드를 체계적으로 평가한다. 각 축은 독립적으로 점검하되, 축 간 연관이 있으면 교차 참조한다. 점검 축 0.5는 BP 입력이 있을 때만 실행한다.

### 점검 축 0: 타깃 적합성 (Target Fit)

기획안의 타깃 프로파일을 기준으로, 슬라이드 전체가 대상 청중에게 적합한지 점검한다. 이 축은 다른 모든 축의 판단 기준이 된다.

| 점검 항목 | 기준 |
|----------|------|
| 용어 수준 | 타깃의 경험 수준에 맞는 용어를 사용하는가 (입문자에게 전문 용어 과다 여부) |
| 사전 지식 전제 | 타깃이 모를 수 있는 개념을 설명 없이 전제하고 있지 않은가 |
| 사례·예시 접점 | 타깃의 업무·일상과 연결되는 사례를 사용하는가 |
| 실습 난이도 | 타깃의 도구 숙련도에 맞는 실습 수준인가 |
| 기대 성과 정렬 | 기획안의 학습 목표·기대 성과가 슬라이드에서 도달 가능한가 |

> 타깃 프로파일이 없으면 슬라이드 내용과 강의 제목에서 추정하되, 추정 근거를 명시한다.

### 점검 축 0.5: 블루프린트 반영률 (Blueprint Fidelity)

lecture-blueprint의 BP_*.md가 있으면 슬라이드가 BP를 얼마나 충실히 반영했는지 점검한다. 이 축은 BP 입력이 있을 때만 실행한다.

| 점검 항목 | 기준 |
|----------|------|
| 제목 반영 | BP의 슬라이드 제목이 실제 슬라이드 제목과 일치 (대소문자·어미 허용 범위 내) |
| 핵심 메시지 반영 | BP의 핵심 메시지가 슬라이드 본문에 포함 (유사도 0.7 이상) |
| T-유형 일치 | BP에 지정된 T-유형대로 실제 슬라이드가 조판되었는가 |
| 시각 힌트 반영 | BP의 `[DIAGRAM/CHART/IMG]` 태그가 실제 시각 자료로 구현되었는가 |
| 증거 반영 | BP의 증거·소재가 슬라이드에 실제로 등장하는가 |

**반영률 산출**: 위 5개 항목 × 슬라이드 수 기준. 각 슬라이드마다 5개 중 몇 개가 통과했는지 집계 후 전체 평균.

| 반영률 | 판정 |
|-------|------|
| 90% 이상 | 통과 — BP 충실 구현 |
| 70~89% | 경고 — 주요 슬라이드 일부 편차 |
| 70% 미만 | 실패 — BP 재실행 권장 |

BP가 없으면 이 축은 "해당 없음"으로 표기한다.

### 점검 축 1: 구조 흐름 (Structure Flow)

전체 슬라이드의 논리적 흐름을 점검한다.

| 점검 항목 | 기준 |
|----------|------|
| 도입 → 전개 → 마무리 구조 | 3단 구성이 명확한가 |
| 섹션 전환 | 섹션 구분 슬라이드가 있고, 전환 논리가 자연스러운가 |
| 학습 목표 커버리지 | 기획안의 학습 목표가 슬라이드에 모두 반영되었는가 |
| 반복·누락 | 같은 내용이 중복되거나, 빠진 개념이 있는가 |
| 난이도 곡선 | 쉬운 것에서 어려운 것으로 점진적으로 진행되는가 |

### 점검 축 2: 분량 배분 (Time Balance)

슬라이드 수와 강의 시간의 균형을 점검한다.

| 점검 항목 | 기준 |
|----------|------|
| 전체 분량 | 총 시간 대비 슬라이드 수가 적절한가 (1~2분/장 기준) |
| 모듈별 편차 | 특정 모듈이 과다하거나 빈약하지 않은가 |
| 실습 비율 | 실습 슬라이드 비율이 30~50% 범위에 있는가 |
| 쉬는 시간 | 60분 이상 강의에 쉬는 시간이 반영되었는가 |

### 점검 축 3: 텍스트 품질 (Text Quality)

슬라이드 텍스트의 품질을 점검한다.

| 점검 항목 | 기준 |
|----------|------|
| 1슬라이드 1메시지 | 한 장에 여러 개념이 섞여 있지 않은가 |
| 제목 품질 | 기능명이 아닌 행동·판단 중심 문장인가 |
| 텍스트 양 | 슬라이드당 텍스트가 과다하지 않은가 (키워드·구문 중심) |
| 금지어 | 공통 하네스 금지어 위반이 있는가 |
| 종결어미 | 슬라이드 내 문체가 일관되는가 |

### 점검 축 4: 시각 자료 (Visual Assets)

다이어그램·이미지·레이아웃의 효과성을 점검한다.

| 점검 항목 | 기준 |
|----------|------|
| 다이어그램 배치 | 도식화가 효과적인 슬라이드에 다이어그램이 있는가 |
| 다이어그램 품질 | 노드 수(3~8), 텍스트 길이(20자 이내), 색상 일관성 |
| 플레이스홀더 | 미삽입 이미지(스크린샷·데모)가 식별되어 있는가 |
| 레이아웃 일관성 | 같은 유형의 슬라이드가 같은 레이아웃을 사용하는가 |
| 여백·정렬 | 텍스트·이미지 겹침이나 잘림이 없는가 |

### 점검 축 5: 발표 전환 (Presentation Flow)

강사가 실제 발표할 때의 흐름을 점검한다.

| 점검 항목 | 기준 |
|----------|------|
| 전환 멘트 | 슬라이드 간 전환이 자연스러운가 (발표 노트 기준) |
| 청중 참여 | 질문·실습·체크포인트가 적절히 배치되었는가 |
| 에너지 곡선 | 정보 전달 → 참여 → 정보 → 참여 리듬이 있는가 |
| 시작과 끝 | 도입부 훅과 마무리 메시지가 강력한가 |

## Phase 3: 피드백 리포트 (Feedback Report)

Phase 2 점검 결과를 구조화된 리포트로 정리한다.

### 리포트 구조

```
## 리뷰 요약
- 총점: ★★★★☆ (5점 만점)
- 타깃: [타깃 프로파일 1줄 요약]
- BP 반영률: 92% (BP 있을 때만 표기)
- 강점 2~3개
- 개선 필요 2~3개

## 점검 결과

### 0. 타깃 적합성: ★★★★☆
- [통과/개선] 항목명

### 0.5. 블루프린트 반영률: 92% (BP 있을 때만 표기)
- [통과] 제목 반영 100% / 핵심 메시지 반영 95%
- [개선] S12·S18에서 시각 힌트 누락

### 1. 구조 흐름: ★★★★☆
- [통과] 항목명
- [개선] 항목명 — 구체적 위치와 수정 제안

### 2. 분량 배분: ★★★☆☆
- ...

### 3. 텍스트 품질: ★★★★★
- ...

### 4. 시각 자료: ★★★☆☆
- ...

### 5. 발표 전환: ★★★★☆
- ...

## 수정 작업 목록

| # | 우선순위 | 슬라이드 | 점검 축 | 수정 내용 |
|---|---------|---------|---------|----------|
| 1 | 높음 | S12~S15 | 구조 | Ch2 후반부 순서 재배치 |
| 2 | 높음 | S23 | 텍스트 | 제목을 행동 중심 문장으로 변경 |
| 3 | 보통 | S30 | 시각 | 다이어그램 추가 (프로세스 플로우) |
```

### 우선순위 기준

| 우선순위 | 기준 |
|---------|------|
| 높음 | 학습 목표 누락, 구조적 흐름 깨짐, 텍스트 과다/금지어, BP 반영률 70% 미만 |
| 보통 | 다이어그램 추가 기회, 분량 미세 조정, 레이아웃 개선, BP 반영률 70~89% 편차 슬라이드 |
| 낮음 | 문체 미세 조정, 발표 노트 보완, 장식적 개선 |

### 산출물

리포트는 **대화창 텍스트로 직접 제공**한다. 사용자가 파일을 요청하면 강의 노트에 `## 슬라이드 리뷰` 섹션으로 추가하거나, 별도 `.md` 파일로 저장한다.

## Phase 4: 수정 반영 (Apply Revisions)

사용자가 피드백 리포트를 확인하고 수정을 승인하면 실행한다.

### 수정 프로세스

1. **수정 범위 확인**: 사용자에게 수정 작업 목록을 제시하고, 전체 반영 / 선택 반영 / 보류를 확인한다
2. **pptx 수정**: pptx 스킬을 사용하여 슬라이드를 직접 수정한다
   - 구조 변경 (슬라이드 순서 이동, 추가, 삭제)
   - 텍스트 수정 (제목, 본문, 발표 노트)
   - 다이어그램 추가/수정 (visual-diagram 스킬 연계)
3. **QA 검증**: 수정된 .pptx를 PDF 변환 → 시각 검수
4. **BP 재점검 (BP 있을 때만)**: 수정으로 인해 BP 반영률이 바뀔 수 있으므로 점검 축 0.5 재실행
   - 재점검 후 반영률이 90% 이상으로 상승했는지 확인
   - 70% 미만으로 유지되면 lecture-blueprint 회귀 권장
5. **변경 요약 제시**: 수정 전/후 비교를 슬라이드 번호별로 정리

### 수정 시 원칙

- 원본 분량의 120%를 초과하는 수정은 사전 확인을 받는다
- 구조 변경(슬라이드 추가/삭제/이동)은 반드시 사용자 승인 후 실행한다
- 텍스트 수정(제목·본문 변경)은 승인된 범위 내에서 일괄 처리한다
- 다이어그램 추가는 visual-diagram 가드레일(노드 3~8, 텍스트 20자 이내)을 준수한다
- BP가 있으면 수정 후 반영률 재측정 필수

### 반복 수정

1차 수정 후 사용자가 추가 피드백을 주면 Phase 2~4를 반복한다. 반복 시:
- 이전 리포트의 [통과] 항목은 재점검하지 않는다
- 새로 발생한 이슈와 미해결 이슈만 점검한다
- BP 반영률은 매 수정 후 재측정한다
- 반복 횟수는 제한하지 않되, 3회 이상 반복 시 근본 원인을 진단하여 사용자에게 보고한다

### 자동 제안 로직 (lecture-feedback-audience)

Phase 3 피드백 리포트 출력 시점에 아래 조건 중 하나라도 해당하면 **lecture-feedback-audience 스킬 실행을 자동 제안**한다.

- 강의 시간 60분 초과 (수강생 이탈 위험 구간 존재)
- 실습 비중 40% 이상 (실습 완수 편차 위험)
- 첫 출강 또는 신규 강의 (예상 이탈 지점 사전 파악 필요)
- 사용자가 점검 축 중 "청중·학습자 반응" 관심사를 명시

자동 제안 메시지 포맷:

```
리뷰가 완료되었습니다. 이 강의는 [조건]에 해당합니다.
수강생 페르소나 관점에서 이탈·막힘 지점을 추가로 점검하려면
lecture-feedback-audience 스킬 실행을 권장합니다.
실행하시겠습니까? (y/n)
```

사용자 승인 시 해당 스킬로 제어를 넘긴다. 거부 시 Phase 4 수정 반영으로 진행.

## 하네스 규칙

### 완성 조건

- 7개 점검 축(타깃 적합성 + 블루프린트 반영률 + 5개) 모두 실행 (해당 없음 표기 가능, 생략 금지)
- 수정 작업 목록의 모든 항목에 우선순위·위치·구체 내용 포함
- 금지어 위반 0건 (공통 하네스 적용)
- 수정 반영 후 QA 검증 1회 이상 실행
- BP가 입력되었는데 반영률 70% 미만이면 lecture-blueprint로 회귀 권장
