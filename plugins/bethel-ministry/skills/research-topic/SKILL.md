# 범용 주제 리서치 워크플로우 (Topic Research Workflow)

사용자가 지정한 주제에 대해 온라인 자료를 수집·정리하고, .md 노트 1개로 저장하는 4단계 워크플로우.

## 보조 파일 안내

| 파일 | 용도 | 참조 시점 |
|------|------|-----------|
| `references/output-template.md` | 노트 출력 포맷 템플릿 (기본/딥) | Step 3 (노트 작성) |
| `references/obsidian-guide.md` | 옵시디언 프론트매터·백링크·MOC·폴더 구조 규칙 | Step 4 (노트 저장) |

## 공용 파일 참조

| 파일 | 용도 |
|------|------|
| `writing-principles.md` | 금지어·문체 규칙 (공용) |

## 다른 리서치 스킬과의 차이

| 비교 | research-topic (이 스킬) | lecture-research | book-research |
|------|--------------------------|------------------|---------------|
| 목적 | 범용 주제 참조 노트 | 강의 기획안 기반 리서치 | 책 챕터 집필용 참조 카드 |
| 입력 | 주제 단독 | 강의 기획안(목차 포함) | 책 챕터 맥락 |
| 출력 형태 | 구조화된 장문 노트 (1,500~5,000자) | 목차 꼭지별 슬롯 블록 (RL_ 노트) | 5슬롯 압축 참조 카드 (500~800자) |
| 연결 대상 | 독립 참조 자료, 글쓰기·판단 근거 | lecture-plan → lecture-slides | book-writing-pro Phase 3 |
| 파일명 | `R_주제명.md` | `RL_강의명_YYYYMMDD.md` | 프로젝트 폴더 내 참조 카드 |

**이 스킬은 강의 리서치를 다루지 않는다.** 강의 기획안이 있거나 강의 목적이 명시된 요청은 `lecture-research`로 처리한다.

---

## 전체 흐름

```
Step 1: 주제 확인 → Step 2: 웹 리서치 → Step 3: 내용 정리·구조화 → Step 4: 노트 저장
```

---

## Step 1: 주제 확인

사용자 입력에서 다음을 파악한다.

1. **리서치 주제**: 무엇에 대해 조사할 것인가
2. **리서치 깊이**: 기본(basic) 또는 딥(deep)
   - 사용자가 "딥 리서치", "딥리서치", "깊이 있게", "상세하게" 등을 언급하면 딥 리서치
   - 별도 언급이 없으면 기본 리서치
3. **관점/초점**: 특정 관점이나 용도가 있는지 (예: "비교 분석", "시장 동향")
4. **파일명**: 사용자가 지정하면 그대로 사용. 미지정 시 `R_주제명.md` 형식으로 자동 생성

사용자가 주제만 짧게 던진 경우(예: "클로드 스킬 리서치해줘"), 추가 질문 없이 기본 리서치로 바로 진행한다. 모호한 경우에만 간단히 확인한다.

### 강의 리서치 요청 감지

사용자가 다음 중 하나를 언급하면 **이 스킬 대신 `lecture-research`를 사용하도록 안내**한다.

- "강의용", "강의 준비", "수업 자료", "교안용", "슬라이드용"
- "강의 리서치", "강의 자료 조사", "커리큘럼에 쓸"
- 강의 기획안·목차가 이미 있는 상황

안내 예시: "강의 목적 리서치는 `lecture-research` 스킬을 사용하면 강의 기획안 기반으로 목차 꼭지별 슬롯형 노트를 만들 수 있습니다. 그쪽으로 진행할까요?"

### 필수 입력 강제 규칙

**리서치 주제**가 확인되지 않으면 Step 2로 넘어가지 않는다. 추측으로 주제를 설정하지 않고 사용자에게 질문한다.
- 주제가 너무 넓은 경우(예: "AI 리서치해줘") → "어떤 측면을 조사할까요? (도구 비교 / 시장 동향 / 기술 원리 등)"
- 주제와 관점이 모두 불명확한 경우에만 질문한다. 주제가 명확하면 바로 진행한다.

## Step 2: 웹 리서치

### 기본 리서치 (basic)
- `web_search`로 3~5개 검색 쿼리 실행
- 상위 결과에서 신뢰할 수 있는 소스 3~5개 선정
- `web_fetch`로 핵심 페이지 2~3개 내용 수집

### 딥 리서치 (deep)
- `web_search`로 5~10개 검색 쿼리 실행 (영문+한글 혼합)
- 소스 10개 이상 수집
- 다각도 분석: 기술 원리, 활용 사례, 시장 동향, 경쟁 비교, 전문가 의견
- `web_fetch`로 주요 페이지 5~8개 상세 수집

### 검색 전략
- 한글 검색과 영문 검색을 병행한다
- 공식 문서, 기술 블로그, 뉴스 기사, 커뮤니티 토론 등 다양한 소스 유형을 포함한다
- 최신성을 확인한다 (날짜 기반 필터링)
- 1차 소스(공식 발표, 문서)를 우선한다

### 소스 평가 기준
- 공식 문서/발표 > 전문 매체/기술 블로그 > 일반 뉴스 > 커뮤니티 토론
- 날짜가 명시된 소스를 우선한다
- 복수 소스에서 교차 확인된 정보를 우선한다

### 수집 결과 검증
- 수집된 소스가 기준 수(basic: 3개, deep: 10개)에 미달하면 검색 쿼리를 변경하여 추가 검색한다
- 수집된 내용이 주제와 무관한 결과가 다수이면, 검색어를 구체화하여 재검색한다

## Step 3: 내용 정리·구조화

수집된 자료를 `references/output-template.md`의 포맷에 따라 구조화한다.

### 작성 원칙

1. **사실 중심**: 의견이 아닌 사실과 데이터를 중심으로 정리
2. **출처 명시**: 모든 핵심 주장에 출처를 병기
3. **구조화**: 섹션별로 명확히 구분, 후속 활용(글쓰기, 판단 근거)에 편리하게
4. **금지어·문체**: 공용 `writing-principles.md`의 규칙을 따른다
5. **문장**: 설명 중심, 능동형, 간결하게

### 출력 슬롯 템플릿 (노트는 반드시 이 구조를 따른다)

```
[YAML 프론트매터] ← title, date, tags, status, folder, research_depth, sources_count
[개요] ← 주제 정의 + 조사 범위 (2~3문장)
[핵심 내용] ← 주제별 구조화된 본문 (소제목 활용)
[주요 수치·데이터] ← 출처 포함 정량 데이터
[시사점] ← 후속 활용 방향 (2~3문장)
[출처 목록] ← URL + 접근일
```

### 문장 품질 기준 (GOOD/BAD 예시)

| BAD (금지) | GOOD (기준) |
|-----------|------------|
| 이 도구는 매우 혁신적인 기능을 제공한다 | 이 도구는 1회 입력으로 텍스트·이미지·코드 3종을 동시에 생성한다 |
| 시장이 빠르게 성장하고 있다 | 시장 규모가 2024년 12억 달러에서 2025년 28억 달러로 증가했다 (출처, 2025) |
| 다양한 분야에서 활용 가능성이 높다 | 교육, 마케팅, 법률 문서 작성 3개 분야에서 도입 사례가 보고되었다 |

### Harness 블록

이 스킬의 하네스 파라미터는 다음과 같다.

| 항목 | 값 |
|------|-----|
| **원문 보존 레벨** | L2 (균형형) — 출처 원문 직접 인용 시 큰따옴표 + 출처, 나머지는 재구성 |
| **생성-평가 분리** | 노트 작성 → 자가 평가 루프 → 필요 시 재생성 |
| **분량 가드레일** | 기본 1,500~2,500자 / 딥 3,000~5,000자 (초과 시 압축) |
| **재생성 트리거** | 자가 평가 항목 중 1개 이상 실패 시 해당 섹션만 재작성 |

### 자가 평가 루프 (출력 전 반드시 실행)

노트 작성 완료 후, 아래 항목을 **순서대로** 확인한다. 실패 항목이 있으면 해당 섹션을 재작성한 뒤 다시 점검한다.

**1. AI 흔적 점검**
- [ ] "혁신적인", "획기적인", "완벽한" 등 과장형 형용사 포함 여부
- [ ] "~할 수 있다" 추측 표현 포함 여부
- [ ] "매우", "쉽게", "빠르게" 등 모호한 부사 포함 여부

**2. 사실·출처 점검**
- [ ] 출처 없이 수치·통계를 기술한 곳이 있는가
- [ ] 동일 사실이 복수 소스에서 교차 확인되었는가 (딥 리서치 한정)
- [ ] 1년 이상 지난 소스를 최신 정보로 기술하지 않았는가

**3. 구조 점검**
- [ ] 슬롯 구조를 따랐는가 (YAML, 개요, 핵심 내용, 수치, 시사점, 출처 순서)
- [ ] YAML 프론트매터가 빠짐없이 포함되었는가
- [ ] 분량 가드레일 범위 내에 있는가

### 분량 기준
- 기본 리서치: 1,500~2,500자
- 딥 리서치: 3,000~5,000자

## Step 4: 노트 저장

### 저장 폴더 선택

노트를 저장하기 전에 사용자에게 저장 폴더를 확인한다.

| 추천 폴더 | 용도 |
|-----------|------|
| `50 주요 기술 자료(참조)` | 범용 기술 참조 노트 (기본 추천) |
| `책 프로젝트명/참조` | 특정 책 집필 프로젝트의 참조 자료 |
| 사용자 지정 폴더 | 직접 입력 |

- 배치 처리(여러 주제)일 때는 첫 번째 주제에서만 폴더를 물어보고, 나머지는 동일 폴더에 저장
- 사용자가 폴더 선택을 생략하면 기본 추천 폴더로 진행

### 파일명 규칙
- 사용자 지정이 없으면: `R_주제명.md`
- 주제명은 한글로, 공백 포함 가능, 30자 이내
- 동일 파일명이 존재하는 경우: `R_주제명_2.md` 형식으로 번호를 추가한다

**주의**: `RL_` 접두어는 이 스킬에서 사용하지 않는다. `RL_`은 `lecture-research` 전용이다.

### YAML 프론트매터

모든 노트에 반드시 포함:

```yaml
---
title: "주제명"
date: YYYY-MM-DD
tags: [research, 주제태그1, 주제태그2]
status: done
folder: "저장 폴더명"
research_depth: basic | deep
sources_count: N
---
```

### 옵시디언 연동

.md 산출물 저장 시 `references/obsidian-guide.md`의 규칙을 적용한다.
- YAML 프론트매터: 위 공통 필드 포함
- 폴더·MOC: 파일 저장 요청 시 MOC 갱신

### 저장 후 안내
- `present_files` 도구로 파일을 사용자에게 제공
- 노트 요약 (3줄 이내)
- 수집한 소스 수와 리서치 깊이 표시
- 후속 활용 안내: "이 노트는 write-content, write-blog, book-writing 등에서 참조 자료로 활용할 수 있다"

## 배치 처리

사용자가 여러 주제를 한 번에 요청할 경우:
1. 주제 목록을 먼저 확인
2. 첫 주제에서 저장 폴더를 확인, 이후 동일 폴더 적용
3. 주제별로 순차 처리 (각 주제당 Step 2~4 반복)
4. 전체 완료 후 생성된 노트 목록을 요약 제공

## 다음 스킬 연계

| 후속 작업 | 연계 스킬 | 연계 방식 |
|----------|----------|----------|
| 일반 글쓰기 | write-content | 핵심 내용 → 아티클·칼럼 소재 |
| 블로그 글쓰기 | write-blog | 핵심 내용 → 블로그 포스트 재료 |
| 브런치 글쓰기 | write-brunch | 핵심 내용 → 브런치 에세이 재료 |
| 책 집필 | book-writing | 핵심 내용 → 챕터 참조 자료 (챕터 단위 리서치는 book-research 사용) |
| 리서치 보고서 | research-report | 핵심 내용 → 5섹션 납품형 보고서 |

**강의 관련 연계는 이 스킬에서 처리하지 않는다.** 강의 리서치가 필요하면 `lecture-research`를 직접 호출한다.

## 사용 예시

**기본 리서치 요청:**
> "클로드 스킬 리서치해줘"
→ 기본 리서치 → 폴더 확인 → `R_클로드 스킬.md` 생성

**딥 리서치 요청:**
> "코워크 기반 글쓰기 딥리서치해줘"
→ 딥 리서치 → 폴더 확인 → `R_코워크 기반 글쓰기.md` 생성

**복수 주제:**
> "클로드 스킬, 코워크 글쓰기, AI 업무보고서 각각 리서치해줘"
→ 폴더 1회 확인 → 3개 노트 순차 생성

**강의 리서치 요청이 들어온 경우:**
> "AI 이미지 생성 도구 비교 강의용으로 리서치해줘"
→ "강의 목적 리서치는 `lecture-research` 스킬이 강의 기획안 기반 슬롯형 노트를 생성합니다. 그쪽으로 진행할까요?"로 안내
