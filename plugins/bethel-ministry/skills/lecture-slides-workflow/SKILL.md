# 강의 슬라이드 워크플로우 (Lecture Slides Workflow)

강의 설계부터 슬라이드 생성, 발표 자료까지 아우르는 5단계 프로세스.

## 전체 흐름

```
Phase 1: 강의 기획 → Phase 2: 커리큘럼 설계 → Phase 3: 슬라이드 구조화 → Phase 4: .pptx 생성 → Phase 5: 발표 노트 + 핸드아웃
```

사용자 상태에 따라 적절한 단계부터 시작한다.
- 주제만 있음 → Phase 1부터
- 커리큘럼/목차 있음 → Phase 3부터
- 기존 슬라이드 수정 → Phase 4에서 pptx 스킬로 직접 편집

### 패스트트랙 (Phase 1~3 통합 처리)

사용자가 주제·대상·시간을 한 번에 제공하면 Phase 1~3을 **하나의 턴**에서 통합 처리한다.

- Phase 1 산출물(강의 개요, 학습 성과)을 간략히 정리
- Phase 2 산출물(시간표, 모듈 구성)을 이어서 설계
- Phase 3 산출물(슬라이드 목록)까지 한 번에 제시
- **색상**: 주제에 맞는 추천 색상을 자동 적용하고, 결과 제시 시 "악센트 색: OOO 적용. 변경을 원하시면 말씀해 주세요." 한 줄 안내
- 사용자 확인 후 바로 Phase 4로 진입

패스트트랙 판단 기준: 주제·대상·시간 3가지가 모두 명시된 경우 자동 적용.
목표·환경이 빠져 있으면 합리적으로 추정하되, 추정 내용을 명시한다.

## 보조 참조 파일

이 스킬은 상세 내용을 보조 파일로 분리한다. 해당 단계 작업 시 반드시 먼저 읽는다.

| 파일 | 용도 | 읽는 시점 |
|------|------|----------|
| `references/template-spec.md` | 템플릿 디자인 사양 (크기, 색상, 폰트, 좌표) | Phase 4 시작 전 |
| `references/slide-types.md` | 슬라이드 유형별 레이아웃 상세 | Phase 3~4 |
| `references/curriculum-guide.md` | 커리큘럼 설계 가이드 + 시간별 구성 | Phase 2 |

## 공통 원칙

### 슬라이드 서술 원칙
- 슬라이드 제목은 기능명이 아닌 **행동·판단 중심 문장**으로 작성
  - ❌ "레이어 기능" → ✅ "레이어로 구조를 분리하는 기준"
- 각 섹션의 첫 슬라이드: **"왜 이걸 배워야 하는가"**를 전달
- 정보 나열 금지 → **개념 → 기준 → 적용** 순서로 전개
- 슬라이드 1장 = 1메시지 원칙
- 텍스트 최소화: 핵심 키워드와 시각 요소 중심

### 금지 요소
- 기능 목록만 나열하는 슬라이드
- 문장 전체를 슬라이드에 그대로 옮기는 구성
- 결과물에 대한 감상형 캡션
- 내용 없이 화려하기만 한 장식 슬라이드

## Phase 1: 강의 기획 (Lecture Planning)

사용자에게 다음 정보를 수집한다.

| 항목 | 질문 | 예시 |
|------|------|------|
| **주제** | 무엇을 가르치는가? | AI 이미지 생성, 프롬프트 설계 |
| **대상** | 누가 듣는가? 현재 수준은? | 입문자, 실무 마케터, 대학생 |
| **시간** | 총 강의 시간은? | 2시간, 반일(4시간), 1일(6시간) |
| **목표** | 수강 후 무엇을 할 수 있어야 하는가? | 독립적으로 프롬프트 설계 가능 |
| **환경** | 실습 가능 여부, 온/오프라인 | 노트북 지참, Zoom 온라인 |

### 산출물

- 강의 기획 내용은 **대화창 텍스트로 직접 제공**한다 (파일 생성하지 않음)
- 사용자가 파일을 명시적으로 요청하거나 확정 후 파일화를 원하면 `01-lecture-plan.docx`로 저장한다

다음 항목을 포함:
- 강의 개요 (주제, 대상, 시간, 목표)
- 수강 전 필요 조건 (사전 지식, 준비물)
- 기대 학습 성과 (Learning Outcomes) 3~5개
- 강의 형식 (강의/실습/워크숍 비율)

## Phase 2: 커리큘럼 설계 (Curriculum Design)

Phase 1을 기반으로 시간 단위 커리큘럼을 설계한다.

**→ 상세 설계 원칙과 시간별 구성 가이드는 `references/curriculum-guide.md`를 읽는다.**

### 설계 핵심

- 전체 흐름: **이해 → 설계 → 실행 → 확장**을 기본 골격으로
- 각 모듈: **"왜 필요한가"로 시작 → 개념 → 실습/적용 → 정리** 구조
- 실습 비율: 전체의 30~50% 권장
- 모듈당 20~40분 단위 (집중력 한계 고려)
- 모듈 사이 휴식·전환 시간 포함

### 산출물: `02-curriculum.docx`

다음 항목을 포함:
- 시간표 (모듈별 시작/종료 시간, 주제, 형식)
- 모듈별 상세: 목표, 핵심 내용, 실습 과제, 필요 자료
- 모듈 간 연결 논리

## Phase 3: 슬라이드 구조화 (Slide Structure)

커리큘럼의 각 모듈을 슬라이드 단위로 분해한다.

**→ 슬라이드 유형별 상세 레이아웃은 `references/slide-types.md`를 읽는다.**

### 슬라이드 유형 요약

| 유형 | 용도 | 핵심 구성 |
|------|------|----------|
| **타이틀** | 강의 시작 | 제목 + 부제 + 강사 정보 + 일러스트 |
| **섹션 구분** | 모듈 전환 | 원형 번호 + 섹션 제목 |
| **콘텐츠** | 핵심 내용 전달 | 번호 제목(판단 중심) + 일러스트 |
| **비교/대조** | 차이점 설명 | 제목 + 2분할 일러스트 |
| **프로세스** | 단계별 흐름 | 제목 + 카드×화살표 레이아웃 |
| **실습 안내** | 참여 유도 | 연한 배경 + 과제/조건/시간/힌트 카드 |
| **체크포인트** | 이해도 확인 | 질문 + 선택지 카드 (정답 악센트 테두리) |
| **다컬럼 정보** | 병렬 비교/로드맵 | 2~4컬럼 카드 + 항목 + 목표 |
| **요약/정리** | 섹션 마무리 | 핵심 포인트 + 일러스트 |
| **Q&A** | 질의응답 | 최소 텍스트, 질문 유도 문구 |

### 모듈별 슬라이드 배분 기준

| 모듈 시간 | 슬라이드 수 | 구성 |
|----------|------------|------|
| 20분 | 8~12장 | 섹션구분 1 + 콘텐츠 4~6 + 예시 2 + 정리 1 |
| 30분 | 12~16장 | 섹션구분 1 + 콘텐츠 5~8 + 예시 3 + 실습 1 + 정리 1 |
| 40분 | 16~22장 | 섹션구분 1 + 콘텐츠 7~10 + 예시 3~4 + 실습 2 + 정리 1 |

실습 모듈은 슬라이드 수가 적고 (5~8장), 실습 안내와 체크포인트 중심으로 구성한다.

### 산출물: `03-slide-structure.docx`

다음 항목을 포함:
- 모듈별 슬라이드 목록 (번호, 유형, 제목, 핵심 내용 1줄)
- 총 슬라이드 수 요약
- 슬라이드 간 전환 논리 메모

## Phase 4: .pptx 생성 (Slide Production)

Phase 3의 구조를 기반으로 실제 슬라이드를 생성한다.

### 생성 전 필수 사항

1. **반드시 `references/template-spec.md`를 먼저 읽는다** — 슬라이드 크기, 색상, 폰트, 좌표 사양
2. **반드시 `/mnt/skills/public/pptx/SKILL.md`를 먼저 읽는다** — pptx 생성 기술 가이드, QA 절차
3. **반드시 `references/slide-types.md`를 읽는다** — 유형별 레이아웃 상세

### 강의 슬라이드 디자인 원칙

- **1슬라이드 = 1메시지**: 한 장에 여러 개념을 넣지 않음
- **텍스트 최소화**: 문장이 아닌 키워드·구문 중심 (발표 노트에 상세 설명)
- **일러스트 중심 구성**: 콘텐츠 슬라이드는 제목 + 대형 일러스트 이미지로 구성
- **일관된 레이아웃 패턴**: 같은 유형의 슬라이드는 같은 레이아웃
- **섹션별 번호 체계**: 섹션 구분 슬라이드에 원형 번호, 콘텐츠 슬라이드에 ①②③ 번호 접두사

### 색상 커스터마이징

- **패스트트랙 경로**: 주제에 맞는 추천 색상이 이미 적용된 상태. 사용자가 변경을 요청하면 반영
- **일반 경로 (Phase 1~3 개별 진행)**: Phase 4 시작 시 "악센트 색을 변경하시겠습니까? (현재: #F27100 주황)" 확인
- 사용자가 색상을 직접 지정하면 그 값을 우선 적용
- 주제별 추천 색상표는 `references/template-spec.md` 섹션 7 참조

### 이미지 처리

- 사용자가 일러스트 이미지를 제공하면 해당 이미지를 슬라이드에 배치
- 이미지 배치: 슬라이드 면적의 60~70%를 차지하도록 하단 중앙에 배치

**이미지 미제공 시 (플레이스홀더 모드):**
- 이미지 자리를 회색 플레이스홀더(#F0F0F0, 점선 테두리)로 표시
- 각 슬라이드의 발표 노트에 `[IMAGE: 설명]` 태그로 이미지 설명을 기록
- Phase 4 완료 시, 슬라이드별 이미지 설명 목록을 `04-image-list.md`로 별도 생성

```
[IMAGE: 설명] 태그 형식:
[IMAGE: Before(서류 더미에 파묻힌 현장소장) vs After(AI로 문서 정리하는 현장소장)]
[IMAGE: 검색엔진(돋보기+서버) vs 생성형 AI(로봇+문서) 비교 도식]
```

> 이후 일러스트 조달 워크플로우가 연결될 때, `04-image-list.md`에서 이미지 설명을 뽑아 사용한다.

### Speaker Notes 삽입

.pptx 생성 시 각 슬라이드에 발표 노트를 함께 삽입한다 (`slide.addNotes()`).
노트 작성 규칙은 `references/template-spec.md` 섹션 8에 정의되어 있다.

### QA

pptx 스킬의 QA 절차를 반드시 따른다:
1. `markitdown`으로 콘텐츠 확인
2. PDF 변환 → 이미지 추출 → 시각 검수
3. 수정 → 재검증 반복

### 산출물: `04-slides.pptx`

## Phase 5: 발표 노트 + 핸드아웃 (Supporting Materials)

### 발표 노트 (Speaker Notes)

**기본: .pptx 내부 노트로 완결.** Phase 4에서 `slide.addNotes()`로 이미 삽입되어 있다.

**별도 `05-speaker-notes.docx` 생성 기준:**
- 사용자가 명시적으로 요청한 경우
- 노트 분량이 슬라이드당 평균 400자를 초과하는 경우 (상세 스크립트)
- 강의를 다른 강사에게 인수인계하는 경우

별도 docx 생성 시 포함 내용:
- 슬라이드 번호와 제목 매칭
- 각 슬라이드에서 **무엇을 말할지** + **왜 이 순서인지** + **전환 멘트**
- 실습 슬라이드: 진행 안내, 시간 관리 팁, 예상 질문과 답변

### 핸드아웃 (수강생 배포용, 선택)

사용자가 요청할 때만 생성한다.
- 모듈별 핵심 포인트 정리
- 실습 과제 및 체크리스트
- 추가 학습 자료 링크
- 용어 정리 (해당 시)

### 산출물

| 파일 | 조건 |
|------|------|
| `05-speaker-notes.docx` | 요청 시 또는 노트 400자/슬라이드 초과 시 |
| `05-handout.docx` | 요청 시 |
