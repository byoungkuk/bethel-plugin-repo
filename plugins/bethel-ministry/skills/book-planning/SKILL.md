# 책쓰기 기획 워크플로우 (Book Planning Workflow)

집필 전 단계 전문. "쓰기 전에 설계하는" 5단계 프로세스.

## 전체 흐름

```
Phase 1: 콘셉트 정의 → Phase 2: 독자·시장 분석 → Phase 3: 목차 설계 → Phase 4: 챕터별 개요 → Phase 5: 출판 기획서
```

사용자의 현재 상태를 파악해 적절한 단계부터 시작한다.
- 아이디어만 있음 → Phase 1부터
- 주제·방향 확정됨 → Phase 2부터
- 독자·시장 분석 완료 → Phase 3부터
- 목차 초안 있음 → Phase 4부터
- 전체 구조 확정, 문서화만 필요 → Phase 5부터

각 Phase 결과물은 대화창 텍스트로 제공한다. Phase 5 출판 기획서 최종본만 .docx로 생성한다.

---

## 문체 기준

이 스킬은 기획 문서를 생성한다. 책 본문 집필 스타일(홍작가 스타일)은 적용하지 않는다.

기획 문서 문체:
- 간결하고 명확한 서술. 한 문장에 하나의 정보
- 설득·논증형 톤. 기획서를 읽는 사람(출판사 편집자, 공저자, 본인)이 판단할 수 있는 근거를 제시한다
- 과장형 형용사, 모호한 부사, 추측 표현 사용 금지
- Phase 1~4 산출물은 실무 메모 톤, Phase 5 출판 기획서는 용도에 맞는 공식 톤

## Phase 1: 콘셉트 정의

**목표:** "이 책이 왜 필요한가"를 한 문장으로 정리한다.

### 입력 수집

사용자에게 아래 정보를 확인한다. 이미 대화에 포함된 내용은 재질문하지 않는다.

1. **주제/아이디어**: 어떤 책을 쓰려고 하는가
2. **집필 동기**: 왜 이 책을 쓰려고 하는가 (개인 경험, 시장 필요, 전문성 등)
3. **기존 유사서와의 차별점**: 이미 나와 있는 책과 무엇이 다른가
4. **저자의 강점**: 이 주제에 대한 저자의 고유한 경험·관점·자격

### 콘셉트 후보 설계

입력을 바탕으로 콘셉트 후보 2~3안을 만든다. 각 안은 같은 주제를 다른 각도에서 잡는다.

**콘셉트 한 문장 구조:**

```
[독자의 문제/상태] + [이 책이 제공하는 기준/관점] + [읽은 뒤 독자의 변화]
```

**후보 제시 양식:**

```
[안 1] 관점: ○○ 중심
콘셉트: (한 문장)
강점: 이 방향이 유리한 이유
약점: 이 방향의 한계

[안 2] 관점: △△ 중심
콘셉트: (한 문장)
강점: ...
약점: ...

[안 3] 관점: □□ 중심
콘셉트: (한 문장)
강점: ...
약점: ...
```

사용자가 하나를 선택하거나, 조합을 요청하면 최종 콘셉트를 확정한다.

### 콘셉트 확장

선택된 콘셉트를 3~5문장으로 확장한다:
- 이 책이 다루는 핵심 질문
- 기존 접근과 다른 관점
- 저자만이 쓸 수 있는 이유

### Phase 1 완료 기준
- 콘셉트 후보 2~3안이 제시되었다
- 사용자가 하나를 선택(또는 조합)하고 최종 콘셉트를 승인했다
- 최종 콘셉트 한 문장이 "누구에게, 무엇을, 왜"를 모두 포함한다

## Phase 2: 독자·시장 분석

**목표:** 이 책의 독자가 누구인지, 어떤 상태에서 이 책을 집어 드는지, 읽고 나서 무엇을 얻는지를 구체화한다.

### 2-1. 독자 프로필

아래 항목을 구조화한다:

| 항목 | 내용 |
|------|------|
| 핵심 독자 | 이 책을 가장 먼저 사는 사람 (직업·역할·상태) |
| 확장 독자 | 핵심 독자 주변에서 관심을 가질 수 있는 층 |
| 독자의 현재 상태 | 지금 어떤 문제를 겪고 있는가, 어떤 시도를 했는가 |
| 독자의 기대 | 이 책에서 무엇을 얻으려 하는가 |
| 읽은 뒤 변화 | 이 책을 읽고 나면 무엇이 달라지는가 |

### 2-2. 시장 분석

| 항목 | 내용 |
|------|------|
| 카테고리 | 서점 기준 분류 (예: 자기계발 > AI활용) |
| 유사서 3~5권 | 제목, 저자, 핵심 내용, 한계점 |
| 차별화 포인트 | 유사서와 비교한 이 책만의 고유 가치 |
| 시장 타이밍 | 지금 이 책이 나와야 하는 이유 |

### 유사서 조사 방법

사용자가 유사서를 이미 알고 있으면 그 정보를 활용한다. 유사서를 모르거나 부족한 경우:

1. **웹 검색 활용**: 주제 키워드 + 카테고리로 온라인 서점(교보문고, YES24, 알라딘)을 검색한다. 사용자에게 "유사서를 웹 검색으로 조사하겠습니다"라고 안내한 뒤 진행한다.
2. **카테고리 탐색**: 유사서가 명확하지 않으면, 해당 주제가 속할 서점 카테고리의 베스트셀러·신간을 조사해 후보를 추린다.
3. **인접 카테고리 확장**: 직접 유사서가 없는 신규 주제라면, 인접 카테고리에서 독자층이 겹치는 책을 대안으로 분석한다.

### Phase 2 완료 기준
- 핵심 독자가 구체적 인물상으로 설명된다 (직업·역할 수준)
- 유사서 대비 차별점이 한 문장으로 정리된다
- 사용자가 독자·시장 분석을 확인·승인한다

## Phase 3: 목차 설계

**목표:** 전체 흐름(도입→전개→심화→마무리)과 챕터별 핵심 메시지를 설계한다.

### 3-1. 전체 구조 설계

책의 흐름을 4단계로 나눈다:

| 단계 | 역할 | 챕터 수 (가이드) |
|------|------|------------------|
| 도입부 | 독자의 문제를 정의하고 이 책의 관점을 선언한다 | 1~2장 |
| 전개부 | 핵심 개념·방법론·기준을 순서대로 제시한다 | 3~5장 |
| 심화부 | 실제 적용 사례, 응용, 확장을 다룬다 | 2~3장 |
| 마무리 | 관점을 재정렬하고 독자의 다음 단계를 제시한다 | 1장 |

총 챕터 수는 책의 성격에 따라 조정한다. 실용서 기준 8~12장이 표준이나, 사용자 의도에 따른다.

### 3-2. 챕터별 핵심 메시지

각 챕터에 대해:

```
Ch [번호]: [챕터 제목]
- 핵심 메시지: 이 챕터에서 독자가 얻는 한 가지 핵심 (1문장)
- 전체 흐름에서의 역할: 앞 챕터와의 연결, 다음 챕터로의 전환
```

### 3-3. 독자 관점 검증

목차 설계 후, Phase 2에서 정의한 핵심 독자의 시선으로 목차를 검증한다.

**검증 방법:** 핵심 독자가 Ch 1부터 순서대로 읽는다고 가정하고, 챕터 간 연결을 점검한다.

```
Ch 1을 읽은 독자의 상태: "○○을 알게 되었다 / ○○이 궁금해졌다"
→ Ch 2로 넘어갈 동기가 있는가? [있다/없다 + 이유]

Ch 2를 읽은 독자의 상태: "..."
→ Ch 3로 넘어갈 동기가 있는가?

... (마지막 챕터까지)

마지막 챕터를 읽은 독자의 상태: "..."
→ Phase 1 콘셉트에서 약속한 변화와 일치하는가? [일치/불일치 + 이유]
```

검증 결과 끊기는 지점이 있으면, 챕터 순서 변경·추가·삭제를 제안한다.

### 3-4. 구조 점검 기준

독자 관점 검증과 별도로, 목차의 구조적 완성도를 점검한다:
1. **메시지 중복**: 서로 다른 챕터가 같은 내용을 반복하지 않는가
2. **균형**: 특정 챕터에 내용이 과도하게 집중되지 않는가
3. **완결성**: 도입에서 제기한 문제가 마무리에서 해소되는가

### Phase 3 완료 기준
- 전체 흐름(4단계)이 설계되었다
- 각 챕터의 핵심 메시지가 1문장으로 정리되었다
- 독자 관점 검증을 통과했다 (끊기는 지점 없음, 또는 수정 완료)
- 구조 점검 3항목을 통과한다
- 사용자가 목차를 확인·승인한다

## Phase 4: 챕터별 개요

**목표:** 각 챕터의 논점·구성·예상 분량·주요 소재를 구체화한다. 실제 집필의 설계도 역할.

### 챕터 개요 양식

각 챕터에 대해 아래 구조로 작성한다:

```
## Ch [번호]: [챕터 제목]

**핵심 논점:** 이 챕터가 답하는 질문 (1문장)

**도입 전략:** 어떤 장면·질문·사례로 시작하는가

**소제목 구성:**
  1. [소제목 1] — 다루는 내용 요약 (1~2문장)
  2. [소제목 2] — 다루는 내용 요약
  3. [소제목 3] — 다루는 내용 요약

**핵심 소재:** 이 챕터에서 사용할 사례·데이터·경험·인용 (있으면)

**마무리 전략:** 어떤 관점 전환 또는 다음 챕터로의 연결로 마무리하는가

**예상 분량:** 원고지 기준 매수 또는 A4 페이지 수
```

### 작성 원칙

- 소제목은 3~5개를 기본으로 한다. 챕터 성격에 따라 조정 가능
- 소제목명은 기능·현상이 아닌 **판단·행동 중심 문장**으로 작성한다
  - ❌ "AI 도구의 종류" → ✅ "도구 선택 기준이 결과를 결정한다"
- 핵심 소재는 저자의 경험·사례를 우선 배치한다. 사용자가 제공한 소재가 없으면 [소재 필요]로 표시한다
- 예상 분량은 정밀하지 않아도 된다. 상대적 비중(짧은/표준/긴)으로 표시해도 된다

### Phase 4 완료 기준
- 모든 챕터의 개요가 위 양식으로 작성되었다
- 소제목이 판단·행동 중심으로 작성되었다
- 사용자가 챕터별 개요를 확인·승인한다

## Phase 5: 출판 기획서

**목표:** Phase 1~4의 결과를 하나의 문서로 종합한다. 출판사 제안용, 자가출판 계획용, 내부 검토용 등 용도에 맞게 톤을 조정한다.

### 용도 확인

사용자에게 기획서 용도를 확인한다:
- **출판사 제안용**: 출판사 편집자가 검토하는 공식 문서. 시장성·차별점·저자 역량 강조
- **자가출판 계획용**: 저자 본인의 집필 로드맵. 일정·분량·작업 계획 중심
- **내부 검토용**: 공저·기획팀과 공유하는 내부 문서. 구조·역할 분담 중심

### 출판 기획서 구성

> **템플릿 참조:** 이 스킬 폴더 내 `publishing-proposal-template.md`를 읽고 적용한다.

기획서는 아래 섹션으로 구성한다:

1. **제목·부제** — 가제 포함 2~3안 제시
2. **저자 소개** — 이 주제에 대한 자격·경험 중심 (약력이 아닌 "왜 이 사람이 쓰는가")
3. **기획 의도** — Phase 1 콘셉트를 확장. "왜 지금 이 책이 필요한가" (300~500자)
4. **독자 대상** — Phase 2 독자 프로필 요약
5. **시장 분석** — Phase 2 유사서·차별점 요약
6. **목차** — Phase 3 목차 전문
7. **챕터별 개요 요약** — Phase 4에서 핵심 논점·소제목만 추출한 압축본
8. **예상 사양** — 총 분량(원고지/페이지), 예상 집필 기간, 판형, 특이사항
9. **마케팅 포인트** (출판사 제안용만 해당) — 타깃 채널, 저자의 기존 플랫폼·독자층, 홍보 가능 자산

### 출력 규칙

- 초안은 대화창 텍스트로 제공한다
- 사용자 확인 후 최종본을 .docx로 생성한다
- .docx 생성 시 docx 스킬(SKILL.md at /mnt/skills/public/docx/SKILL.md)을 참조한다

### Phase 5 완료 기준
- 용도에 맞는 기획서가 작성되었다
- Phase 1~4 결과가 빠짐없이 반영되었다
- 제목안이 2~3개 제시되었다
- 사용자가 최종 기획서를 확인·승인한다

- 기본 집필 → `book-writing` (6단계 집필 프로세스)
- 경험 주입 집필 → `book-writing-pro` (7단계 + 작가 관점·경험 뱅크)

기획서의 목차와 챕터별 개요를 집필 스킬의 Phase 2~3 입력 자료로 바로 활용할 수 있다고 안내한다.

---

## 단계 간 이동 규칙

- 각 Phase는 사용자 승인 후 다음 Phase로 진행한다
- 이전 Phase로 돌아가 수정하는 것은 언제든 가능하다. 수정 시 이후 Phase에 영향이 있으면 변경 사항을 안내한다
- 사용자가 이미 준비한 자료(기존 목차, 독자 분석 등)가 있으면 해당 Phase를 건너뛴다

---

## 압축 모드

사용자가 "바로 기획서 만들어줘", "기획서 한 번에" 등 최종 산출물만 요청하면 압축 모드로 실행한다.

### 압축 모드 프로세스

Phase 1~4를 내부에서 순차 실행하되, 사용자에게는 핵심 결정 포인트만 확인한다.

**최소 확인 항목 (사용자 입력 필수):**
1. 주제와 집필 동기 (Phase 1 입력)
2. 콘셉트 방향 선택 — 후보 2~3안 제시 후 선택 요청 (Phase 1 산출)
3. 기획서 용도 — 출판사 제안용 / 자가출판 / 내부 검토 (Phase 5 입력)

**내부 처리 (사용자 확인 없이 진행):**
- 독자 프로필, 시장 분석, 목차 설계, 챕터별 개요는 콘셉트를 기반으로 자동 생성한다
- 독자 관점 검증(Phase 3-3)은 내부에서 실행하되, 결과를 기획서에 반영한다

**압축 모드 산출물:**
- Phase 5 출판 기획서 전문을 대화창 텍스트로 제공한다
- 기획서 앞에 "콘셉트 → 독자 → 목차" 요약(10줄 이내)을 붙여 전체 기획 과정을 보여준다
- 사용자가 특정 Phase를 수정하고 싶으면 해당 Phase로 전환한다
