# 인제스트 패턴 (ingest-patterns)

소스 연결 3방식, 단일·배치 인제스트 절차, MOC 갱신·교차링크 규칙, 코워크(Cowork) 지시문 예시입니다. 소스 연결 3방식은 wiki-activate의 reuse-pipelines와 동일 규약을 공유합니다.

## 목차
1. 소스 연결 3방식
2. 단일 인제스트 절차
3. 배치 인제스트 절차
4. MOC 갱신·교차링크
5. 코워크 지시문 예시

---

## 1. 소스 연결 3방식

위키 볼트 안의 여러 폴더를 소스로 묶는 방식입니다. 코워크는 지정한 폴더는 어디든 읽고, 옵시디언 `[[ ]]`·그래프뷰는 같은 볼트면 폴더 무관하게 연결됩니다.

### 방식 A — CLAUDE.md 소스 등록 (기본)

물리 이동 없이, 위키 볼트의 CLAUDE.md에 소스 폴더와 권한을 명시합니다.

```
## 위키 소스 폴더 (읽기 전용, 수정 금지)
- 01 매일 루틴 글쓰기/
- 02 AI 리서치 노트/
- 03 주제별 작업 노트/
- raw/web/
- chat/

## 위키 폴더 (코워크가 생성·갱신)
- 50 LLM 위키/
```

코워크는 소스 폴더는 읽기만, 위키 폴더만 생성·갱신합니다.

### 방식 B — 위키 페이지 frontmatter sources 경로

페이지별 출처 추적이 필요할 때 사용합니다. page-schema의 `sources` 필드에 소스 노트 경로를 배열로 적습니다. 소스가 갱신되면 위키를 재컴파일할 근거가 됩니다.

### 방식 C — 소스 레지스트리 노트

흩어진 자료를 옮기지 않고 목록으로만 등록합니다. 위키 폴더에 "어느 폴더의 어떤 노트가 소스인지" 링크 목록 노트 한 장을 둡니다.

### 경계 유지 주의

여러 폴더를 소스로 연결하면 트리거 간섭 표면이 넓어집니다. 위키 작업은 별도 볼트로 분리하거나, 같은 볼트라면 CLAUDE.md 상단에 "위키 작업 중 write-/lecture-/book- 스킬 트리거 비활성화"를 명시합니다. 이 규칙을 폴더 CLAUDE.md 상단에 상시 두면 매 세션 반복 선언이 없어집니다.

## 2. 단일 인제스트 절차

소스 노트 1장을 위키 페이지로 변환합니다.

1. 소스 노트를 읽습니다.
2. 의미 단위로 분해합니다. 한 노트가 여러 주제면 주제별로 나눕니다.
3. 주제별로 유형을 판별합니다(concept / experience).
4. page-schema 템플릿으로 페이지를 작성합니다(Generator).
5. 소스 일치를 검증합니다(Evaluator).
6. 위키 폴더에 저장하고 MOC에 추가합니다. 폴더가 작업 로그(log.md 등)를 요구하면 [Ingest] 1줄을 기록합니다.

한 소스가 개념과 경험을 함께 담으면 2장 이상으로 분리합니다. 예: 리서치 노트에 "MCP 정의 + 내가 강의에 적용한 기록"이 섞여 있으면 concept 1장 + experience 1장으로 나눕니다.

---

## 3. 배치 인제스트 절차

소스 폴더의 여러 노트를 일괄 변환합니다.

1. 소스 폴더의 노트 목록을 확인합니다.
2. 노트별로 단일 인제스트 절차(2번)의 1~5단계를 반복합니다.
3. 모든 페이지 생성·검증이 끝나면 MOC를 한 번에 갱신합니다.
4. 페이지 간 교차링크를 일괄 제안합니다.
5. 폴더가 작업 로그를 요구하면 배치 결과를 [Ingest] 1줄로 기록합니다.

배치 처리 중 중복·충돌 페이지가 보이면 그 페이지만 건너뛰고 사용자에게 보고합니다. 임의 병합하지 않습니다. 병합 판단은 wiki-audit로 넘깁니다.

## 4. MOC 갱신·교차링크

### 인덱싱 갱신

위키 폴더가 dataview index(index.md 자동수집)를 쓰면 MOC 갱신을 생략하고 index 노출만 확인합니다. MOC 방식 폴더에서만 다음을 적용합니다. 신규 페이지 저장 시 MOC(LLM-Wiki-MOC.md)의 해당 카테고리에 링크를 추가합니다. 카테고리는 type(개념/경험) 또는 주제군으로 둡니다. 새 주제군이 생기면 카테고리를 추가합니다.

### 교차링크 규칙

- 명확한 관련 쌍은 양쪽 페이지 `연결` 항목에 `[[ ]]` 링크를 추가합니다.
- 관련성이 약하면 링크 제안 목록으로만 제시하고 자동 추가하지 않습니다.
- concept ↔ experience 연결을 우선합니다. 개념과 그 개념을 적용한 경험을 잇는 링크가 활용 단계에서 가장 쓸모 있습니다.

## 5. 코워크 지시문 예시

### 단일 인제스트

```
50 LLM 위키 작업. 02 AI 리서치 노트/RL_MCP.md를 읽어
위키 페이지로 컴파일해줘.
- 개념과 경험이 섞여 있으면 concept·experience로 분리.
- frontmatter에 type·sources·updated(KST) 필수.
- 사실·수치·출처는 소스 그대로, 소스에 없는 건 "소스에 근거 없음"으로.
- 저장 후 LLM-Wiki-MOC.md에 링크 추가하고, 관련 기존 페이지와
  교차링크 제안.
```

### 배치 인제스트

```
50 LLM 위키 작업. chat/ 폴더의 5월 강의 Q&A 노트 전체를
경험 페이지로 인제스트해줘.
- 각 노트 → experience 페이지(상황·한 일·결과·적용 원칙).
- 외부 통계·정의가 섞였으면 concept로 분리.
- 전부 생성·검증 후 MOC 한 번에 갱신, concept↔experience 교차링크 제안.
- 기존 페이지와 중복되면 건너뛰고 목록으로 보고.
```

### 소스 연결 등록

```
이 볼트의 CLAUDE.md에 위키 소스 폴더를 등록해줘.
- 읽기 전용 소스: 01 매일 루틴 글쓰기/, 02 AI 리서치 노트/, 03 주제별 작업 노트/, chat/
- 갱신 대상 위키 폴더: 50 LLM 위키/
- 상단에 "위키 작업 중 write-/lecture-/book- 트리거 비활성화" 명시.
```
