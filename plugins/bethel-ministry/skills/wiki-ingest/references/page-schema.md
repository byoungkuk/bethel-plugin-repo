# 페이지 스키마 (page-schema)

concept·experience 두 유형의 frontmatter 스키마와 본문 템플릿, 페이지명 규약입니다. 이 스키마는 wiki-activate의 L1 검증·출처 표기와 1:1로 맞물립니다.

## 목차
1. 공통 frontmatter
2. concept 페이지 템플릿
3. experience 페이지 템플릿
4. 페이지명 규약
5. MOC 항목 형식

---

## 1. 공통 frontmatter

모든 위키 페이지는 다음 필드를 갖습니다. `type`·`sources`·`updated`는 필수입니다. 단, 위키 폴더 지침이 다른 스키마를 정하면 그 스키마를 우선하며, 폴더가 `type` 대신 분류 필드(예: `category`)를 쓰면 그 필드로 개념/경험을 구분하고 `type`은 생략합니다. 파일명 접두어(`W_` 등)·하위 폴더(`wiki/` 등)·본문 섹션 구성(8섹션 등)도 폴더 규약이 있으면 아래 템플릿보다 우선합니다.

```
---
type: concept        # concept 또는 experience
title: 페이지 제목
sources:
  - "02 AI 리서치 노트/RL_MCP.md"
  - "03 주제별 작업 노트/karpathy-llm-wiki.md"
tags: [llm, mcp]
created: 2026-06-02   # KST
updated: 2026-06-02   # KST, 갱신 시 변경
---
```

- `sources`는 소스 노트 경로 배열입니다. 소스가 갱신되면 위키 재컴파일 근거가 됩니다. 위키링크(`[[ ]]`)는 노트형 소스에만 쓰고, docx·pptx·pdf 등 비노트 원본은 경로 문자열로 적어 신선도 점검 대상에서 제외합니다.
- `tags`는 검색·연결용. 과다 부착하지 않습니다.
- 외부 웹 자료가 출처면 `sources`에 URL을 넣고 본문 출처란에 접근일을 적습니다.

## 2. concept 페이지 템플릿

외부 사실·데이터·출처가 중심인 페이지입니다.

```
---
type: concept
title: MCP (Model Context Protocol)
sources:
  - "02 AI 리서치 노트/RL_MCP.md"
tags: [llm, protocol, tool-use]
created: 2026-06-02
updated: 2026-06-02
---

# MCP (Model Context Protocol)

## 정의
한 문단으로 핵심 정의. 소스의 사실을 그대로 옮깁니다(L1).

## 핵심 내용
- 항목 1 (사실·메커니즘)
- 항목 2
- 항목 3

## 주요 수치
- 수치 1 (출처 명시)
- 수치 2

## 출처
- 소스 노트명 또는 URL (접근일)

## 연결
- [[관련 페이지 1]]
- [[관련 페이지 2]]
```

규칙: 정의·핵심 내용·주요 수치는 L1로 소스 그대로, 도입 한 줄과 연결 메모만 L3로 작성합니다. 소스에 수치가 없으면 "주요 수치" 항목에 "소스에 근거 없음"으로 표시합니다.

## 3. experience 페이지 템플릿

1인칭 현장 기록 페이지입니다. 책 경험 주입의 직접 소스입니다.

```
---
type: experience
title: 강좌 운영에 Cowork를 붙인 기록
sources:
  - "chat/2026-05 출판AI 8강 Q&A.md"
tags: [cowork, 강의운영, 경험]
created: 2026-06-02
updated: 2026-06-02
---

# 강좌 운영에 Cowork를 붙인 기록

## 상황
언제·어디서·무엇을 하던 중이었는지. 1인칭.

## 한 일
구체적으로 어떤 도구를 어떤 순서로 썼는지.

## 결과
무엇이 달라졌는지. 수치가 있으면 함께.

## 적용 원칙
이 경험에서 일반화한 판단 기준 1~2개. 책·강의에서 재사용할 형태로.
```

규칙: 상황·한 일·결과는 사실 그대로(L1), 적용 원칙만 일반화(L3)합니다. 경험 페이지에는 외부 통계·정의를 섞지 않습니다. 그런 내용이 필요하면 별도 concept 페이지로 분리하고 `연결`로 잇습니다.

---

## 4. 페이지명 규약

- 주제 단위 명사구로 작성합니다.
- 도구·개념의 고유명은 원어 표기를 유지합니다(MCP, Cowork, RAG).
- 경험 페이지는 "무엇을 한 기록" 형태로 동작을 드러냅니다.
- 파일명 = 페이지 제목. 같은 제목이 있으면 신규 생성하지 않고 기존 페이지를 갱신하거나 wiki-audit로 충돌을 점검합니다.

---

## 5. 인덱싱 — MOC 또는 dataview index

위키 폴더가 dataview index(예: index.md 자동수집)를 쓰면 이 절을 건너뜁니다. 신규 페이지는 저장 즉시 index에 노출되어 수동 등록이 필요 없습니다. MOC 방식 폴더에서만 아래를 적용합니다.

MOC(LLM-Wiki-MOC.md)에는 카테고리별로 페이지 링크를 둡니다.

```
## 개념 (concept)
- [[MCP (Model Context Protocol)]]
- [[RAG]]
- [[Cowork]]

## 경험 (experience)
- [[강좌 운영에 Cowork를 붙인 기록]]
```

신규 페이지를 저장할 때마다 해당 카테고리에 링크를 추가합니다. 카테고리가 없으면 새로 만듭니다.
