# wiki-ingest

소스 데이터를 읽어 LLM 위키 페이지로 컴파일하는 인제스트 워크플로우입니다. 카파시(Karpathy) LLM-Wiki 패턴에서 위키는 코드베이스, 코워크(Cowork)는 프로그래머, 옵시디언(Obsidian)은 IDE에 해당합니다. 이 스킬은 코드베이스를 쌓는 단계를, wiki-activate는 그것을 읽어 실행하는 단계를 담당합니다. 위키에 들어갈 원문 보존 리서치(raw 스크랩·1차 대조)는 wiki-research가 앞 단계를 담당합니다.

## 전제 조건

1. 위키 폴더가 지정되어 있습니다(예: `50 LLM 위키/`). 없으면 사용자에게 폴더명을 확인합니다. 운영 지침(CLAUDE.md)이 없는 폴더에는 임의로 새 위키를 만들지 않고, 대상 폴더를 먼저 확인합니다(폴더 가드).
2. 소스 폴더가 1개 이상 있습니다. 소스는 raw/ 아래로 한정하지 않습니다. `01 매일 루틴 글쓰기`, `02 AI 리서치 노트`, `03 주제별 작업 노트` 등 기존 폴더도 소스로 등록합니다.

전제가 충족되지 않으면 진행하지 않고, 위키 폴더와 소스 폴더를 먼저 확정합니다.

## 위키 폴더 지침 우선

위키 폴더에 운영 지침(CLAUDE.md 등)이 있으면 그 스키마·인덱싱·소스 표기 규약을 이 스킬 기본값보다 우선 적용합니다.

- 스키마: 폴더가 `type` 필드를 쓰지 않고 다른 분류 필드(예: `category`)로 개념/경험을 구분하면 그 필드를 따릅니다. 이때 `type` 미사용은 결함이 아닙니다.
- 인덱싱: 폴더가 MOC 대신 dataview index(예: index.md 자동수집)를 쓰면 수동 MOC 갱신·점검을 생략하고 index 노출만 확인합니다.
- 소스 표기: 폴더가 정한 sources 형식을 따릅니다. 위키링크(`[[ ]]`)는 노트형 소스에만 쓰고, docx·pptx·pdf 등 비노트 원본은 경로 문자열로 표기합니다.
- 명명·배치·본문 구조: 폴더가 파일명 접두어(예: `W_`)·하위 폴더(예: `wiki/`)·본문 섹션 구성(예: 8섹션)을 정하면 기본 템플릿보다 그 규약을 따릅니다.

폴더 지침이 없을 때만 아래 기본 규약(`type`·MOC)을 적용합니다.

## 페이지 유형 (2종)

위키 페이지는 두 종류로 분리해 생성합니다. 혼합 금지가 핵심입니다. 경험 주입(book-writing-pro) 소스를 골라내려면 경험이 별도 페이지여야 합니다.

| 유형 | type | 담는 것 | 활용 |
|------|------|---------|------|
| 개념 페이지 | concept | 정의·핵심 내용·주요 수치·출처 | 책 개념 깊이, 강의 비교 데이터, 블로그 핵심 |
| 경험 페이지 | experience | 본인 상황·한 일·결과·적용 원칙 | 책 경험 주입, 페북 후크, 강의 본인 사례 |

판별 기준: 외부 사실·데이터·출처가 중심이면 concept, 1인칭 현장 기록이면 experience입니다. 한 소스 안에 둘이 섞여 있으면 두 페이지로 분리합니다.

## 프로세스 (Phase 0 ~ 5)

### Phase 0 — 소스 연결과 위키 폴더 확인

위키 폴더와 소스 폴더를 확정합니다. 소스 폴더는 읽기 전용으로 다루고 수정하지 않습니다. 위키 폴더만 생성·갱신 대상입니다. 연결 방식은 `references/ingest-patterns.md`의 소스 등록 3방식을 따릅니다.

같은 볼트에서 작업할 경우, 인제스트 중 write-/lecture-/book- 스킬이 오발동하지 않도록 CLAUDE.md 상단에 트리거 비활성화를 명시하거나 위키를 별도 볼트로 분리합니다.

### Phase 1 — 인제스트 범위 확정

처리 단위를 정합니다.

1. 단일 노트 인제스트 — 소스 노트 1장 → 위키 페이지 1~N장
2. 폴더 배치 인제스트 — 소스 폴더의 여러 노트 → 위키 페이지 일괄 생성

배치 인제스트는 노트별로 Phase 2~4를 반복하고 Phase 5에서 MOC를 한 번에 갱신합니다.

### Phase 2 — 소스 읽기·청크 분해

소스 노트를 읽어 의미 단위로 분해합니다. 한 노트가 여러 주제를 담으면 주제별로 나눕니다. 분해 시 사실·수치·출처는 원문 그대로 표시(L1)하고, 묶음과 순서만 재배열(L2)합니다.

### Phase 3 — 페이지 생성 (Generator)

페이지 유형을 판별하고 스키마에 맞게 작성합니다. frontmatter·본문 템플릿은 `references/page-schema.md`를 따릅니다. 핵심 규약은 다음과 같습니다.

- frontmatter 필수 필드: `type`, `title`, `sources`(소스 경로 배열), `created`, `updated`(KST). 위키 폴더가 다른 스키마를 정하면 폴더 우선이며, `type` 미사용 폴더면 폴더 분류 필드(예: `category`)로 대체합니다
- concept 본문: 정의 / 핵심 내용 / 주요 수치 / 출처
- experience 본문: 상황 / 한 일 / 결과 / 적용 원칙 (1인칭)
- 페이지명 규약: 주제 단위 명사구. 도구·개념은 원어 표기 유지(MCP, Cowork)

### Phase 4 — 검증 (Evaluator)

Phase 3과 분리된 시점에서 점검합니다.

- 페이지의 사실·수치·출처가 소스 노트와 일치하는가
- 소스에 없는 내용을 임의 생성하지 않았는가
- frontmatter 필수 필드(type·sources·updated)가 모두 있는가
- 개념과 경험이 한 페이지에 섞이지 않았는가
- 기존 위키 페이지와 제목·내용이 중복·충돌하지 않는가

불일치는 소스 근거로 교정합니다. 소스에 근거가 없는 부분은 "소스에 근거 없음"으로 표시하고 보충 리서치를 권합니다(위키 원천 품질이 필요하면 wiki-research, 일반 주제는 research-topic·book-research). 기존 위키와의 충돌·중복이 의심되면 wiki-audit로 넘깁니다.

### Phase 5 — 위키 저장·MOC 갱신·교차링크

검증을 통과한 페이지를 위키 폴더에 저장합니다.

1. 페이지 파일 저장(.md). 파일명은 페이지 제목 규약을 따릅니다.
2. 인덱싱: 폴더가 MOC를 쓰면 신규 페이지 링크를 추가합니다(새 카테고리는 반영). dataview index(예: index.md 자동수집)를 쓰면 수동 갱신 없이 index 노출만 확인합니다.
3. 관련 기존 페이지와 `[[ ]]` 교차링크를 제안합니다. 명확한 쌍은 양쪽에 링크를 추가합니다.
4. 위키 폴더가 작업 로그(예: log.md)를 요구하면 [Ingest] 1줄을 기록합니다(소스·생성 페이지 포함).

상세는 `references/ingest-patterns.md`를 참조합니다.

## 소스 연결 규칙

raw/ 단일 의존이 아니라 위키 볼트 안의 여러 폴더를 소스로 묶습니다. 세 가지 방식 중 상황에 맞게 선택합니다. 상세는 `references/ingest-patterns.md`를 참조합니다.

1. CLAUDE.md 소스 등록 — 소스 폴더 목록과 권한 명시. 기본 방식.
2. 위키 페이지 frontmatter `sources` 경로 — 페이지별 출처 추적이 필요할 때.
3. 소스 레지스트리 노트 — 흩어진 자료를 옮기지 않고 목록으로 등록할 때.

## Harness Engineering

- 생성-평가 분리: Phase 3(Generator)과 Phase 4(Evaluator)를 분리해, 소스 일치를 별도 시점에서 검증합니다.
- AI 흔적 제거: 페이지에서 금지어(혁신적인·획기적인·완벽한·매우·쉽게·빠르게·~할 수 있습니다)와 모호한 수식을 제거합니다. 종결어미는 ~합니다체로 통일합니다.
- 보존 레벨:
  - L1 (원문 보존) — 소스의 사실·수치·출처. 변경하지 않고 그대로 기록합니다.
  - L2 (재배열 허용) — 청크 묶음·페이지 분할·순서. 위키 구조에 맞게 재배열합니다.
  - L3 (자유 생성) — 페이지 요약 문장·연결 메모·도입. 새로 작성합니다.
- 분량 가드레일: 한 페이지는 한 주제. 여러 주제가 보이면 분할합니다. 페이지 본문은 핵심 위주로 압축하고, 소스 전문 복사는 하지 않습니다.

## 출력 규약

- 한국어로 출력합니다. 날짜·시각은 KST 기준입니다.
- 코워크 지시문·코드·설정은 코드 블록(```)에 넣습니다.
- 생성한 페이지명과 소스 경로를 작업 끝에 표기합니다.
- 소스에 근거가 없는 부분은 임의 생성하지 않고 "소스에 근거 없음"으로 표시합니다.

## 참조 파일

- `references/page-schema.md` — concept·experience 페이지의 frontmatter 스키마와 본문 템플릿, 페이지명 규약.
- `references/ingest-patterns.md` — 소스 연결 3방식, 단일·배치 인제스트 절차, MOC 갱신·교차링크 규칙, 코워크 지시문 예시.
