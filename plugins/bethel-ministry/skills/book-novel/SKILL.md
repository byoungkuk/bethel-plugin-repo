# 소설 쓰기 워크플로우 (Novel Writing Workflow)

7단계 소설 창작 프로세스. 사람이 설계하고 AI가 문장을 만드는 분업 구조.

## 전체 흐름

```
Phase 1: 설계 키트 → Phase 2: 파일럿 챕터 → Phase 3: 톤 레퍼런스 확정
→ Phase 4: 본격 집필 → Phase 5: 중간 점검 → Phase 6: 퇴고 → Phase 7: 최종 편집
```

사용자의 현재 상태를 파악해 적절한 단계부터 시작한다.
- 소설 아이디어만 있음 → Phase 1부터
- 설계 키트(인물·플롯·세계관) 완성됨 → Phase 2부터
- 초안이 이미 있음 → Phase 6부터
- 특정 씬만 작성 요청 → Phase 4의 씬 작성 프로세스 직접 진입

---

## 소설 문체 원칙

이 스킬의 모든 원고에 적용하는 기본 문체. 스타일 가이드 파일이 있으면 그것이 이 섹션보다 우선한다.

> **스타일 가이드:** `references/style-guide.md`
> 현재 "내면 서사형(Inner Narrative Style)" 스타일이 설정되어 있다.
> 다른 스타일로 교체하려면 이 파일의 내용을 바꾼다.
> 스타일 가이드가 없는 경우 아래 기본 원칙을 적용한다.

**기본 태도:** 소설은 설명하지 않고 보여준다(Show, don't tell). 감정을 형용사로 직접 서술하지 않고, 행동·감각·풍경으로 드러낸다.

**문장:** 간결하고 리듬이 있다. 긴 문장과 짧은 문장을 섞되, 긴장감이 높은 장면일수록 문장을 짧게 끊는다.

**묘사:** 시각·청각·촉각·후각 중 2가지 이상의 감각을 장면마다 배치한다. 추상적 묘사("아름다운 풍경")보다 구체적 디테일("담장 위에 마른 이끼가 벗겨지고 있었다")을 쓴다.

**대화문:** 인물의 성격과 관계가 대사에 드러나야 한다. 모든 인물이 같은 말투로 말하면 안 된다. 대사에 정보를 과도하게 담지 않는다(설명적 대사 금지).

**금지 패턴:**
- "갑자기", "문득", "왠지" 같은 전환 부사 남용
- 작가 개입형 설명 ("사실 그는 ~한 사람이었다")
- 느낌표(!)는 대화문 내에서만, 최소한으로 사용
- (추가 금지 표현은 스타일 가이드 참조)

## Phase 1: 설계 키트 (Design Kit)

소설 집필 전 반드시 준비해야 하는 6가지 설계 문서를 만든다. 사용자가 아이디어만 가지고 온 경우, 대화를 통해 아래 항목을 하나씩 채워간다.

> **참조:** `references/design-kit-template.md`
> 각 항목의 상세 양식과 가상 예제(〈회색 수조〉)가 포함되어 있다. Phase 1 시작 전 반드시 읽는다.

### 1-1. 장르와 톤
수집 항목:
- 장르 (스릴러, 로맨스, SF, 판타지, 일상물, 문학, 웹소설 등)
- 톤 (건조한, 감성적인, 유머러스한, 어두운, 담담한 등)
- 분위기 키워드 3~5개
- 참조 작품 1~2개 (문체·구조·분위기 중 무엇을 참조하는지 명시)
- 독자 타깃

### 1-2. 인물 설계서
주요 인물 3~5명에 대해 수집:
- 이름, 나이, 직업, 외형 특징
- 성격 (핵심 2~3가지)
- 말투 (대사 예시 포함)
- 핵심 욕망과 핵심 결핍
- 변화 방향 (아크): 시작점 → 끝점

인물 설계서가 충실할수록 AI가 일관된 인물을 유지한다. 특히 **말투**는 대사 예시 2~3개를 반드시 포함한다.

### 1-3. 플롯 구조
3막 구조를 기본으로, 10~20개 씬(Scene) 단위로 설계한다.

| 구분 | 내용 |
|------|------|
| 1막 (발단·전개) | 일상 → 균열 → 사건 발생. 전체의 25% |
| 2막 (위기·갈등) | 추적·갈등·시련·반전. 전체의 50% |
| 3막 (절정·결말) | 최종 선택·대결·해소. 전체의 25% |

씬 리스트 각 항목에 포함할 정보:
- 장소
- 등장 인물
- 사건 (무엇이 일어나는가)
- 감정 변화 (시작 감정 → 끝 감정)
- 이 씬이 전체 이야기에서 하는 역할

### 1-4. 세계관·배경 설정
- 시간 (시대, 계절, 기간)
- 공간 (주요 장소 3~5곳, 각 장소의 감각적 특징)
- 사회적 배경 (이야기에 영향을 미치는 규칙·관습·제도)
- 감각 소재 팩 (장면 묘사에 반복 사용할 시각·청각·후각·촉각 소재)

### 1-5. 서술 시점과 문체 규칙
확정할 항목:
- 서술 시점 (1인칭 / 3인칭 제한 / 3인칭 전지 / 다시점)
- 시제 (과거형 / 현재형)
- 종결어미 (~다체 / ~요체 / 기타)
- 문장 길이 기준 (기본: 40자 이내)
- 문단 길이 기준 (기본: 3~5문장)
- 대화문 비중 (기본: 40~50%)
- 인물별 말투 규칙
- 금지 표현 목록

### 1-6. 작업 단위 설계
- 전체 목표 분량
- 챕터 수와 챕터당 분량
- 1회 AI 요청 분량 (권장: 1,500~2,000자)
- 작업 순서 계획

### 산출물

설계 키트 6개 항목을 대화창 텍스트로 제공한다. 사용자가 확인·수정한 후 Phase 2로 진행한다.

---

## Phase 2: 파일럿 챕터 (Pilot Chapter)

설계 키트가 실제로 작동하는지 테스트한다. 챕터 1~2를 작성하고 3가지를 점검한다.

### 점검 항목

| # | 항목 | 기준 |
|---|------|------|
| 1 | 톤 일치 | 설계 키트의 톤·분위기 키워드가 문장에 반영되는가 |
| 2 | 인물 말투 | 각 인물의 대사가 설계서의 말투 규칙과 일치하는가 |
| 3 | 장면 흐름 | 씬 리스트의 감정 변화가 자연스럽게 표현되는가 |

### 프로세스

1. 씬 리스트에서 챕터 1의 정보를 추출한다
2. 씬 작성 프롬프트(Phase 4 참조)에 따라 초안을 작성한다
3. 점검 항목 3가지를 확인한다
4. 문제가 있으면 설계 키트를 수정한다 (프롬프트 지시문 구체화, 인물 정보 보완 등)
5. 수정 후 챕터 2를 작성하여 재점검한다

파일럿 챕터에서 설계 키트 수정이 2회 이상 발생하면, 수정 내용을 사용자에게 요약 보고한다.

---

## Phase 3: 톤 레퍼런스 확정 (Tone Reference)

파일럿 챕터에서 "이 소설의 기준 문장"이라 할 수 있는 문단 3~5개를 선별한다.

### 선별 기준
- 서술 톤이 설계 키트의 분위기 키워드와 정확히 일치하는 문단
- 인물 말투가 가장 잘 드러나는 대화 문단
- 풍경·감각 묘사가 이 소설의 스타일을 대표하는 문단

### 활용 방식
이후 모든 챕터 작성 요청 시 톤 레퍼런스 문단을 함께 전달한다. AI가 문체 일관성을 유지하는 앵커(anchor) 역할을 한다.

---

## Phase 4: 본격 집필 (Chapter Drafting)

씬 리스트 순서대로 챕터를 작성한다. 한 챕터를 1~3회 요청으로 나눠 작성한다.

### 씬 작성 시 AI에게 전달할 정보 (매 요청마다)

```
[고정 정보 — 매번 동일]
1. 서술 규칙 (Phase 1-5에서 확정한 시점·시제·문체·금지 표현)
2. 톤 레퍼런스 문단 (Phase 3에서 선별)

[가변 정보 — 매 챕터마다 변경]
3. 해당 챕터의 씬 정보
   - 챕터 번호, 장소, 등장 인물
   - 사건 요약
   - 감정 변화 (시작 → 끝)
4. 이 장면에서 반드시 포함할 요소
5. 이 장면에서 하지 말아야 할 것
6. 직전 챕터 마지막 2~3문단 (연결용)
7. 해당 인물 설계서 (이 챕터에 등장하는 인물만)
```

### 씬 작성 프로세스

1. 씬 리스트에서 해당 챕터 정보 확인
2. 등장 인물의 설계서 확인
3. 직전 챕터 끝부분 확인 (첫 챕터 제외)
4. 위 7가지 정보를 조합하여 초안 작성
5. 초안 완성 후 자가 점검:
   - 감정을 직접 서술한 문장이 있는가 → 행동/감각으로 교체
   - 인물 말투가 설계서와 일치하는가
   - 씬의 감정 변화가 자연스럽게 진행되는가
   - 금지 표현이 포함되어 있는가
6. 대화창 텍스트로 제공

### 분량 통제

- 1회 요청 기본 분량: 1,500~2,000자
- 긴장도가 높은 장면(클라이맥스, 반전): 1,500자 이하로 밀도를 높인다
- 전환·이동 장면: 1,000자 이하로 간결하게
- 사용자가 분량을 지정하면 그것을 따른다

### 작업 유형별 처리

- **"다듬어줘" / "수정해줘"** = 원문의 문장 수·구조를 유지하고 표현만 정리
- **"보강해줘"** = 지정 부분에 한해 내용 추가. 미지정 부분은 원문 유지
- **"이어서 써줘"** = 직전 문단의 톤과 흐름을 이어받아 다음 장면 작성
- **"다시 써줘"** = 같은 씬 정보로 완전히 새로운 초안 작성

> **참조:** `references/scene-prompt-templates.md`
> 씬 초안 요청, 퇴고 요청, 대화문 점검 등 프롬프트 템플릿이 포함되어 있다.

## Phase 5: 중간 점검 (Mid-Point Review)

전체 챕터의 절반(50~60%) 완료 시점에서 통독 점검한다.

### 점검 항목

| # | 항목 | 확인 내용 |
|---|------|-----------|
| 1 | 복선 | 1막에서 깐 복선이 2막에서 회수되고 있는가 |
| 2 | 감정 곡선 | 인물의 감정 변화가 급격하거나 느슨하지 않은가 |
| 3 | 인물 일관성 | 말투·성격·행동 패턴이 설계서와 일치하는가 |
| 4 | 톤 일관성 | 챕터 간 문체 편차가 크지 않은가 |
| 5 | 반복 표현 | 같은 비유·묘사·전환 표현이 반복되지 않는가 |
| 6 | 페이싱 | 사건 간 간격이 균형 잡혀 있는가 |

점검 결과를 사용자에게 보고하고, 수정이 필요한 챕터를 특정한다. 앞부분 수정은 이 시점에서 하는 것이 전체 완성 후보다 효율적이다.

---

## Phase 6: 퇴고 (Revision & Editing)

전체 초안 완성 후 3회 패스 편집을 실행한다.

### Pass 1: 구조 편집

| # | 점검 항목 |
|---|----------|
| 1 | 전체 스토리 아크가 처음부터 끝까지 논리적으로 흐르는가 |
| 2 | 각 챕터가 전체 이야기를 전진시키는가 (불필요한 챕터 없는가) |
| 3 | 페이싱이 균형 잡혀 있는가 (늘어지거나 급한 부분 없는가) |
| 4 | 1막 도입부가 독자를 끌어당기는가 |
| 5 | 결말이 전제와 일관되고 감정적 해소가 있는가 |
| 6 | 복선이 모두 회수되었는가 |
| 7 | 인물 아크(변화)가 완결되었는가 |

### Pass 2: 장면·문장 편집

| # | 점검 항목 |
|---|----------|
| 1 | 감정 직접 서술이 남아 있는가 → 행동/감각 묘사로 교체 |
| 2 | 문장 길이가 기준을 초과하는가 → 분리 |
| 3 | 금지 표현("갑자기", "문득", 느낌표 등)이 남아 있는가 → 제거 |
| 4 | 인물 말투가 전체적으로 일관되는가 |
| 5 | 대화문에 불필요한 설명이 포함되어 있는가 → 삭제 |
| 6 | 감각 묘사가 장면마다 충분한가 (시각+1가지 이상) |
| 7 | 비유가 챕터당 상한(기본 2회)을 초과하는가 |
| 8 | 같은 단어·표현이 한 페이지 안에 반복되는가 |

### Pass 3: 교정

| # | 점검 항목 |
|---|----------|
| 1 | 맞춤법·띄어쓰기 오류 |
| 2 | 인물 이름·나이·직업 등 사실관계 일관성 |
| 3 | 시간 흐름의 논리적 정합성 (날짜·요일·계절) |
| 4 | 장소 묘사의 일관성 (같은 장소가 다르게 묘사되지 않는가) |
| 5 | 서술 시점 이탈이 없는가 (3인칭 제한 시점에서 다른 인물 내면 서술 등) |

### 퇴고 요청 방식

챕터 단위로 퇴고를 요청한다. 원문을 붙여넣고, 수정 기준(Pass 1/2/3 중 어느 단계인지)을 명시한다. 수정한 부분은 【 】로 표시하고 수정 이유를 각주로 단다.

### 산출물

퇴고 완료 원고를 대화창 텍스트로 제공한다. 사용자 요청 시 `.docx`로 저장한다.

## Phase 7: 최종 편집 (Final Polish)

전체 원고를 출판/배포 수준으로 마무리한다.

### 최종 편집 항목

1. **프롤로그** (선택): 본편 시작 전 독자를 끌어당기는 장면이나 문단
2. **에필로그** (선택): 결말 이후의 여운, 또는 열린 결말의 확장
3. **챕터 제목 점검**: 각 챕터 제목이 내용을 암시하되 스포일러가 아닌지 확인
4. **첫 문장·마지막 문장 점검**: 각 챕터의 첫 문장(훅)과 마지막 문장(다음 챕터로의 견인력) 최종 확인
5. **통독**: 처음부터 끝까지 이어 읽으며 독자 경험 점검
6. **최종 원고 생성**: 사용자 요청 시 `.docx` 파일로 출력
