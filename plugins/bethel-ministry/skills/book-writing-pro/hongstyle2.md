용도: 실용서·가이드·교재 집필 시 적용하는 문체·구조·표기 규칙

## 종결어미

합니다체를 기본으로 사용합니다.

| 유형 | 패턴 | 예시 |
|------|------|------|
| 서술 | ~합니다 | "결과가 매번 달라지는 이유는 도구의 성능이 아니라 요청의 구조에 있습니다." |
| 상태 | ~입니다, ~있습니다 | "이것이 프롬프트를 '일회용 지시'에 머물게 하는 가장 현실적인 원인입니다." |
| 부정 | ~않습니다, ~없습니다 | "한 번의 프롬프트로 완벽한 결과를 기대하기보다" |
| 제안 | ~보겠습니다 | "채널별로 적용할 수 있는 글쓰기 스킬을 설계해 보겠습니다." |
| 조건 | ~면, ~경우 | "프롬프트를 정교하게 작성해도 맥락이 초기화되면 같은 설명을 반복하게 됩니다." |

### 금지하는 종결어미
- "~해 보세요", "~하시면 됩니다" (존칭형)
- "~해봅시다", "~알아봅시다" (청유형)
- "~할 수 있습니다", "~될 것입니다" (추측형)
- "살펴보겠습니다", "알아보겠습니다" (AI 흔적)

## 어조

가르치지 않되 이끕니다. 독자 위에 서지 않고 같은 문제를 함께 바라보는 위치를 취합니다. 설득보다 납득을 유도하는 설명자의 태도를 유지합니다.

❌ "이렇게 하면 됩니다. 꼭 기억하세요."
⭕ "이 기준으로 보면 판단이 달라집니다."

❌ "AI 글쓰기의 3가지 팁을 알려드립니다."
⭕ "대부분 스킬을 '프롬프트 저장'의 문제로 봅니다. 그런데 실제로 반복되는 건 프롬프트가 아니라 판단입니다."

## 문장 규칙

### 1문장 1정보 원칙
한 문장에 두 가지 이상의 정보를 넣지 않습니다.

❌ "AI에게 일을 시키는 방식은 사람에게 지시하는 것과 구조부터 달랐고, 동일한 프롬프트를 넣어도 대화가 길어지면 맥락이 흐려졌으며, 검증을 마친 워크플로우를 전달해도 다른 프로젝트에서는 전혀 다른 결과가 나타났습니다."
⭕ "AI에게 일을 시키는 방식은 사람에게 지시하는 것과 구조부터 달랐습니다. 동일한 프롬프트를 넣어도 대화가 길어지면 맥락이 흐려졌습니다. 검증을 마친 워크플로우를 그대로 전달해도 다른 프로젝트에서는 전혀 다른 결과가 나타났습니다."

### 문장 길이
20~50자 범위를 기본으로 하되, 정보량에 따라 70자까지 허용합니다.

### 능동형 우선
❌ "결과가 생성되었습니다"
⭕ "결과를 생성합니다"

## 문단 구성

### 기본 규칙
- 2~4문장 기본, 최대 5문장.
- 문단 첫 문장: 해당 문단의 핵심 판단 또는 전환점을 제시합니다.
- 문단 마지막 문장: 다음 문단으로의 전환을 암시하거나 판단을 닫습니다.

### 문단 내 점층 구조
문단 앞부분은 가볍게, 뒤로 갈수록 판단 밀도가 높아지는 구조를 따릅니다.

```
[관찰문] 현상·상황을 짧게 제시합니다 (단문, 20자 이내)
[전환문] 그 현상이 왜 문제인지 연결합니다 (30~40자)
[판단문] 기준·결론을 제시합니다 (40~50자)
```

### 적용 예시

❌ 밀도 없는 문단:
> 스킬을 만들면 반복 작업을 줄일 수 있고, 이를 통해 작업 시간을 단축할 수 있으며, 결과적으로 더 많은 콘텐츠를 생산할 수 있게 됩니다.

⭕ 점층 구조 문단:
> 프롬프트는 잘 작동했습니다. 하지만 다음 대화에서 같은 결과를 재현하지 못했습니다. 톤이 달라지고, 구조가 흔들리고, 이전에 합의한 판단 기준이 사라졌습니다. **매번 같은 설명을 반복하게 되면, 결국 AI 없이 직접 쓰는 쪽이 빠릅니다.**

## 논리 전개

### 기본 패턴
현상 → 원인/문제 지점 → 판단 기준 → 적용 방식

❌ "스킬 설계법 3가지를 소개합니다."
⭕ "프롬프트를 길게 쓴다고 해서 스킬이 되지는 않습니다. 스킬의 품질을 결정하는 것은 지시의 양이 아니라 판단 기준의 명확도입니다."

### 스킬/실습 해설 패턴
통제 기준을 먼저 선언하고, 첫째/둘째/셋째로 풀어 설명합니다.

⭕ "이 스킬에서 통제하는 기준은 3가지입니다. 첫째, 글의 목적을 유형별로 분기합니다. 둘째, 각 유형에 맞는 구조 템플릿을 지정합니다. 셋째, 리라이팅 단계에서 금지어와 이탈 징후를 점검합니다."

### 유지/변경 분리 패턴
실습에서 무엇을 고정하고 무엇을 바꾸는지 명시합니다.

⭕ "이 스킬에서는 유지 대상(5단계 프로세스, 문체 규칙)과 변경 대상(플랫폼 규칙, 도입부 설계, 소제목 구조)을 분리해 지정합니다."

### 대비 패턴
기존 방식의 한계 → 새 방식의 차이 → 그 차이가 실무에서 작동하는 지점

⭕ "기존 프롬프트 활용에는 '매번 맥락을 다시 설명해야 한다'는 전제가 깔려 있었습니다. 반면 스킬 기반 워크플로우에서는 '판단 기준이 이미 내장되어 있다'로 전제가 바뀝니다."

## 서술 전략

- 글의 첫 문장은 **독자의 문제 상황** 또는 **"왜 이것이 필요한가"**로 시작합니다.
- 기능·현상을 나열하는 것으로 시작하지 않습니다.
- 소제목은 기능명이 아닌 **판단 기준 중심**으로 작성합니다.
- 사례는 결론을 증명하기 위한 도구로만 사용합니다.
- 마무리는 요약이 아닌 **관점 재정렬 + 다음 판단 기준**으로 마무리합니다.

❌ 첫 문장: "클로드 스킬은 반복 작업을 자동화하는 기능입니다."
⭕ 첫 문장: "AI에게 일을 시키는 것과 일하는 방식을 가르치는 것은 구조부터 다릅니다."

❌ 소제목: "write-content의 5단계 기능"
⭕ 소제목: "write-content가 해결하는 문제 — '매번 설명'에서 '판단 기준 내장'으로"

## 소제목 구조

### 파트 제목: 주제 + 엠대시 + 부연
```
PART 01 [주제] — [부연 설명]
```
예: `PART 01 스킬이라는 개념 — AI에게 일하는 방식을 가르치기 전에 알아야 할 것`

### 섹션 제목: 키워드 + 엠대시 + 판단 기준
```
[핵심 키워드] — [판단 기준 또는 의미]
```
예: `트리거 설계 — 스킬이 정확히 호출되기 위한 조건`
예: `워크플로우 단계 분리 — 한 덩어리가 아니라 점검 가능한 구간으로`

### 프로젝트(실습) 제목
```
[동사형 제목]
Project [번호]
```
예: `브런치 전용 글쓰기 스킬 만들기` / `Project 01`

## 번호 체계

### 하위 항목: 원문자 ①②③④⑤
섹션 내부에서 하위 항목을 나열할 때 사용합니다. 각 항목은 볼드 제목 + 해설 문단으로 구성합니다.
```
① 트리거 설계 — 스킬이 정확히 호출되기 위한 조건
② 워크플로우 단계 분리 — 한 덩어리가 아니라 점검 가능한 구간으로
③ 문체 규칙 내장 — 톤과 구조를 매번 지시하지 않아도 되는 상태
```

### 실습 순서: 1단계, 2단계, 3단계
```
1단계  원형 스킬 구조 분석
2단계  파생 규칙 설계 및 적용
3단계  결과 확인 후 이탈 징후 점검
```

### 통제 기준: 첫째/둘째/셋째
```
이 스킬에서 통제하는 기준은 3가지입니다. 첫째, ~ 둘째, ~ 셋째, ~
```

## 용어 설명 규칙

전문 용어는 독자가 모른다고 가정합니다. 아래 3가지 패턴을 상황에 맞게 적용합니다.

### 패턴 1: 일상어 병기 (첫 등장 시)
전문 용어 뒤에 괄호로 일상어 풀이를 붙입니다. 영문 병기와 함께 쓸 경우, 영문 먼저 일상어 뒤에 배치합니다.

⭕ "프론트매터(YAML Frontmatter, 파일 상단의 설정 영역)에 스킬 이름을 작성합니다."
⭕ "컨텍스트 윈도우(AI가 한 번에 읽을 수 있는 분량의 한계)는 모델마다 다릅니다."
⭕ "토큰(AI가 텍스트를 처리하는 최소 단위)으로 환산하면 약 75만 자입니다."

### 패턴 2: 대응 비유 (개념 도입 시)
기술 용어를 독자가 이미 아는 개념에 대응시킵니다. 파트 도입부 또는 용어가 핵심 역할을 하는 챕터에서 사용합니다.

⭕ "스킬은 AI용 업무 매뉴얼입니다. 사람에게 인수인계 문서를 만들 듯, AI에게 작업 기준을 문서로 남깁니다."
⭕ "코워크는 AI에게 내 컴퓨터 폴더를 열어주는 것입니다. 대화창에서 텍스트만 주고받던 것과 달리, 파일을 직접 만들고 수정합니다."

### 패턴 3: 한 줄 풀이 (본문 중간)
기술적 설명 직후에 "즉, ~" 또는 "~라는 뜻입니다"로 한 문장을 추가합니다. 별도 박스가 아니라 본문 흐름 안에서 처리합니다.

⭕ "YAML 프론트매터에 name과 description을 작성합니다. 즉, 이 스킬의 이름과 언제 호출할지를 AI에게 알려주는 부분입니다."
⭕ "MCP를 통해 외부 도구와 연결합니다. 즉, 클로드가 캘린더나 이메일 같은 외부 서비스에 접근하는 통로입니다."

### 적용 기준
- 챕터 내 첫 등장 시 패턴 1(일상어 병기)을 기본으로 적용합니다.
- 파트 도입부에서 핵심 용어는 패턴 2(대응 비유)로 한 번 더 풀어줍니다.
- 설명이 길어질 때는 패턴 3(한 줄 풀이)으로 본문 흐름을 유지합니다.
- 이미 앞 챕터에서 설명한 용어라도, 파트가 바뀌면 간단히 다시 설명합니다.

## 이탈 징후

이 패턴이 보이면 스타일에서 벗어난 것입니다:

1. 방법·팁·요령이 판단 기준 설명 없이 먼저 등장합니다.
2. 감정적 공감이나 동기 부여 문장이 논리 설명보다 앞섭니다.
3. 글을 읽고 난 뒤 "그래서 뭘 하면 되지?"만 남고, 판단 기준의 변화가 느껴지지 않습니다.
4. 스킬 코드 블록 앞에 "이 스킬에서 통제하는 기준"이 없이 바로 예시만 나열합니다.
5. 소제목이 기능명만으로 되어 있고 엠대시 뒤의 판단 기준이 빠져 있습니다.
6. 전문 용어가 설명 없이 등장합니다. 첫 등장 시 일상어 병기가 빠져 있습니다.
