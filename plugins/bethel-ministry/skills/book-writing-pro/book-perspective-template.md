# 작가 관점 선언 템플릿 (Book Perspective Template)

이 파일은 `book-writing-pro` 스킬의 Phase 1에서 참조하는 작가 관점 선언 작성 가이드다.
새 책 프로젝트를 시작할 때, 이 템플릿을 복사하여 `book-perspective-{프로젝트명}.md`로 저장한다.

> **핵심 원칙:** 이 파일이 없으면 Claude는 "일반적으로 좋은 글"을 쓴다. 이 파일이 있으면 "이 작가가 이 책에서 하고 싶은 말"을 쓴다.

---

## 1. 핵심 주장 (한 문장)

이 책을 한 문장으로 말하면?

```
[여기에 작성]
```

**작성 기준:**
- 독자가 이 한 문장을 읽고 "이 책이 무엇을 주장하는지" 알 수 있어야 한다
- 방법론이 아니라 관점을 담는다
- 예: ❌ "AI로 책을 쓰는 5단계 방법" → ✅ "AI 시대에 작가의 역할은 쓰는 것이 아니라 설계하는 것이다"

---

## 2. 차별 시각

기존 책들(경쟁서)과 다른 나의 시각은?

```
[여기에 작성]
```

**작성 기준:**
- "이 주제를 다른 사람들은 이렇게 말하지만, 나는 이렇게 본다"의 구조
- 최소 1개, 최대 3개까지 명시
- 예: "대부분의 AI 글쓰기 책은 '어떻게 쓰는가'에 집중한다. 이 책은 '무엇을 설계하는가'에 집중한다."

---

## 3. 독자에게 남길 판단 기준

독자가 이 책을 읽고 스스로 판단할 수 있게 되는 것은?

```
[여기에 작성]
```

**작성 기준:**
- "독자가 이 책을 다 읽고 나면, ~을 스스로 판단할 수 있다"의 형태
- 구체적 판단 상황을 포함한다
- 예: "AI가 만든 초안을 볼 때, 어디를 고쳐야 하는지 스스로 판단할 수 있다"

---

## 4. 반복 키워드·개념 정의 (Glossary)

이 책에서 자주 등장할 핵심 용어와 내 정의는?

| 용어 | 이 책에서의 정의 | 일반적 정의와의 차이 |
|------|-----------------|---------------------|
| [용어1] | [정의] | [차이점] |
| [용어2] | [정의] | [차이점] |
| [용어3] | [정의] | [차이점] |

**작성 기준:**
- 이 책에서 특별한 의미로 사용하는 용어만 정리한다
- 일반적 정의와 같으면 여기에 넣지 않는다
- 챕터 간 용어 일관성의 기준이 된다
- **5개 이하면 이 파일 안에 유지**, 6개 이상이면 `glossary-{프로젝트명}.md`로 분리하고 여기에는 "glossary 파일 참조"로만 표기한다

---

## 5. 판단 문장 비율 기준

이 책의 성격에 맞는 판단:설명 비율은?

```
판단 문장: [  ]%  |  설명·절차·사례: [  ]%
```

**장르별 참고 기준:**
- 실용서: 판단 30% + 설명·절차 70%
- 경험서: 판단 50% + 서사·사례 50%
- 입문서: 판단 20% + 개념 설명 80%
- 에세이: 판단 40% + 서사 60%

---

## 6. 쓰지 않을 것 (방향성)

이 책에서 의도적으로 배제하는 **접근법·범위·논조**는?

> **역할 구분:** 이 항목은 책의 방향성(무엇을 다루지 않는가, 어떤 논조를 피하는가)을 정의한다.
> 구체적인 금지 문장 패턴·표현은 `anti-patterns-{프로젝트명}.md` 별도 파일에서 관리한다.
> 프로젝트 고유 금지 패턴이 5개 미만이면 별도 파일 없이 이 항목만으로 운영한다.

### 다루지 않는 범위
```
[여기에 작성]
```

### 피해야 할 표현/논조
```
[여기에 작성]
```

### 경쟁서에서 흔한 접근법 중 의도적으로 배제할 것
```
[여기에 작성]
```

**작성 기준:**
- "이 책은 ~을 다루지 않는다"를 명확히 한다
- 경쟁서 분석 후 "다들 이렇게 하지만 나는 안 한다"를 정리한다
- 예: "도구별 기능 비교표를 넣지 않는다. 이 책은 도구 선택이 아니라 사용 기준을 다룬다."

---

## 7. 경험 vs 근거 구분 기준

내 경험에서 온 주장과 외부 근거의 비중은?

```
경험 기반 주장: [  ]%  |  외부 근거 기반 설명: [  ]%
```

**서술 톤 구분:**
- **경험 기반** → 1인칭 서술, 구체적 상황 묘사, "나는 ~했다" "강의에서 ~를 봤다"
- **근거 기반** → 출처 명시, 객관적 톤, "~에 따르면" "~연구에서"

---

## 사용법

1. Phase 1 기획 단계에서 사용자와 대화하며 위 7개 항목을 채운다
2. 최소 필수 항목: 핵심 주장, 차별 시각, 쓰지 않을 것 (3개)
3. 나머지는 집필 과정에서 보완 가능하다
4. 완성된 파일은 `book-perspective-{프로젝트명}.md`로 저장한다
5. Phase 3~7 전 단계에서 이 파일을 참조한다
