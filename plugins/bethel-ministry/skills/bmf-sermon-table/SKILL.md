# BMF 설교준비 도표(_02 시트) 채움

목적: 한 주의 설교준비 전 과정을 A4 가로 한 장 도표로 압축한다. 이 도표는 목사님의 설교 아카이브이자 설아클래스 교육 자료다. 셀 하나하나가 규격 분량을 가지며, 표 전체가 하나의 신학적 논리(메인아이디어의 전개)로 읽혀야 한다.

## 작업 철학 — 구조화가 아니라 맥락화

이 도표는 채워야 할 칸의 격자가 아니라, 한 주의 설교 준비가 하나의 신학적 논리로 응축된 기록이다. 목적 자체에 이미 명시돼 있듯 표 전체가 하나의 신학적 논리로 읽혀야 한다 — 셀 하나하나의 완성도보다, 표를 세로로 훑었을 때 메인아이디어 하나로 수렴하는가가 최종 기준이다(아래 품질 점검 마지막 항목과 동일).

같은 이유로, 빈 셀을 채울 때도 형식을 먼저 정하고 내용을 거기 욱여넣지 않는다 — 이전 단계 산출물(세션 산출물)이 실제로 말하는 맥락을 따라간 결과로 칸이 채워지는 순서를 지킨다.

### 판단 루프 — 목사님의 작업 성향 참조
규칙이 명시하지 않는 판단(제안 셀의 표현, 압축 방향 등)이 필요할 때는 볼트 파일 `40.설교/00.공통참조/목회자-작업성향-프로파일.md`를 참조해 그 성향을 기본 기준으로 삼는다(볼트 루트 Vault_BK 기준 경로 — 어느 프로젝트·폴더 스코프에서 세션을 열든 동일하게 참조 가능; 폴더 이동 가능성이 있으니 `.obsidian/` 판정 우선, 경로 하드코딩 금지). 새로운 개입이 나오면 작업 종료 후 그 볼트 파일에 사례를 추가한다.

## 입력

1. **세션 산출물** (필수): sermon-lectionary 작업 결과 md 파일 또는 대화 내용. 필요한 요소 — 메인아이디어, 사전적 의미, 복음적 전환, 성서정과 4본문 핵심 구절+해설, ABIT(A블록들·B·I·T), 3대지 개념·선포문, 주제문, 귀납 5단계(A~E), 네장면 요소(T/G·D·N·I·M·P1~P4), 1차라인 무브(5~6개)와 무브별 논지.
2. **부분 채움 시트** (선택): 목사님이 작업 중인 _02 도표의 PDF/PNG. Read로 판독한다.
3. **레퍼런스 HWPX** (선택): 완성된 _02 도표의 .hwpx 파일. 있으면 표 구조를 그대로 복원해 텍스트만 교체할 수 있다.

## 철칙: 기존 기입 우선

부분 채움 시트에 목사님이 이미 기입한 셀은 **세션의 제안과 다르더라도 시트가 이긴다.** 목사님이 도표에 적으면서 내린 선택(예: 트러블·그레이스 개념 교체, 주제문 2안 채택, 선포문 축약)이 최종 결정이다. 빈 셀만 채우고, 기입된 셀은 셀맵에 "유지"로 표기해 전체 기록을 완성한다. 기입 내용과 세션 결론이 충돌해 후속 셀 작성에 영향을 주면, 시트 쪽 선택을 기준으로 후속 셀을 작성한다.

## 작업 순서

1. 세션 산출물과 부분 채움 시트를 읽고, 채워진 셀 / 빈 셀 목록을 만든다.
2. `references/format-spec.md`를 읽는다 (판형 해부, 셀별 규격 분량, 최근 동향). 셀 작성은 반드시 이 규격을 따른다.
3. 빈 셀을 채운다. 작성 원칙:
   - 단문 스피치체. 만연체 금지.
   - 선포문·C6·주제문은 하나님/주님이 능동 주어 (선행적 은혜).
   - Being→Doing: 정체성이 행동에 선행. 도덕 훈화식 마무리 금지.
   - 원어는 표 전체에서 1~2회만, 괄호 병기.
   - 근거 없는 묘사·숫자 금지. 이단(구원파·신천지) 논리 배제.
   - 새로 제안하는 셀에는 `[제안]` 표시를 붙여 목사님이 한눈에 검토할 수 있게 한다.
4. **셀맵 md 생성**: 표의 읽기 순서(헤더 → 사전적 의미/복음적 전환 → 정과 4행 → ABIT → 개념/연역 → 귀납 → 네장면 → 본문 읽기)대로 셀 주소를 달아 저장. 파일명: `{YYYYMMDD}_{본문약칭}({메인아이디어})_02셀맵.md`. 저장 위치는 도표 원본과 같은 폴더.
5. **HWPX 생성** (기본 경로 — 내장 템플릿 사용):
   - 이 스킬에는 목사님의 공식 도표 템플릿이 내장되어 있다: `assets/template_02.hwpx` (27행×14열 병합 표, A4 가로 1쪽). 셀 주소 지도는 `references/format-spec.md`의 "템플릿 셀 주소" 절 참조.
   - 셀 내용을 cellmap.json(형식은 `scripts/fill_cells.py` 상단 주석 참조)으로 정리한 뒤 실행:
     `python3 scripts/fill_cells.py assets/template_02.hwpx cellmap.json {출력}.hwpx`
   - 스크립트는 표 구조(행·열·병합·크기)를 절대 변경하지 않고 각 셀의 기존 문단 스타일을 복제해 텍스트만 넣는다. 좌측 세로 메인아이디어 셀(r0,c0)은 `main_idea`에 글자를 한 자씩 배열로 넣는다.
   - 완성본 파일명: `{YYYYMMDD}_{본문약칭}({메인아이디어})_02.hwpx`. 같은 이름의 목사님 원본이 이미 있으면 `_02자동.hwpx`로 저장해 원본을 보호한다. 저장 위치는 해당 연도 BMF 폴더.
   - 분량 규격을 지키면 1쪽이 유지된다. 셀별 상한(format-spec.md)을 넘긴 텍스트는 넣기 전에 압축한다.
   - 사용자가 새 템플릿 .hwpx를 제공하면 내장 템플릿 대신 그것을 쓰고, 구조가 다르면 hwpx 스킬의 analyze_template.py로 셀 주소를 다시 뽑는다.
6. present_files로 산출물을 제시하고, `[제안]` 셀 목록을 요약해 검토를 요청한다.

## 품질 점검 (제출 전)

- [ ] 모든 셀이 규격 분량 안에 있는가 (특히 본문 읽기 무브: 150~250자)
- [ ] 선포문이 "주님은/하나님은 ~ 말씀하십니다" 형식인가
- [ ] 귀납 A~E가 현상→본문→은혜→전환→소망의 흐름인가
- [ ] P1~P4가 세상트러블→성경트러블→성경은혜→세상은혜 순서인가
- [ ] 본문 읽기 무브 순서가 1차라인과 일치하고 무브 키워드가 표기됐는가
- [ ] 기입된 셀을 덮어쓰지 않았는가
- [ ] 표 전체를 세로로 훑었을 때 메인아이디어 하나로 수렴하는가
