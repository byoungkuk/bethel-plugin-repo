## 페이스북 플랫폼 이해

스킬의 모든 단계는 아래 플랫폼 특성을 전제로 한다.

### 알고리즘 기반 노출

페이스북 뉴스피드 노출은 4가지 시그널로 결정된다.
- **관계(Relationship):** 자주 인터렉션하는 사람의 글이 우선 노출
- **콘텐츠 유형(Content type):** 사용자가 주로 반응하는 미디어 유형 우선
- **인기도(Popularity):** 좋아요·댓글·공유가 많은 글이 더 많이 노출
- **최신성(Recency):** 새 글이 피드 상단에 배치

핵심 원칙: 알고리즘은 **대화와 의미 있는 인터렉션을 촉발하는 게시물**에 가중치를 부여한다. 단순 좋아요보다 댓글과 공유가 노출에 더 큰 영향을 준다.

### 글의 수명과 승부 시간

- 포스팅 후 **1시간 내**에 초기 반응이 결정된다
- 1시간 내 반응이 약하면 알고리즘이 노출을 줄이고, 글은 사실상 사라진다
- 초기 댓글에 대한 작성자 응답이 추가 노출을 유발한다
- 공유가 발생하면 2차 도달이 시작되며, 글의 수명이 연장된다

### 긴 글의 현실적 조건

**긴 글이 읽히는 3가지 조건:**
1. **필자에 대한 신뢰** — 이전 글들이 쌓은 신뢰가 "이 사람 글은 길어도 읽을 가치가 있다"는 판단을 만든다
2. **'더보기' 너머의 보상** — 첫 3~4줄이 강력해서 '더보기'를 누를 수밖에 없게 만든다
3. **독자적 관점 또는 즉시 활용 가치** — 다른 곳에서 볼 수 없는 해석·경험·기준이 담겨 있거나, 복사해서 바로 쓸 수 있는 실용물이 포함되어 있다

**긴 글의 한계:** 200자 원고지 10매(약 2,000자)가 페이스북 긴 글의 실질적 상한이다. 실용 가이드형·템플릿 배포형은 프롬프트 목록 포함 시 초과 가능하나, 본문 설명은 상한 이내로 유지한다.

### '더보기'(See more) 메커니즘

페이스북 피드에서 긴 글은 첫 3~4줄(약 100~120자) 이후 '더보기' 버튼으로 접힌다. 이 접힌 지점 위의 텍스트가 **사실상의 제목이자 도입부**다. 독자는 이 부분만 보고 글 전체를 읽을지 결정한다.

### 서식 제한 환경

페이스북 일반 게시물에는 볼드, 기울임, 소제목, 구분선 등의 서식이 지원되지 않는다. 가독성 확보 수단:
- **행간 띄우기** (줄바꿈) — 주요 가독성 도구
- **번호·기호** (①②③, ─, ■, ▶ 등) — 실용 가이드형·교육 콘텐츠형에서 구조 분리 장치
- **이모지** (선택적) — 번호 이모지(1️⃣2️⃣)는 템플릿 내 가독성 도구로 허용
- **구분선** (------) — 본문과 실물(프롬프트/템플릿) 구간 분리 시 사용

## 글 유형 체계 (7가지)

홍작가 인기 글 7편 분석 결과, 실제 고반응 글은 7가지 유형으로 분류된다. 기존 5유형(경험 인사이트, 전문 해설, 시사·트렌드, 일상 성찰, 짧은 소통형)을 실제 반응 데이터 기반으로 재설계했다.

| 유형 | 핵심 목적 | 톤 | 분량 | 종결어미 | 공유 동기 |
|------|----------|-----|------|---------|----------|
| **관점 제시형** | 기준의 이동, 판단 제시 | 판단자 | 800~1,500자 | 합니다체 | 정보 가치 |
| **시스템 해설형** | 작동 원리·구조 설명 | 판단자 | 1,000~2,000자 | ~다체 또는 합니다체 | 실물 보상 |
| **경험 공유형** | 써보니 이렇더라 | 경험 공유자 | 800~1,500자 | 합니다체 | 대리 정리 |
| **교육 콘텐츠형** | 단계별 이해 확장 | 강사 | 1,000~2,000자 | 합니다체 | 교육 전달 |
| **실용 가이드형** | 따라하기·복사 가능한 목록 | 안내자 | 500~2,000자+ | ~다체/해라체 | 도구 확보 |
| **템플릿 배포형** | 실물 배포 | 안내자 | 맥락30%+실물70% | ~다체 | 도구 확보 |
| **프레임워크형** | 점검 기준 제공 | 코치 | 800~1,500자 | 합니다체 | 문제 해결 전달 |

**유형 선택 기준:**
- 반응 목표가 "공유 극대화"라면 → 실용 가이드형, 템플릿 배포형, 교육 콘텐츠형
- 반응 목표가 "전문성 각인"이라면 → 관점 제시형, 시스템 해설형
- 반응 목표가 "좋아요+공유 균형"이라면 → 경험 공유형, 프레임워크형

## 전체 흐름

```
Step 1: 주제·훅 설계 → Step 2: 구조 설계 → Step 3: 초안 작성 → Step 4: 리라이팅 → Step 5: 발행 준비
```

사용자의 상태에 따라 적절한 단계부터 시작한다.
- 주제만 있음 → Step 1부터
- 훅/구조 있음 → Step 3부터
- 초안 있음 → Step 4부터
- 다른 스킬에서 변환 → Step 2부터
- 메모·초안 텍스트를 붙여넣으며 "페이스북 글 써줘" → Step 3부터
- 프롬프트/가이드/템플릿 공유 요청 → Step 2부터 (실용 가이드형 또는 템플릿 배포형 자동 선택)

### Step 간 전환 규칙

각 Step 완료 후, 다음 Step으로 넘어가기 전에 사용자 확인을 받는다. 사용자가 "끝까지 진행해줘" 또는 "한 번에 해줘"라고 요청한 경우, 확인 없이 연속 진행한다.

## 공통 집필 원칙

### 종결어미 규칙

| 글 유형 | 기본 종결어미 |
|---------|-------------|
| 관점 제시형 | **합니다체** |
| 시스템 해설형 | ~다체 또는 합니다체 (사용자 선택) |
| 경험 공유형 | **합니다체** |
| 교육 콘텐츠형 | **합니다체** |
| 실용 가이드형 | **~다체/해라체** ("입력하면 된다", "요청한다") |
| 템플릿 배포형 | **~다체** |
| 프레임워크형 | **합니다체** |

**기본값은 합니다체다.** 실용 가이드형·템플릿 배포형은 ~다체/해라체가 기본이다.

**합니다체 작성 시 주의사항:**
- "~습니다"의 반복이 단조로워지지 않도록 문장 길이와 구조를 변화시킨다
- 질문문, 명사형 종결, 인용문, 괄호 부가설명으로 리듬을 만든다

**~다체와 합니다체 혼용은 금지한다.** 한 글 안에서 종결어미가 섞이면 톤이 흔들린다.

### 문체 기준

- 표준어 사용
- 문장은 12~20단어 내외 (모바일 스크롤 환경)
- **한 문장에는 하나의 정보, 하나의 판단만 담는다**
- 능동형 문장 기본
- 감정적 표현·감탄형 문장 지양
- 말하듯이 쓰되, 구어체에 빠지지 않는다
- 경험 공유형에서는 "~느껴집니다", "~좋더군요" 등 체감 표현 허용

### 페이스북 가독성 규칙

**행간 띄우기:**
- 2~3문장마다 한 줄 띄우기
- 주제가 전환될 때 두 줄 띄우기
- 한 문단(행간 사이 블록)은 최대 4문장
- 연속으로 5문장 이상 이어 쓰지 않는다

**시각적 리듬:**
- 짧은 문장(5~8단어)과 보통 문장(12~20단어)을 교차 배치
- 핵심 판단 문장은 단독 행으로 분리 (앞뒤 행간)
- 긴 문장 3개가 연속되지 않도록 한다

**리스트 표현 규칙 (유형별 차이):**
- 관점 제시형, 경험 공유형: 산문 중심. 리스트 최소화. 사용 시 ─ 기호 + 줄바꿈
- 교육 콘텐츠형, 프레임워크형: 번호 사용 허용 (1. 2. 3. 또는 ①②③)
- 실용 가이드형, 템플릿 배포형: - 기호 불릿 허용. 항목별 구분 명확하게

**여운 장치 — "..." 사용 규칙:**
- 글 전체에서 1~2회 이내로 제한
- 남용하면 글이 느슨해진다

**금지:**
- 과도한 이모지 (번호 이모지 외 사용자 지정이 아닌 한 사용하지 않음)
- 해시태그 본문 삽입 (본문 끝에만 배치)

### 글쓰기 금지어 규칙

모든 문장은 **판단·기준·결과**가 드러나야 한다. 단, 실용 가이드형·템플릿 배포형에서는 지시·안내 문장도 허용한다.

**① 과장형 형용사 금지:** 혁신적인, 획기적인, 창의적인, 강력한, 완벽한, 최고의
→ 무엇이 어떻게 다른지, 수치·사례로 설명한다.

**② 모호한 부사 금지:** 매우, 굉장히, 상당히, 꽤, 쉽게, 빠르게
→ 시간·단계·수치·조건으로 대체한다.

**③ 추측·완곡 표현 금지:** ~할 수 있습니다, ~일 수 있습니다
→ 단정형으로 서술한다. 단, 경험 공유형에서 성찰적 불확실성 허용.

**④ 불필요한 여유 연결어 금지:** 전반적으로 볼 때, 일반적으로 말하면
→ 근거 → 주장 구조로 직접 연결한다.

**⑤ 추상 명사 중심 문장 지양:** 중요성, 필요성, 가능성
→ 동사 중심 문장으로 전환.

**⑥ AI 흔적 조합 금지:** 부사 + 형용사 + 가능성 표현 + 추상 명사 패턴 금지.

### 문장 품질 기준 (GOOD/BAD 예시)

규칙보다 예시가 출력 품질에 더 큰 영향을 준다. 초안 작성 시 아래 쌍을 기준으로 삼는다.

| BAD (금지) | GOOD (기준) |
|-----------|------------|
| AI를 활용하면 쉽게 콘텐츠를 만들 수 있습니다 | AI에 원고 구조를 입력하면, 초안 생성 시간이 3시간에서 40분으로 줄어든다 |
| 혁신적인 방법으로 업무 효율을 높일 수 있습니다 | 반복 보고서 3건을 템플릿화하자, 주간 작성 시간이 절반이 됐다 |
| 이 도구는 매우 강력한 기능을 제공합니다 | 이 도구는 10장의 이미지를 한 번에 생성하고, 스타일을 3가지로 분기한다 |

### 금지 요소

- 정보 나열식 구성 (리스트만 던지고 해설 없는 글) — 단, 실용 가이드형 제외
- "오늘은 ~에 대해 이야기해 보겠습니다" 식의 메타 서술
- 결과물에 대한 감상형 표현
- 외부 링크 본문 삽입 (알고리즘이 외부 링크 게시물의 도달을 제한함)
- 참여를 강요하는 표현 ("좋아요 눌러주세요", "공유 부탁드립니다")

## 홍작가 글쓰기 스타일

이 스킬의 모든 글은 아래 스타일 기준을 최우선으로 적용한다.

**한 문장 정의:** 현상을 관찰해 문제를 재정의하고, 해결이 아닌 기준의 이동을 통해 독자의 사고 방식을 정렬하는 설명 중심 글쓰기. 단, 실용형(가이드·템플릿·프레임워크) 글에서는 기준 이동보다 **즉시 활용 가치**를 우선한다.

**어조:** 가르치지 않되 이끈다. 독자 위에 서지 않고 같은 문제를 함께 바라보는 위치를 취한다.

**톤 스펙트럼 (유형별):**
- 판단자: 기준을 세우고 방향을 제시 (관점 제시형, 시스템 해설형)
- 경험 공유자: 관찰과 체감을 나눔 (경험 공유형)
- 강사: 단계별로 풀어서 설명 (교육 콘텐츠형)
- 안내자: 지시+안내 (실용 가이드형, 템플릿 배포형)
- 코치: 진단하고 처방 (프레임워크형)

**핵심 규칙 5가지:**
1. 해결책을 서두르지 말고, 먼저 문제의 기준부터 다시 정의한다.
2. 기능·방법 설명보다, 왜 그 방식이 흔들리는지를 먼저 설명한다.
3. 사례는 결론을 증명하기 위한 도구로만 사용한다.
4. 독자의 행동을 바꾸려 하지 말고, 판단 기준을 이동시키는 데 집중한다.
5. 글의 마지막은 요약이 아니라 관점의 재정렬로 마무리한다.

**실용형 글(가이드·템플릿·프레임워크)에서는 규칙 1~4를 완화하고, "독자가 바로 써먹을 수 있는가"를 최우선 기준으로 적용한다.**

## 홍작가 문체 패턴 레퍼런스

**패턴 14가지의 상세 설명과 예시는 `references/writing-patterns.md`를 참조한다.** 이 파일은 페이스북, 블로그, 브런치, 책쓰기 스킬에서 공통 사용한다.

### 유형별 문체 패턴 적용 가이드

| 글 유형 | 필수 패턴 | 선택 패턴 |
|---------|----------|----------|
| 관점 제시형 | 양보+전환, 단독 판단문, 2문장 쌍, 대비 반복 | 체감 환산, 기준 명시 |
| 시스템 해설형 | 양보+전환, 질문형 전환, 작업 서사, 단독 판단문 | 기준 명시, 괄호 부가설명 |
| 경험 공유형 | 시간 대비 | 직접 인용, 괄호 부가설명 (자연스러운 흐름 우선) |
| 교육 콘텐츠형 | Before/After 변환 예시, 단독 판단문 | 양보+전환, 기준 명시, 체감 환산 |
| 실용 가이드형 | 라벨+핵심+부연 유닛 | 기준 명시 (패턴 강제 없음) |
| 템플릿 배포형 | 단독 판단문 1개 (맥락부) | 괄호 부가설명 (패턴 최소) |
| 프레임워크형 | 라벨+핵심+부연 유닛, 비유형 마무리 | 양보+전환, 단독 판단문 |

## Step 1: 주제·훅 설계 (Topic & Hook Design)

### 수집 항목

| 항목 | 질문 | 비고 |
|------|------|------|
| **주제** | 무엇에 대해 쓰는가? | |
| **훅(Hook)** | 스크롤을 멈추게 할 첫 문장은? | |
| **독자** | 누가 읽는가? | 기본값은 `references/audience-profile.md` 참조. 별도 지정 시 해당 프로필 우선 |
| **글 유형** | 7가지 중 어떤 유형인가? | 반응 목표에 따라 자동 추천 |
| **반응 목표** | 어떤 반응을 원하는가? | 좋아요 극대화 / 공유 극대화 / 전문성 각인 / 커뮤니티 유입 |
| **종결어미** | 합니다체(기본) / ~다체 | 유형별 기본값 자동 적용 |

### 필수 입력 강제 규칙

아래 3개 항목이 확인되지 않으면 Step 2로 넘어가지 않는다. **추측으로 채우지 않고 사용자에게 질문한다.**
- **주제** — 누락 시: "어떤 주제로 쓸까요?"
- **글 유형** — 누락 시: "어떤 반응을 원하시나요?" → 유형 자동 추천
- **핵심 메시지** (1문장) — 누락 시: "이 글에서 가장 전달하고 싶은 한 문장은?"

나머지 항목(독자, 반응 목표, 종결어미)은 기본값 자동 적용이 가능하므로 누락 시 기본값을 쓰고 진행한다.

### 훅 설계 기준

**훅 후보 생성 시 `references/hook-examples.md`를 참조한다.** 9가지 패턴, 실제 작동한 원문, 실패 패턴 6가지, 설계 체크리스트가 포함되어 있다.

### 산출물

수집 항목 요약 + 훅 후보 3개를 제시. 사용자 확인 후 Step 2.

## Step 2: 구조 설계 (Structure Design)

### 유형별 구조 패턴

**관점 제시형 — 4블록 점층 (800~1,500자, 합니다체):**
```
훅: 선언+부정 긴장 (2~3문장)
── 더보기 ──
블록1: 환경/현상 관찰 — 수치 체감 환산 (3~5문장)
블록2: 문제 재정의 — 양보+전환으로 기준 전환 (3~5문장)
블록3: 자기 작업 공개 — 작업 서사, 대비 반복 (5~8문장)
블록4: 미래 방향/확장 (3~5문장)
마무리: 대비 압축 1문장 또는 2문장 쌍 판단문
```

**시스템 해설형 — 질문-응답 체인 (1,000~2,000자, ~다체 또는 합니다체):**
```
훅: 제목형 + (댓글에 자료 제공) + 양보+전환 (3~4문장)
── 더보기 ──
블록1: 문제 제기 — 질문형 전환으로 진입 (3~5문장)
블록2: 시스템 해설 — 판단 기준 중심, 기준 명시 (5~8문장)
블록3: 작업 서사 — 실제 입력물 원문 공개 (5~8문장)
마무리: 단독 판단문 기준 재정렬 (1~2문장)
```

**경험 공유형 — 작업 순서 서사 (800~1,500자, 합니다체):**
```
훅: 경험 진입 (제목이 훅 역할, 본문 1~2문장)
── 더보기 ──
블록1: 기존 방식 — 장점 인정 + 한계 체감 (3~5문장)
블록2: 새로운 방식 — 차이 발견, 구체적 비교 (3~5문장)
블록3: 조합/보완 — 각각의 역할 정리 (3~5문장)
마무리: 역할 정리 또는 경험 요약 (2~3문장)
```
주의: 판단을 강제하지 않는다. "좋더군요" 톤.

**교육 콘텐츠형 — 점층 구조 (1,000~2,000자, 합니다체):**
```
훅: 질문+1줄 답 (2~3문장)
── 더보기 ──
1단계: 원리 (3~5문장)
2단계: 재정의 — 통념 뒤집기 (3~5문장)
3단계: 구분 + Before/After 변환 예시 3~5개 (5~10문장)
4단계: 심화 (3~5문장)
5단계: 기준 — 실전 적용 조건 (3~5문장)
6단계: 결론 — 3단계 점층 마무리
```

**실용 가이드형 — 규칙→목록→팁→예시 (500~2,000자+, ~다체/해라체):**
```
훅: 실용물 선언 (1~2문장)
── 더보기 ──
파트1: 기본 규칙 (2~4문장)
파트2: 항목별 목록 — 추천 상황 + 사용 프롬프트/예시
파트3: 추가 팁 (2~4항목)
파트4: 완성 예시 — 그대로 복사 가능한 실전 프롬프트 1개
```

**템플릿 배포형 — 맥락30%+실물70%:**
```
훅: 공유 선언 (1~2문장)
── 더보기 ──
맥락 (30%): 배경 + 단독 판단문 1개
───────── (구분선)
실물 (70%): 프롬프트 템플릿 전문
───────── (구분선)
마무리: 커뮤니티 유입 안내 (선택)
```

**프레임워크형 — 진단→원칙→항목→비유 (800~1,500자, 합니다체):**
```
훅: 진단형 (공감 + 원인 재지정) (2~3문장)
── 더보기 ──
도입: 해결 방향 선언 (2~3문장)
본론: ①~⑤ 번호 항목 — 라벨+핵심+부연 3줄 유닛
마무리: 비유형 압축 + 행동 제안 (2~3문장)
```

### 산출물

아웃라인 + '더보기' 전 텍스트 + 마무리 방향. 사용자 확인 후 Step 3.

| 유형 | 마무리 방식 |

| 프레임워크형 | 비유형 압축 + 행동 제안 |

### 출력 슬롯 템플릿 (초안은 반드시 이 구조를 따른다)

Step 2에서 선택한 유형별 구조 패턴을 슬롯 템플릿으로 강제 적용한다. AI는 각 슬롯을 순서대로 채우며, **슬롯을 건너뛰거나 순서를 바꾸지 않는다.** 슬롯 안의 내용은 자유롭게 작성하되, 슬롯 경계와 순서는 변경하지 않는다.

- [ ] "매우", "쉽게", "빠르게" 등 모호한 부사 포함 여부

## Step 4: 리라이팅 (Rewriting)

> **리라이팅 원본 보존 원칙** (`writing-principles.md` 참조): 리라이팅은 내용을 바꾸지 않는다. 같은 내용을 더 정확하고 읽기 좋은 문장으로 다듬는다. 구조 변경이 필요하면 별도 제안으로 분리한다.

### 역할 전환 선언 (리라이팅 진입 조건)

이 단계에서는 초안 작성자의 시점을 내려놓는다. 편집자로서, 작성 의도를 참고하지 않고 **독자 시점에서만 판단**한다. "왜 이렇게 썼는가"가 아니라 "독자가 읽었을 때 작동하는가"를 기준으로 점검한다. 이 선언 없이 체크리스트를 돌리면, 구조적 문제보다 표현만 다듬는 쪽으로 흐른다.

### 리라이팅의 핵심 원칙

리라이팅은 "문장을 다듬는 작업"이 아니다. **글의 설계를 점검하는 작업**이다.

1. 이 글이 전달하려는 기준(판단) 또는 실용 가치는 무엇인가?
2. 그것이 글의 구조 안에서 제대로 작동하고 있는가?
3. 유형에 맞는 문체 패턴이 적절한 위치에서 작동하고 있는가?
4. 반응 목표에 맞는 공유 장치가 설계되어 있는가?

### 점검 체계 (6가지)

**`references/rewriting-checklist.md`를 로드하여 점검 1~6을 순서대로 진행한다.**
- 점검 4(금지어 대조)에서는 `references/anti-patterns.md`를 교차 참조
- 점검 6(오디언스 대조)에서는 `references/audience-profile.md`를 교차 참조
- 점검 완료 후 변경 요약 표준 포맷(rewriting-checklist.md 내 포함)으로 정리

### 발행 타이밍

- 한국 기준 최적: 오전 8~9시, 저녁 7~9시, 주말 낮 12~1시
- 포스팅 직후 30분간 댓글 응답 가능한 시간에 발행

## 분량 통제 규칙

### 원문 보존 강도 레벨

사용자의 요청 동사에 따라 보존 강도를 자동 판별한다. 레벨을 혼동하지 않는다.

| 레벨 | 트리거 | 허용 범위 | 금지 행위 |
|------|--------|----------|----------|
| **L1 교정** | "다듬어줘", "교정해줘", "수정해줘" | 맞춤법·띄어쓰기·종결어미 통일만. 문장 구조 변경 금지 | 문장 분리·병합, 새 문장 추가, 문단 재배치 |
| **L2 정리** | "정리해줘", "깔끔하게", "보강해줘" | 문장 분리·접속 보강, 지정 부분 내용 추가. 미지정 부분 원본 유지 | 구조 재배치, 슬롯 순서 변경, 미지정 부분 수정 |
| **L3 리라이팅** | "리라이팅해줘", "다시 써줘" | 구조 재배치·문장 교체·패턴 적용 허용 | 분량 120% 초과 (초과 시 사유 확인) |

- 사용자가 레벨을 명시하지 않으면 트리거 동사로 자동 판별한다
- 유형별 분량 상한 초과 시 사용자에게 먼저 확인한다
