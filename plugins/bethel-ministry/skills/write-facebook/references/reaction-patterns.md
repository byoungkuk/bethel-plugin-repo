# 홍작가 페이스북 반응 패턴 레퍼런스

이 문서는 홍작가의 실제 인기 글 7편을 분석해 추출한 반응 패턴이다. SKILL.md의 글 유형별 구조, 훅 설계, 공유 전략의 근거 자료로 사용한다.

## 1. 분석 대상 글 7편 반응 데이터

| # | 제목 (요약) | 유형 | 좋아요 | 공유 | 좋아요:공유 비율 |
|---|------------|------|--------|------|----------------|
| 글1 | AI 글쓰기가 달라지고 있습니다 | 관점 제시형 | 200+ | 80+ | 2.5:1 |
| 글2 | 클로드의 글쓰기 워크플로우 스킬 | 시스템 해설형 | 80+ | 40+ | 2:1 |
| 글3 | 챗GPT와 제미나이를 함께 쓰며 | 경험 공유형 | 300+ | 150+ | 2:1 |

| 글5 | 나노바나나 프로 한글 텍스트 가이드 | 실용 가이드형 | 400+ | 200+ | 2:1 |

## 2. 반응 공식: 공유수를 결정하는 3가지 변수

7편 분석 결과, 공유수는 다음 3가지 변수에 의해 결정된다.

**① 즉시 활용도** — 복사해서 바로 쓸 수 있는가
- 높음: 글5(프롬프트 목록), 글6(템플릿), 글4(변환 예시)
- 낮음: 글1(관점), 글2(시스템 설명)

**② 진입 장벽** — 전문 지식 없이 이해되는가
- 가장 낮음: 글5(따라하기), 글4(AI 질문은 누구나 해당)
- 가장 높음: 글2(커스텀 스킬 전제)

**③ 전달 동기** — "이거 너도 봐" 충동이 드는가
- 도구 확보: "이거 저장해둬야 해" (글5, 글6)
- 교육 전달: "이거 너도 알아야 해" (글4)
- 대리 정리: "내 고민을 정리해줬네" (글3, 글7)
- 정보 가치: "이 관점이 유용하다" (글1)
- 실물 보상: "댓글에서 파일 받는다" (글2)

**핵심 발견:** 판단 강도와 공유수는 반비례한다. 관점이 강한 글(글1, 글2)은 좋아요는 받지만 공유는 제한적. 즉시 활용도가 높은 글(글4, 글5)이 공유를 폭발시킨다.

## 4. 유형별 본론 구조 레퍼런스

### 4-1. 관점 제시형 4블록 점층 (글1)
```
블록1: 환경 변화 — 팩트 나열, 수치 체감 환산
블록2: 문제 재정의 — "모델이 좋아졌다고 글이 좋아지는 건 아닙니다"
블록3: 자기 작업 공개 — "지금 제가 쓰는 방식은 이렇습니다"
블록4: 미래 방향 — 에이전틱 시스템, 메모리 축적
```
특징: 관찰→재정의→실천→확장. 각 블록이 이전 블록보다 한 단계 깊어진다.

### 4-2. 시스템 해설형 질문-응답 체인 (글2)
```
블록1: 문제 제기 — 왜 프롬프트만으로 안 되는가
블록2: 시스템 해설 — 5단계 각각의 판단 기준
블록3: 작업 서사 — 메모 → 완성 글 실제 과정 (원본 공개)
블록4: 기준 재정렬 — 1문장 마무리
```
특징: 질문이 섹션 제목 역할. 실제 입력물(메모 텍스트) 원본 공개가 차별점.

### 4-3. 경험 공유형 작업 순서 서사 (글3)
```
블록1: 기존 방식 — 장점 인정 + 한계 체감
블록2: 새로운 방식 추가 — 차이 발견
블록3: 문제 발생 — 새 방식의 한계 → 기존 방식으로 보완
블록4: 정리 — 역할 분담 결론
```
특징: 시간순 경험 흐름 자체가 논증. 판단을 강제하지 않음. "좋더군요"처럼 경험을 나누는 톤.

### 4-4. 교육 콘텐츠형 점층 구조 (글4)
```
1단계: 원리 — 왜 이것이 중요한가
2단계: 재정의 — 통념을 뒤집기 ("못하는 게 아니라 다른 것이다")
3단계: 구분 — 핵심 차이를 명확히 분리
4단계: 심화 — 차이의 구조적 원인
5단계: 기준 — 실전 적용 조건 제시
6단계: 결론 — 행동/관점 변화로 마무리
```
특징: 번호 매긴 단계별 구조. 각 단계가 이전의 질문에 답하며 다음 질문을 열어감. Before/After 변환 예시가 공유 핵심 동인.

### 4-5. 실용 가이드형 (글5)
```
파트1: 기본 규칙 (1~2가지 핵심 원칙)
파트2: 항목별 목록 (각각 추천 상황 + 사용 프롬프트)
파트3: 추가 팁 (자주 겪는 문제 해결)
파트4: 완성 예시 (그대로 복사 가능한 실전 프롬프트)
```
특징: 서사 없음, 관점 없음, 정보 전달에 집중. 복사→붙여넣기 가능한 실물이 본문 대부분.

### 4-6. 템플릿 배포형 (글6)
```
파트A (30%): 맥락 설명 — 왜 이 템플릿이 필요한가 + 단독 판단문 1개
파트B (70%): 실물 — 복사해서 바로 쓸 수 있는 프롬프트 템플릿 전문
```
특징: 설명보다 실물이 압도적으로 많음. 좋아요<공유 현상 발생 (감상보다 확보 동기).

### 4-7. 프레임워크형 (글7)
```
도입: 문제 진단 + 해결 방향 선언
본론: 번호 항목 (각각 "라벨+핵심+부연" 3줄 유닛)
마무리: 비유로 핵심 압축 + 행동 제안
```
특징: 글5(목록 나열)과 글4(교육 점층)의 중간. "이 기준으로 점검하라"는 프레임워크 제공.

7편에서 추출한 마무리 유형:

| 패턴 | 예시 | 해당 글 |
|------|------|---------|

## 6. 새로 발견된 문체 패턴

기존 스킬의 8가지 패턴 외에 7편 분석에서 추가 발견된 패턴:

### 패턴 9: 2문장 쌍 판단문 (Paired Judgment)
기존 단독 판단문이 1문장인데, 2문장이 쌍으로 더 강하게 작동하는 경우.

좋은 예:
- "문제는 AI가 아니었습니다. / 작업 방식이었습니다." (글1)
- "프롬프트 한 줄은 주문입니다. / 워크플로우는 설계입니다." (글1)

적용 규칙:
- 부정+긍정, 문제+원인, A가 아니라+B이다 구조
- 각 문장을 별도 행에 배치
- 글 전체에서 1~2회. 남용하면 효과가 약해진다

### 패턴 10: 대비 반복 (Repeated Contrast)
같은 대비를 다른 표현으로 2~3회 반복해서 핵심 메시지를 각인시킨다.

좋은 예 (글1에서 같은 대비의 3회 반복):
- "프롬프트 한 줄은 주문입니다. 워크플로우는 설계입니다."
- "프롬프트 시대에는 AI가 글을 썼습니다. 워크플로우 시대에는 제가 글을 설계합니다."
- "주도권의 위치가 다릅니다."

적용 규칙:
- 관점 제시형, 프레임워크형 글에서 사용
- 같은 핵심을 표현만 바꿔서 반복. 글 초반/중반/후반에 분산 배치
- 3회 이상은 지루해진다

### 패턴 11: 체감 환산 (Tangible Conversion)
추상적 수치를 독자가 체감할 수 있는 단위로 변환한다.

좋은 예:
- "100만 토큰이면 소설 5~10권 분량을 한 세션에서 다룹니다. (A4 2000~3000 p)" (글1)

적용 규칙:
- 기술 수치를 일상 단위(권, 장, 시간, 인원)로 변환
- 괄호 안에 추가 환산을 넣어 이중 체감 제공
- 관점 제시형, 교육 콘텐츠형에서 사용

### 패턴 12: Before/After 변환 예시 (Transformation Example)
같은 입력을 변환 전/후로 나란히 보여준다.

좋은 예 (글4):
- "이 기능 뭐예요?" → "이 기능이 콘텐츠 기획 단계에서 어떤 역할을 하는지, 초보 사용자를 기준으로 단계별로 설명해 주세요."

적용 규칙:
- 교육 콘텐츠형에서 핵심 장치
- 3~5개 예시를 나열하되 각각 다른 상황을 커버
- 변환 후 문장은 독자가 그대로 복사해서 쓸 수 있어야 한다

### 패턴 13: 비유형 마무리 (Metaphor Close)
핵심 대비를 일상어 비유로 압축해서 마무리한다.

좋은 예:
- "프롬프트는 주문이 아니라 레시피입니다. 재료가 같아도, 순서와 구조가 다르면 결과는 완전히 달라집니다." (글7)

적용 규칙:
- 프레임워크형, 교육 콘텐츠형에서 사용
- 비유는 독자의 일상에서 가져온다 (요리, 건축, 운동 등)
- 비유 뒤에 1문장으로 적용 방향을 안내

### 패턴 14: 라벨+핵심+부연 유닛 (Label-Core-Detail Unit)
번호 항목을 3줄로 통일된 포맷으로 작성한다.

좋은 예 (글7):
- "① 대상(Subject) / 무엇을 그릴 것인가를 명확히 지정합니다. / 인물, 사물, 캐릭터의 핵심 특징을 먼저 고정합니다."

적용 규칙:
- 프레임워크형, 실용 가이드형에서 사용
- 라벨: 한 단어 또는 짧은 명사구
- 핵심: 그 항목이 무엇인지 1문장
- 부연: 왜 중요한지 또는 어떻게 적용하는지 1문장

## 7. 톤 스펙트럼

7편에서 발견된 합니다체 내부의 톤 변주:

| 톤 | 특징 | 해당 유형 |
|-----|------|----------|
| 판단자 | 기준을 세우고 방향을 제시 | 관점 제시형, 시스템 해설형 |
| 경험 공유자 | 관찰과 체감을 나눔. "~느껴집니다", "~좋더군요" | 경험 공유형 |
| 강사 | 단계별로 풀어서 설명. "~기 때문입니다" | 교육 콘텐츠형 |
| 안내자 | 지시+안내. "~하면 된다", "~로 입력한다" | 실용 가이드형, 템플릿 배포형 |
| 코치 | 진단하고 처방. "문제는 ~에 있습니다", "~를 확인해보시기 바랍니다" | 프레임워크형 |

## 8. 공유 설계 전략 매트릭스

글을 쓸 때 목표 반응에 따라 다른 전략을 적용한다.

| 목표 | 전략 | 핵심 장치 | 기대 반응 |
|------|------|----------|----------|
| 좋아요 극대화 | 보편 공감 + 낮은 진입 장벽 | 경험 서사, 체감 비교 | 좋아요 300+ |
| 공유 극대화 | 즉시 활용 가능한 실물 포함 | 프롬프트 목록, 템플릿, 변환 예시 | 공유 200+ |
| 좋아요+공유 균형 | 교육 가치 + 실용 예시 병행 | 원리 설명 + Before/After | 좋아요 300/공유 200 |
| 전문성 각인 | 독자적 관점 + 기준 제시 | 양보+전환, 단독 판단문, 재정의 | 좋아요 200/공유 80 |
| 커뮤니티 유입 | 실물 배포 + 참여 경로 | 댓글 자료, 단톡방 안내 | 공유 > 좋아요 |
