# 나노바나나 인포그래픽 프롬프트 생성 스킬

강의 원고·교안의 본문 텍스트를 나노바나나 프로(Gemini 3 Pro Image)용 **슬라이드 1장 인포그래픽** 이미지 프롬프트로 변환하는 스킬이다.

**핵심 흐름**: 원고 텍스트 입력 → 핵심 추출·압축 → 유형×스타일 판단 → 슬라이드 1장 프롬프트 출력

나노바나나 프로는 고급 추론 기능으로 사실 정보 기반 인포그래픽을 직접 생성하는 데 강점이 있다. 프롬프트에 "인포그래픽"을 반드시 포함하고, 구도·배치 방향 중심으로 지시하면 가장 좋은 결과를 얻을 수 있다.

**참조 파일 안내**:
- `references/style-templates.md` — 스타일 A~F별 상세 템플릿 (유형별 변형 포함)
- `references/examples.md` — 스타일별 실전 예시 (원고→추출→프롬프트 변환)

프롬프트를 작성하기 전에 반드시 해당 스타일의 템플릿과 예시를 참조한다.

---

## 시각 스타일 기본값 (모든 유형·스타일 공통)

모든 프롬프트에 아래 시각 규칙을 반드시 포함한다.

| 항목 | 기본값 |
|------|--------|
| 배경 | #FFFFFF (Solid pure white, flat color, no shadows) |
| 폰트 | Noto Sans KR |
| 캐릭터 | 스틱맨(stickman) — 필요할 때만 사용 |
| 화면 비율 | 16:9 가로형 |
| 스타일 | 플랫 디자인, 미니멀, 깔끔한 선과 도형 중심 |
| 색상 체계 | 주제별 2~3색 조합, 채도 중간, 흰 배경 대비 명확 |

> **사이즈 지정**: 나노바나나 프로는 픽셀이 아닌 **비율**로 지정한다. 프롬프트에 `가로세로 비율 16:9`로 명시. 필요시 `4:3`, `1:1`, `9:16(세로형)` 등으로 변경 가능.

## 텍스트 규칙 통합표

나노바나나 프로는 한글 렌더링이 가능하지만, 글자 수가 많으면 오탈자·깨짐이 발생할 수 있다. 아래 기준을 일관 적용한다.

| 요소 | 글자 수 기준 | 비고 |
|------|-------------|------|
| 슬라이드 제목 | 12자 이내 | 상단 제목 영역 |
| 항목 키워드 | 8자 이내 (최대 12자) | 카드·단계·가지의 메인 레이블 |
| 부가 설명 | 15자 이내 | 아이콘 옆 또는 카드 내 한 줄 설명 |
| 불릿 설명 (장면형) | 25자 이내 | 장면형 카드 하단 불릿 포인트 |
| 하위 태그 | 6자 이내 | 키워드 아래 보조 태그 |
| 전체 항목 수 | 6개 이내 | 카드·단계·가지 등 메인 요소 |

**추가 규칙**:
- 키워드 중심: 문장이 아닌 명사·동사 키워드로 압축
- 영문 병기 고려: 핵심 용어는 한글(영문) 병기하면 렌더링 안정성 향상
- 생성 후 한글 확인 필수

## 인포그래픽 유형 3가지

### 1. 요약형 (Summary)

하나의 소주제를 핵심 포인트 3~5개로 압축해 한눈에 보여준다.

- 상단: 제목(소주제명)
- 중앙: 핵심 포인트를 아이콘+키워드로 배치
- 적합한 원고: 개념 설명, 원칙·팁 나열, 특징 정리

### 2. 구조형 (Structure)

요소 간 관계·위계·비교를 시각적 구조로 표현한다.

- 상단: 제목
- 중앙: 비교표·매트릭스·계층 다이어그램·관계도
- 적합한 원고: 개념 비교, 분류 체계, 프레임워크 설명, 장단점 대비

### 3. 프로세스형 (Process)

순서가 있는 단계·흐름을 시각적으로 표현한다.

- 상단: 제목
- 중앙: 좌→우 단계 흐름, 화살표 연결
- 적합한 원고: 절차 안내, 워크플로우, 단계별 가이드, 실습 순서

---

## 시각화 스타일 6가지

유형(요약형·구조형·프로세스형)과 별개로, **시각화 스타일**을 선택한다. 같은 유형이라도 스타일에 따라 완전히 다른 인포그래픽이 나온다.

| 스타일 | 핵심 | 적합한 원고 |
|--------|------|------------|
| A. 다이어그램형 | 아이콘+키워드+카드/화살표 도식 | 개념 구조, 분류, 학습 단계 |
| B. 장면형 | 스틱맨이 카드 안에서 상황을 행동으로 연기 | 문제 상황, 사례, 실수, 시나리오 |
| C. 비교형 | 좌우 대비 또는 Before/After 분할 | 장단점, 변화 전후, A vs B |
| D. 타임라인형 | 시간축 위에 이벤트·단계 배치 | 발전 과정, 로드맵, 역사, 일정 |
| E. 데이터형 | 숫자·비율·그래프를 전면 배치 | 통계, 성과 수치, 비율 비교 |
| F. 마인드맵형 | 중심에서 방사형 확산 | 하나의 개념에서 파생, 카테고리 분류 |

> **상세 템플릿**은 `references/style-templates.md`에서 확인한다. 각 스타일별로 유형 변형(요약형/구조형/프로세스형 적용) 템플릿이 제공된다.

## 스타일 자동 추천 로직

원고를 분석한 뒤 **2~3개 스타일을 추천**하고, 각 추천에 해당하는 완성 프롬프트를 함께 제공한다.

### 추천 판단 기준

| 원고에서 감지되는 신호 | 추천 스타일 (우선순위) |
|---------------------|---------------------|
| 개념·구조·분류·기술 설명 | ①다이어그램형 ②마인드맵형 |
| 문제 상황·사례·시나리오·경험담 | ①장면형 ②비교형 |
| 장단점·변화 전후·A vs B | ①비교형 ②장면형 |
| 시간 순서·발전 과정·로드맵 | ①타임라인형 ②다이어그램형 |
| 숫자·통계·비율·성과 데이터 | ①데이터형 ②비교형 |
| 하나의 핵심에서 여러 요소 파생 | ①마인드맵형 ②다이어그램형 |
| 단계별 절차 (추상적) | ①다이어그램형 ②타임라인형 |
| 단계별 절차 (구체적 행동 묘사) | ①장면형 ②다이어그램형 |
| 비포/애프터 + 숫자 포함 | ①비교형 ②데이터형 ③장면형 |

### 유형과 스타일 충돌 시 판단 기준

하나의 원고에 여러 성격이 섞여 있을 때, 아래 우선순위로 판단한다.

| 상황 | 판단 기준 |
|------|----------|
| 비교 내용 + 시간 순서 | 시간축이 명확하면 → 프로세스형+타임라인형. 비교 관점이 주이면 → 구조형+비교형 |
| 나열 + 순서 | 순서가 필수이면 → 프로세스형. 순서 없이 병렬이면 → 요약형 |
| 구조 설명 + 숫자 데이터 | 숫자가 핵심 메시지이면 → 요약형+데이터형. 구조가 핵심이면 → 구조형+다이어그램형 |
| 사례 나열 + 비교 | 대비 축이 명확하면(A vs B) → 구조형+비교형. 독립 사례 나열이면 → 요약형+장면형 |

**원칙**: 원고의 **핵심 메시지가 무엇을 전달하려는지**를 기준으로 판단한다. "이 슬라이드를 본 사람이 무엇을 가져가야 하는가?"에 대한 답이 유형과 스타일을 결정한다.

## 프롬프트 생성 워크플로우

### 기본 동작 모드

**기본값은 "한 번에 출력"이다.** 추출 결과 + 스타일 추천 3개 + 각 프롬프트를 한 번의 응답에 모두 제공한다. 사용자가 "단계별로 확인하면서 진행해줘" 또는 "추출 결과 먼저 보여줘"라고 요청할 때만 단계를 분리한다.

### Step 1: 원고 텍스트 수신

사용자가 단락·소주제 단위(수백 자)의 강의 원고 또는 교안 텍스트를 입력한다.

확인할 사항:
- **원고 텍스트**: 시각화할 본문 (필수)
- **유형 지정**: 요약형·구조형·프로세스형 중 택1 (선택 — 미지정 시 자동 판단)
- **스타일 지정**: 6가지 중 택1 (선택 — 미지정 시 자동 추천)
- **추가 요청**: 색상, 캐릭터, 비율 변경, 강조 포인트 등 (선택)

### Step 2: 핵심 추출·압축

원고에서 슬라이드 1장에 담을 핵심을 추출한다. 이 단계가 스킬의 핵심이다.

**추출 규칙**:
1. 원고의 **중심 주장·핵심 메시지**를 1문장으로 파악한다
2. 이를 뒷받침하는 **하위 포인트 3~5개**를 추출한다
3. 각 포인트를 **한글 8자 이내 키워드**로 압축한다
4. 슬라이드 제목을 **12자 이내**로 만든다

**압축 전략**:
- 원고에 나열된 항목이 있으면 → 그대로 키워드화
- 원고가 설명 중심이면 → 핵심 개념어 추출
- 원고에 순서·절차가 있으면 → 단계별로 분리
- 원고에 비교·대비가 있으면 → 비교 축 추출

### Step 3: 유형·스타일 판단

사용자가 유형/스타일을 지정하지 않은 경우, 추출된 내용의 성격으로 자동 판단한다.

| 원고 내용의 성격 | 판단 유형 |
|-----------------|----------|
| 핵심 포인트·원칙·팁 나열 | 요약형 |
| 개념 비교, 분류, 관계 설명 | 구조형 |
| 절차, 단계, 흐름, 순서 | 프로세스형 |

스타일은 위 "스타일 자동 추천 로직"에 따라 2~3개를 추천한다.

### Step 4: 프롬프트 작성

`references/style-templates.md`의 해당 스타일 템플릿을 참조하여 한국어 프롬프트를 작성한다.

**프롬프트 공통 구조**:

```
[유형] [스타일] 인포그래픽 이미지를 생성해줘.

제목: "OOO"

[콘텐츠 영역 — 스타일별 템플릿 참조]

시각 스타일:
- 배경: #FFFFFF (Solid pure white, flat color, no shadows)
- 폰트: Noto Sans KR
- 스타일: 플랫 디자인, 미니멀, 깔끔한 선과 도형
- 색상: [주제별 팔레트에서 선택]
- 가로세로 비율: 16:9
[캐릭터가 필요한 경우] - 캐릭터: 스틱맨(stickman)
```

### Step 5: 출력

**스타일 미지정 시** (기본 동작): 추출 결과 + 3개 스타일 추천 + 각 프롬프트를 한 번에 출력한다.

```
[추출 결과]
- 제목: OOO
- 유형: OO형
- 핵심 포인트: ...

[스타일 추천 — 3개 프롬프트 동시 제공]

추천1: OO형 — 이유 설명
(프롬프트 코드블록)

추천2: OO형 — 이유 설명
(프롬프트 코드블록)

추천3: OO형 — 이유 설명
(프롬프트 코드블록)
```

**스타일 지정 시**: 해당 스타일 프롬프트 1개만 출력한다.

프롬프트 출력 후 반드시 안내:
- "생성된 이미지에서 한글 텍스트가 정확한지 확인하세요. 오류 시 해당 텍스트만 수정 요청하거나 새로 생성하는 것이 낫습니다."
- 수정 가능 항목: 색상, 항목 추가/삭제, 스타일 전환, 비율 변경 등

## 프롬프트 작성 원칙

1. **첫 문장에 유형+스타일 필수**: `[유형] [스타일] 인포그래픽 이미지를 생성해줘.` 형식으로 시작
2. **한국어로 작성**: 프롬프트 전체를 한국어로
3. **비율로 사이즈 지정**: `16:9` 기본, 필요시 변경
4. **텍스트 기준**: 통합표 참조 (제목 12자, 키워드 8자, 부가 설명 15자, 항목 6개 이내)
5. **색상 명시**: 주색은 헥스코드, 보조색은 팔레트 참조
6. **구도 중심 지시**: 배치 방향·위치를 명확히, 세밀한 수치는 지양
7. **시각 스타일 블록 필수**: 모든 프롬프트 하단에 공통 스타일 포함
8. **시각 밀도 확보**: 아래 밀도 보강 규칙을 반드시 적용

**지시 수준 가이드**: 구도·색상·배치 방향 수준으로 지시한다. CSS 수준의 수치는 피한다.

| 적절한 지시 | 피해야 할 지시 |
|-------------|---------------|
| "가로로 균등 배치" | "카드 간 8px 간격" |
| "둥근 모서리 카드" | "border-radius: 12px" |
| "연한 파랑 배경" | "#E3F2FD, opacity 0.8" |
| "굵은 화살표로 연결" | "화살표 두께 3px" |

## 시각 밀도 보강 규칙

16:9 가로 비율에서 슬라이드로 바로 쓸 수 있는 밀도를 확보하려면, 프롬프트 작성 시 다음 3가지 보강 장치를 반드시 적용한다.

### 보강 1: 하위 정보 레이어 추가

각 포인트에 **하위 태그·부가 설명·세부 항목**을 1~3개씩 붙여 정보량을 늘린다.

| 보강 전 | 보강 후 |
|--------|--------|
| "SKILL.md" — 문서 아이콘 | "SKILL.md" — 문서 아이콘, 설명: "트리거·절차·출력 규칙", 하위 태그: "워크플로우", "조건 분기", "출력 형식" |
| "초안 작성" — 연필 아이콘 | "초안 작성" — 연필 아이콘, 설명: "AI로 재료 확보", 하위 태그: "빠른 생성", "완벽보다 속도" |

### 보강 2: 배경·구역 분리

화면을 **2~3개 구역**으로 나눠 시각적 밀도를 높인다.

- **제목 영역**: 진한 색상 배경 띠 위에 흰색 제목 텍스트
- **콘텐츠 영역**: 연한 회색 또는 연한 색상 배경 블록 안에 주요 요소 배치
- **하단 영역**: 흰색 여백에 요약 문구 또는 부가 정보

### 보강 3: 시각 장치 추가

- **번호 뱃지**: 각 카드/단계 좌상단에 원형 번호 배치
- **카드 색상 분리**: 각 카드마다 다른 연한 색상 배경
- **연결 장치**: 굵은 연결선, 화살표, 점선 구분선 등
- **크기 지시**: "카드 크기를 크게", "요소가 화면을 충분히 채우도록" 등 명시
- **한 줄 설명**: 각 항목 아래 짧은 부가 설명 추가

### 밀도 보강 체크리스트

프롬프트 작성 완료 후 아래를 점검한다. **3개 이상 충족해야 출력**한다.

- [ ] 각 핵심 포인트에 하위 태그 또는 부가 설명이 있는가
- [ ] 화면이 2개 이상 구역(제목 띠 + 콘텐츠 블록)으로 나뉘어 있는가
- [ ] 각 카드/요소에 서로 다른 색상이 적용되어 있는가
- [ ] 번호 뱃지 또는 아이콘이 모든 항목에 포함되어 있는가
- [ ] "화면을 충분히 채우도록" 또는 "카드 크기를 크게" 같은 크기 지시가 있는가

## 프롬프트 길이 가이드라인

나노바나나 프로는 프롬프트가 길어도 비교적 잘 처리하지만, 다음 기준을 지킨다.

| 항목 수 | 적정 프롬프트 줄 수 | 주의사항 |
|---------|-------------------|---------|
| 3개 | 25~30줄 | 가장 안정적 |
| 4개 | 30~40줄 | 권장 범위 |
| 5~6개 | 40~50줄 | 부가 설명·하위 태그를 1~2개로 축소 |
| 7개 이상 | 생성하지 않음 | 항목을 6개 이하로 줄이거나 2장으로 분리 |

**핵심 원칙**: 항목이 늘어날수록 카드당 정보량(부가 설명·하위 태그)을 줄여 전체 프롬프트 밀도를 조절한다. 장면형은 동작 묘사가 길어지므로 항목 4개 이하를 권장한다.

## 수정·변환 대응

- **스타일 전환**: 같은 원고를 다른 스타일로 재구성
- **항목 추가/삭제**: 원고에서 추출한 포인트 수 조정
- **색상 변경**: 헥스코드 또는 색상명 교체 (팔레트 참조)
- **유형 전환**: 같은 원고를 다른 유형으로 재구성
- **캐릭터 추가/제거**: 스틱맨 포함 여부
- **장면 수정**: 스틱맨 동작·소품·표정 변경
- **비율 변경**: 16:9 → 4:3, 1:1, 9:16 등
- **한글 오류 수정**: "이미지에서 OOO를 OOO로 수정해줘" 후속 프롬프트 안내
- **원고 재입력**: 다른 단락을 넣어 새 슬라이드 프롬프트 생성

수정 시 전체 프롬프트를 다시 코드블록으로 출력한다.
