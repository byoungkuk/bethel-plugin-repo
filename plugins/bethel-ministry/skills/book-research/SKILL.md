# 책쓰기 전용 리서치 워크플로우 (Book Research Workflow)

책 프로젝트의 챕터별 참조 자료 팩을 생성하는 3단계 워크플로우. 두 가지 모드를 지원한다.

| 모드 | 사용 시점 | 분량 | 슬롯 | 연결 대상 |
|------|----------|------|------|----------|
| **A 모드** (기본형) | 집필 전 — 원고 없음 | 500~800자 | ①~⑤ | book-writing-pro Phase 3 입력 |
| **B 모드** (확장형) | 집필 후 — 초안 완성 | 1,200~2,000자 | ①~⑥ | book-editing 퇴고 근거 |

사용자가 모드를 지정하지 않으면, 해당 챕터의 원고 파일 존재 여부로 자동 판단한다. 원고 파일이 있으면 B 모드, 없으면 A 모드. 사용자가 명시적으로 지정하면 그것을 따른다.

## 보조 파일 안내

| 파일 | 용도 | 참조 시점 |
|------|------|-----------|
| `references/output-template.md` | 참조 자료 팩 출력 포맷 | Step 3 (팩 생성) |
| `references/examples.md` | 실전 좋은 예시 2개 + 나쁜 예시 1개 | Step 2~3 (조사·출력 시 참고) |

## research-report와의 차이

이 스킬은 리서치 보고서를 만드는 스킬이 아니다. 차이를 명확히 구분한다.

| 비교 | research-report | 이 스킬 (book-research) |
|------|-------------------------|------------------------|
| 목적 | 독립된 리서치 보고서 납품 | 챕터 집필·퇴고용 참조 자료 제공 |
| 출력 형태 | 5섹션 보고서 (요약→배경→발견→시사점→출처) | A: 5슬롯 참조 카드 / B: 6슬롯 확장 참조 카드 |
| 분량 | 보고서 1편 분량 (1,500~3,000자) | A: 압축형 (500~800자) / B: 확장형 (1,200~2,000자) |
| 연결 대상 | 단독 산출물 | A: book-writing-pro Phase 3 입력 / B: book-editing 퇴고 근거 |
| 톤 | 분석·보고 톤 | 톤 없음. 사실 중심, 집필·퇴고 참조용 |

## 전체 흐름

```
Step 1: 챕터 맥락 확인 → Step 2: 자료 조사·정리 → Step 3: 참조 자료 팩 생성
```

사용자의 상태에 따라 적절한 시작점을 선택한다.
- 챕터 번호+주제만 있음 → Step 1부터
- 조사 방향이 구체적으로 지정됨 → Step 2부터
- 이미 수집한 자료를 정리만 해달라는 요청 → Step 3부터

### Step 간 전환 규칙

각 Step 완료 후, 다음 Step으로 넘어가기 전에 사용자 확인을 받는다.

| 전환 | 확인 방식 |
|------|----------|
| Step 1 → 2 | 리서치 방향 요약을 제시하고, 조사 범위·방향 수정 여부를 확인한 뒤 진행 |
| Step 2 → 3 | 5슬롯 조사 결과를 제시하고, 보강·삭제 요청이 있는지 확인한 뒤 팩 생성 |

사용자가 "한 번에 해줘" 또는 "바로 팩 만들어줘"라고 요청한 경우, 확인 없이 연속 진행한다.

## Step 1: 챕터 맥락 확인 (Context Check)

리서치 방향을 잡기 위해 프로젝트 기존 파일을 확인한다. **프로젝트 초기에는 참조 파일이 없는 경우가 대부분이다. 파일이 없어도 챕터 주제만으로 리서치를 시작할 수 있다.**

### 기본 경로: 참조 파일 없이 시작

참조 파일이 하나도 없을 때의 흐름:
1. 사용자에게 **챕터 주제(1문장)**를 확인한다 — 이것이 유일한 필수 입력. **추측으로 주제를 설정하지 않고 반드시 사용자에게 확인한다.**
2. 조사 방향 메모(선택)가 있으면 반영한다
3. 챕터 주제를 기반으로 리서치 방향 4개 항목을 도출한다
4. "작가 관점 연결"과 "조사하지 않을 것"은 생략하고, 챕터 주제 중심으로 진행한다

이 경로가 가장 빈번하게 사용된다. 참조 파일이 있으면 아래 표에 따라 맥락을 보강한다.

### 참조 파일 (있을 때만 활용)

| 파일 | 확인 항목 | 없을 경우 |
|------|----------|----------|
| 목차 파일 (02-table-of-contents 또는 목차.md) | 해당 챕터 시놉시스, 앞뒤 챕터와의 연결 | 생략. 사용자에게 챕터 주제를 직접 질문 |
| 작가 관점 선언 (book-perspective-*.md) | 이 챕터에서 강조할 관점, 쓰지 않을 것 | 생략. 관점 제약 없이 일반 조사 |
| 경험 뱅크 (experience-bank-*.md) | 이미 확보된 사례 — 리서치로 보강할 빈 영역 파악 | 생략. 전 영역 조사 |
| 이전 챕터 참조 자료 팩 (research-Ch[이전번호].md) | 앞 챕터에서 이미 조사한 내용 — 중복 방지, 연속성 확보 | 생략. 독립 조사 |
| **[B 모드 전용]** 챕터 원고 (원고/Ch[번호]*.md) | 원고에서 인용된 수치·사례·주장 확인, 검증 대상 추출 | B 모드 불가 → A 모드로 전환 |

### 리서치 방향 도출

참조 파일을 읽은 뒤 다음을 정리한다:

1. **챕터 핵심 주제** — 이 챕터가 다루는 것 (1문장)
2. **조사 방향** — 어떤 종류의 자료가 필요한지 (2~3문장)
3. **작가 관점 연결** — 이 챕터에서 작가 관점 선언의 어떤 요소를 뒷받침해야 하는지
4. **조사하지 않을 것** — 작가 관점 선언의 "쓰지 않을 것"과 겹치는 영역

사용자가 조사 방향을 직접 지정한 경우, 사용자 지정 방향을 우선한다. 파일에서 확인한 맥락은 보조 참고로만 활용한다.

### B 모드 추가 확인 (원고가 있을 때)

B 모드에서는 위 4개 항목에 더해 원고를 읽고 다음을 추가로 정리한다:

5. **원고 내 인용·수치 목록** — 원고에서 이미 사용한 수치·사례·출처를 추출한다
6. **검증 대상** — 추출한 수치·사례 중 출처 확인이 필요한 항목을 리스트업한다
7. **교차 인용 후보** — 다른 챕터 원고와 겹치는 개념·수치가 있는지 확인한다

이 정보가 Step 2에서 팩트 검증과 사례 대조의 기준이 된다.

### 산출물

리서치 방향 요약을 대화창에 제시한다. B 모드는 검증 대상 목록도 함께 제시한다. 사용자 확인 후 Step 2로 진행.

## Step 2: 자료 조사·정리 (Research & Organize)

Step 1에서 확인한 방향에 따라 자료를 조사하고, A 모드는 5개 슬롯, B 모드는 6개 슬롯으로 분류한다.

### 조사 키워드 도출

Step 1의 리서치 방향을 기반으로, 실제 조사에 사용할 검색 키워드 3~5개를 먼저 정리한다. 키워드는 대화창에 별도로 제시하지 않고, 내부적으로 도출하여 조사에 활용한다. 사용자가 키워드를 직접 지정한 경우 그것을 우선한다.

### 조사 방법

| 환경 | 방법 |
|------|------|
| 웹 검색 가능 | 검색 우선. 검색 결과 + 프로젝트 폴더 내 기존 자료를 조합 |
| 웹 검색 불가 (오프라인 코워크 등) | 클로드의 일반 지식 기반으로 정리한다. 단, ② 인용 가능 수치 슬롯에는 `[오프라인 — 출처 확인 필요]` 표시. 사용자가 제공한 자료가 있으면 해당 자료를 우선 활용 |
| 사용자 자료 제공 | 사용자 자료를 5슬롯에 분류. 부족한 슬롯은 검색 또는 일반 지식으로 보충 |

### 슬롯 구조

조사 결과를 슬롯으로 분류한다. **슬롯을 건너뛰거나 순서를 바꾸지 않는다.** 조사 결과가 부족한 슬롯도 비워두지 않고 `[조사 미흡]` 표시를 삽입한다.

**A 모드 (5슬롯)**

| 슬롯 | 내용 | 분량 기준 |
|------|------|----------|
| ① 핵심 팩트 | 챕터 주장을 뒷받침하는 사실·데이터 | 3~5개, 각 1~2문장 |
| ② 인용 가능 수치 | 구체적 숫자·통계·비율 (출처 필수) | 2~3개 |
| ③ 사례·레퍼런스 | 인용·참조할 수 있는 외부 사례 | 1~2개, 각 2~3문장 요약 + 출처 + 집필 활용 메모 |
| ④ 반론·주의점 | 해당 주제의 흔한 오해, 반대 의견, 한계 | 1~2개 |
| ⑤ 관련 키워드 | 집필 시 자연스럽게 사용할 용어·개념 | 3~5개 |

**B 모드 (6슬롯)**

| 슬롯 | 내용 | 분량 기준 |
|------|------|----------|
| ① 핵심 팩트 | 챕터 주장을 뒷받침하는 사실·데이터 | 4개 이상, 각 1~2문장 |
| ② 인용 가능 수치 | 구체적 숫자·통계·비율 (출처 필수) | 3개 이상 |
| ③ 사례·레퍼런스 | 인용·참조할 수 있는 외부 사례 | 2~3개, 각 2~3문장 요약 + 출처 + **원고 인용 위치** + **검증 결과** |
| ④ 반론·주의점 | 해당 주제의 흔한 오해, 반대 의견, 한계 | 2개 이상 |
| ⑤ 관련 키워드 | 집필 시 자연스럽게 사용할 용어·개념 | 4~6개 |
| ⑥ 교차 인용 | 다른 챕터와 겹치는 개념·수치·사례 | 챕터당 1문장 |

B 모드의 ③ 사례에는 "집필 활용" 대신 **"원고 인용 위치"**(원고에서 이 사례가 들어갈 소제목/문단)와 **"검증 결과"**(원고 서술과 출처 데이터의 일치 여부, 불일치 시 차이 명시)를 기재한다. 이 정보는 퇴고 시 팩트 검증 근거로 직접 연결된다.

### 문장 품질 기준 (GOOD/BAD 예시)

| BAD (금지) | GOOD (기준) |
|-----------|------------|
| AI 이미지 생성 도구의 성능이 매우 향상되었다 | Gemini 2.0의 이미지 생성은 텍스트 렌더링 정확도가 이전 버전 대비 40% 개선되었다 (Google, 2025.03) |
| 다양한 분야에서 활용 가능성이 높다 | 교육용 인포그래픽, 제품 목업, 블로그 썸네일 3개 용도에서 도입 사례가 확인되었다 |
| 이 접근 방식은 혁신적이다 | 이 접근 방식은 프롬프트 1회 입력으로 스타일 3종을 동시에 생성한다 |

### 자가 점검 (출력 전 반드시 실행)

참조 카드 작성 완료 후, 아래 항목을 확인한다. 해당 항목이 있으면 수정한 뒤 출력한다.

**공통 점검:**
- [ ] "혁신적인", "획기적인", "완벽한" 등 과장형 형용사 포함 여부
- [ ] "~할 수 있다" 추측 표현 포함 여부
- [ ] "매우", "쉽게", "빠르게" 등 모호한 부사 포함 여부
- [ ] ② 인용 가능 수치에 출처가 누락된 항목이 있는가
- [ ] 슬롯 순서가 지켜졌는가

**A 모드 점검:**
- [ ] ③ 사례에 "집필 활용" 메모가 빠진 항목이 있는가
- [ ] 전체 분량이 500~800자 범위인가

**B 모드 추가 점검:**
- [ ] ③ 사례에 "원고 인용 위치"와 "검증 결과"가 빠진 항목이 있는가
- [ ] 검증 결과에서 불일치 항목이 명확히 표시되었는가
- [ ] ⑥ 교차 인용 슬롯이 포함되었는가
- [ ] 전체 분량이 1,200~2,000자 범위인가

### 조사 결과 부실 시 처리

조사 결과가 충분하지 않아 슬롯을 채우지 못하는 경우, 빈 슬롯을 비워두지 않는다.

- 해당 슬롯에 `[조사 미흡 — 추가 자료 필요]` 표시를 삽입한다
- 어떤 종류의 자료가 부족한지 1문장으로 명시한다 (예: `[조사 미흡 — 2024년 이후 국내 사례 필요]`)
- 사용자가 이 표시를 보고 자료를 보충하거나, 해당 슬롯을 생략할지 판단한다

### 슬롯별 작성 규칙

**① 핵심 팩트:**
- 의견이 아닌 검증 가능한 사실만 포함한다
- 출처를 확인할 수 없는 팩트는 `[미확인]` 표시한다
- 챕터의 판단 기준을 뒷받침하는 팩트를 우선한다

**② 인용 가능 수치:**
- 수치에는 반드시 출처(기관명, 발행년도, URL)를 붙인다
- "약", "대략" 같은 표현보다 정확한 수치를 기재한다
- 2년 이상 된 수치는 `[YYYY년 기준]`을 명시한다

**③ 사례·레퍼런스:**
- A 모드: 각 사례에 "집필 활용" 메모를 반드시 추가한다 — 이 사례를 챕터 어떤 맥락에서 쓸 수 있는지 1문장
- B 모드: "집필 활용" 대신 "원고 인용 위치"(소제목/문단 지정)와 "검증 결과"(원고↔출처 대조)를 기재한다
- 국내·해외 사례를 구분하여 표기한다
- 사례 요약은 사실 중심, 평가·감상을 넣지 않는다

**④ 반론·주의점:**
- 챕터의 주장에 대해 독자가 가질 수 있는 반론을 미리 정리한다
- "이런 오해가 있다" + "왜 오해인지" 구조로 작성한다
- 집필 시 "흔한 오해 교정" 소제목의 재료가 된다

**⑤ 관련 키워드:**
- 작가 관점 선언의 glossary에 이미 정의된 용어는 동일 표기를 사용한다
- 새로운 용어가 등장하면 간단한 정의(1문장)를 괄호 안에 추가한다

**⑥ 교차 인용 (B 모드 전용):**
- 다른 챕터와 공유하는 개념·수치·사례를 정리한다
- 챕터 번호 + 겹치는 내용을 1문장으로 기술한다
- 중복 서술 방지와 챕터 간 참조 연결에 활용한다

### 분량 통제

| 모드 | 분량 범위 | 초과 시 조치 |
|------|----------|-------------|
| A 모드 | 500~800자 | 우선순위 낮은 항목 제거 |
| B 모드 | 1,200~2,000자 | 우선순위 낮은 항목 제거 |

보고서처럼 길게 쓰지 않는다. 집필·퇴고 시 바로 눈에 들어오는 압축도가 핵심이다. B 모드는 A 모드보다 분량이 넓지만, 검증 결과·원고 인용 위치·교차 인용 등 구조적 정보가 추가되기 때문이다. 서술을 늘리는 것이 아니라 슬롯과 메타데이터를 확장하는 것이다.

### 산출물

조사 결과를 대화창에 제시한다 (A 모드: 5슬롯 / B 모드: 6슬롯). 사용자 확인 후 Step 3으로 진행.

## Step 3: 참조 자료 팩 생성 (Reference Pack Output)

Step 2의 조사 결과를 출력 포맷에 맞춰 .md 파일로 생성한다.

### 출력 규칙

- 출력 포맷은 `references/output-template.md`를 따른다
- 파일명: `research-Ch[번호].md` (예: research-Ch05.md)
- **번호 표기는 book-writing-pro의 `chapter-XX-draft.docx`와 동일하게 맞춘다.** Ch01, Ch02, Ch10 등 2자리 숫자를 기본으로 한다
- 초안은 대화창 텍스트로 제공한다
- 사용자가 파일 저장을 요청하면 .md 파일로 생성한다
- 코워크 환경이면 프로젝트 폴더 내 리서치 폴더에 바로 저장한다

### 연결 가이드

#### A 모드 → book-writing-pro Phase 3

| 참조 자료 팩 슬롯 | Phase 3 활용 위치 | 연결 방식 |
|-------------------|-----------------|----------|
| 챕터 정보 → 작가 관점 연결 | 장 작성 요청 "핵심 판단 기준" | 리서치가 뒷받침하는 판단 기준 확인 |
| ① 핵심 팩트 + ② 인용 가능 수치 | 장 작성 요청 "참조 자료" | 본문에서 근거로 직접 인용 |
| ③ 사례·레퍼런스 | 장 작성 요청 "참조 자료" | 외부 사례로 논거 보강 |
| ④ 반론·주의점 | 챕터 내 "흔한 오해 교정" 소제목 | 독자 오해 교정 소재 |
| ⑤ 관련 키워드 | 본문 용어 선택 | 자연스러운 키워드 배치 |

**주의:** 참조 자료 팩을 통째로 집필 스킬에 넘기지 않는다. 필요한 슬롯만 선별해서 "참조 자료"로 지정하는 것이 원고 품질을 결정한다. 특히 ③ 사례는 경험 뱅크와 겹치지 않는지 확인한다.

#### B 모드 → book-editing (퇴고)

| 참조 자료 팩 슬롯 | 퇴고 활용 위치 | 연결 방식 |
|-------------------|--------------|----------|
| ③ 사례 → 검증 결과 | 구조 편집 (1패스) | 불일치 항목을 퇴고 시 수정 대상으로 직접 반영 |
| ③ 사례 → 원고 인용 위치 | 구조 편집 (1패스) | 사례 배치가 적절한지 점검 근거 |
| ⑥ 교차 인용 | 구조 편집 (1패스) | 챕터 간 중복 서술 제거, 상호 참조 연결 |
| ① 핵심 팩트 + ② 수치 | 문장 편집 (2패스) | 수치·팩트 정확성 대조 근거 |

B 모드 팩에서 "검증 결과: 불일치" 항목은 퇴고 시 반드시 수정해야 하는 필수 체크리스트가 된다.

---

## 복수 챕터 일괄 처리

여러 챕터의 리서치를 한꺼번에 요청받은 경우:

1. 챕터별로 Step 1~3을 순차 진행한다
2. 챕터 간 조사 결과가 겹치면 중복을 제거하고, 겹치는 팩트는 먼저 등장하는 챕터에 배치한다
3. 전체 팩 생성 완료 후, 챕터별 파일 목록을 요약 제시한다

---

## 수정·보강 대응

| 요청 | 처리 방식 |
|------|----------|
| "팩트 더 추가해줘" | 지정 슬롯에 항목 추가. 분량 상한(A: 800자 / B: 2,000자) 초과 시 사용자에게 확인 |
| "이 사례 빼고 다른 걸로" | 해당 사례 교체. 집필 활용/원고 인용 위치 메모도 새로 작성 |
| "반론을 더 강하게" | ④ 슬롯 보강. 반론의 근거와 대응 논리 추가 |
| "이 자료를 기반으로 정리해줘" | 사용자 제공 자료를 슬롯에 분류하여 팩 생성 (Step 3부터 시작) |
| "리서치 방향을 바꿔줘" | Step 1로 돌아가서 방향 재설정 후 Step 2~3 재진행 |
| "이전 챕터 리서치 참고해서 다음 챕터도 해줘" | 이전 챕터 참조 자료 팩(research-Ch[이전번호].md)을 Step 1에서 읽고, 중복 팩트를 제거하며, 앞 챕터에서 이어지는 맥락을 반영하여 조사 |
| "리서치 결과를 경험 뱅크와 합쳐줘" | ③ 사례 슬롯의 외부 사례와 경험 뱅크의 내부 사례를 비교·정리. 겹치는 사례는 경험 뱅크 우선, 외부 사례는 보조 근거로 배치. 결과를 참조 자료 팩에 반영 |
| "A 모드로 만들어줘" / "B 모드로 만들어줘" | 사용자 지정 모드로 전환. 자동 판단 무시 |
| "리서치 보강해줘" / "리서치 확장해줘" | 기존 A 모드 팩이 있으면 B 모드로 확장 재생성. 기존 B 모드면 슬롯 내 항목 추가 |

| 단계 | 산출물 | 형태 |
